01. Syntax Directed Definitions (SDD) HIGH
How grammar rules carry "meaning" along with syntax
Definition

A Syntax Directed Definition (SDD) is a context-free grammar in which each grammar symbol is associated with a set of attributes, and each production rule is associated with a set of semantic rules that define how to compute the attribute values, allowing the grammar to specify both the syntax and the "meaning" (translation) of a language simultaneously.

🇮🇳 Hinglish Explanation
SDD ek tarika hai grammar ke saath-saath "meaning" bhi attach karne ka. Normal grammar sirf batati hai ki valid sentence kaisa dikhega, lekin SDD har grammar symbol ke saath kuch extra information (attributes) jodti hai aur batati hai ki har production rule apply hone par yeh information kaise calculate hogi — jaise expression ka value, ya variable ka type.

Types of Attributes

TypeDescriptionComputed Using
Synthesized AttributeValue computed from the attribute values of its children (bottom-up flow)Information flows UP the parse tree
Inherited AttributeValue computed from the attribute values of its parent and/or siblings (top-down/left-right flow)Information flows DOWN/ACROSS the parse tree
Example

For E → E1 + T { E.val = E1.val + T.val } — E.val is a synthesized attribute, computed from its children E1.val and T.val.

02. Construction of Syntax Trees HIGH

Definition

A Syntax Tree (abstract syntax tree) is a condensed/compressed form of a parse tree in which operators appear as interior nodes and their operands as children, with chain productions and unnecessary grammar-specific detail removed — capturing only the essential hierarchical structure of an expression/statement.

🇮🇳 Hinglish
Syntax tree, parse tree ka simplified version hai. Parse tree mein har grammar rule ka ek node hota hai (bahut detailed), lekin syntax tree sirf important operators aur operands ko rakhta hai — extra/unnecessary nodes hata diye jaate hain. Yeh compiler ke liye zyada compact aur useful representation hai.

Constructing Syntax Tree via SDD EXAM HOT

ProductionSemantic Rule
E → E1 + TE.node = mknode('+', E1.node, T.node)
E → E1 − TE.node = mknode('−', E1.node, T.node)
E → ( E1 )E.node = E1.node
E → idE.node = mkleaf(id, id.entry)

Fig 1: Syntax tree for expression a*b + c — operators as interior nodes, operands as leaves

03. S-Attributed Definitions HIGH — MOST ASKED

Definition

An SDD is called S-Attributed if every attribute used in it is a synthesized attribute — i.e., every attribute's value depends only on the attribute values of its children, never on its parent or siblings, allowing values to be computed entirely bottom-up during a single post-order traversal of the parse tree.

🇮🇳 Hinglish
S-attributed SDD mein sirf synthesized attributes hote hain — matlab har node ki value sirf uske children se aati hai, kabhi parent se nahi. Isiliye yeh bottom-up parsing (jaise LR parsing) ke saath bahut aasani se kaam karta hai, kyunki values niche se upar ki taraf calculate hoti jaati hain.

Implementation: Bottom-Up Evaluation with a Parser Stack EXAM HOT

S-attributed SDDs can be implemented conveniently along with an LR-parser. Each grammar symbol's attribute value is stored alongside it on the parser stack. When a reduction occurs (production used), the semantic rule computes the new synthesized attribute using values already present on the stack for the children.

ProductionSemantic Rule (Synthesized)
E → E1 + TE.val = E1.val + T.val
T → T1 * FT.val = T1.val * F.val
F → ( E )F.val = E.val
F → digitF.val = digit.lexval
⚠ Important

S-attributed SDDs are a subset of L-attributed SDDs (since synthesized-only is a special/simpler case). All S-attributed grammars are L-attributed, but not vice-versa.

04. L-Attributed Definitions HIGH — MOST ASKED

Definition

An SDD is called L-Attributed if, for each production A → X1 X2 ... Xn, every inherited attribute of Xi depends ONLY on: (a) the attributes of X1, X2, ..., Xi−1 (symbols to its left), and/or (b) the inherited attributes of A itself — never on attributes of symbols to the right.

🇮🇳 Hinglish
L-attributed SDD thoda flexible hai — yeh synthesized AND inherited dono attributes allow karta hai, lekin ek rule ke saath: koi bhi inherited attribute sirf apne LEFT side ke symbols ya parent se information le sakta hai, RIGHT side (aage waale symbols) se nahi. "L" isiliye kyunki information sirf Left-to-right flow follow karti hai, jaise hum bayein se dayein padhte hain.

Why "L"-Attributed? — Single Left-to-Right Pass

The "L" restriction (no looking right) ensures that attribute values can be computed in a single left-to-right, depth-first traversal of the parse tree — making L-attributed SDDs implementable with predictive (top-down, LL) parsers as well as during bottom-up parsing.

Example

D → T L { L.inh = T.type }   L → L1 , id { L1.inh = L.inh; addtype(id.entry, L.inh) }   L → id { addtype(id.entry, L.inh) }

Here L.inh (inherited) is passed from the parent D (a symbol to the left in the production) — this is valid L-attributed flow used for declarations like int a, b, c;.

S-Attributed vs L-Attributed EXAM HOT — Comparison Guaranteed

FeatureS-AttributedL-Attributed
Attribute Types AllowedOnly SynthesizedSynthesized + Inherited (restricted)
Information FlowBottom-up onlyLeft-to-right, top-down & bottom-up
Compatible ParsersBottom-up (LR) parsersBoth Top-down (LL) and Bottom-up parsers
GeneralitySubset (more restrictive)Superset (more general)

05. Top Down Translation MEDIUM

Definition

Top Down Translation refers to performing syntax-directed translation while doing top-down (predictive/recursive-descent) parsing — the semantic actions associated with grammar productions are executed as the parser expands non-terminals from the start symbol downward.

🇮🇳 Hinglish
Top-down translation matlab — jab parser grammar ko top (start symbol) se expand karte hue niche jaata hai, usi waqt semantic actions (translation rules) bhi execute hote jaate hain. Yeh recursive-descent parsers ke saath naturally fit hota hai.

Requirements for Top-Down Translation

  • The SDD must be L-attributed (since top-down parsing processes symbols left-to-right).
  • Left recursion must first be eliminated from the grammar (top-down parsers cannot handle left recursion).
  • Each non-terminal is implemented as a procedure/function; inherited attributes are passed as parameters, synthesized attributes are returned as the function's result.
Example

A recursive-descent parser procedure for non-terminal E might look like: function E(inh_attr) { call T(...); call Eprime(T.val, ...); return Eprime.val; } — each procedure call corresponds to expanding a non-terminal in the parse tree.

06. Postfix Notation (Reverse Polish Notation) HIGH

Definition

Postfix Notation is a form of intermediate code in which every operator appears immediately AFTER its operands (rather than between them, as in infix), eliminating the need for parentheses to indicate operator precedence and making expression evaluation straightforward using a stack.

🇮🇳 Hinglish
Postfix notation mein operator hamesha operands ke baad aata hai (jaise ab+ for a+b). Isme bracket ki zaroorat nahi padti kyunki order khud hi precedence batata hai. Compiler isse easily ek stack use karke evaluate kar sakta hai — left se right padho, operand mile to push karo, operator mile to top do values pop karke operate karo.

Infix to Postfix Conversion EXAM HOT — Numerical

Infix ExpressionPostfix Expression
a + ba b +
a + b * ca b c * +
(a + b) * ca b + c *
a * b + c * da b * c d * +

Stack-Based Evaluation of Postfix

Algorithm: scan left to right; if symbol is an operand, push onto stack; if symbol is an operator, pop the required number of operands, apply the operator, and push the result back. At the end, the stack contains exactly one value — the final result.

Example

Evaluate postfix 3 4 + 2 *: push 3, push 4 → stack[3,4]; see '+', pop 4,3 → 3+4=7, push 7 → stack[7]; push 2 → stack[7,2]; see '*', pop 2,7 → 7*2=14, push 14 → stack[14]. Result = 14 (equivalent to infix (3+4)*2).

07. DAG as an Intermediate Code Form HIGH

Definition

As an intermediate code representation, a DAG (Directed Acyclic Graph) represents an expression such that each interior node is labelled with an operator, its children are its operands, and identical sub-expressions are represented by a SHARED single node — directly exposing common sub-expressions that postfix or plain syntax trees would otherwise duplicate.

🇮🇳 Hinglish
DAG bhi syntax tree jaisa hi hota hai, lekin ismein agar same expression baar-baar use ho raha ho, to usse sirf ek hi node se represent kiya jata hai (reuse hota hai), tree ki tarah dobara nahi banaya jata. Isse redundant calculations avoid hoti hain.

Syntax Tree vs DAG EXAM HOT — Comparison Guaranteed

FeatureSyntax TreeDAG
Repeated Sub-expressionsEach occurrence gets a separate, duplicate nodeShared — single node with multiple parents
StructureAlways a tree (no node has >1 parent)Graph (nodes can have multiple parents)
Detects Common Sub-expr?NoYes
Memory UsageHigher (duplicates)Lower (sharing)
Example

For a = (b+c)*(b+c): a syntax tree creates TWO separate b+c subtrees, but a DAG creates only ONE b+c node and points to it twice from the * node — saving computation.

08. Three Address Code (TAC) HIGH — BACKBONE OF THIS UNIT

Definition

Three Address Code is an intermediate code representation in which each statement contains AT MOST three addresses (operands) — typically two operands and one result — and at most one operator per statement, resembling assembly-like instructions while remaining machine-independent.

🇮🇳 Hinglish
Three Address Code (TAC) ek aisa intermediate code hai jisme har statement mein zyada se zyada 3 addresses hoti hain (do operands + ek result) aur sirf ek operator. Yeh complex expressions ko simple, ek-ek operation waale chhote statements mein todta hai — jaise x = y + z.

General Form of TAC Statement

x = y op z

where x, y, z are names, constants, or compiler-generated temporaries, and op is a single binary/unary operator.

Common TAC Statement Types EXAM HOT

TypeFormExample
Assignment (binary op)x = y op zt1 = a + b
Assignment (unary op)x = op yt2 = −a
Copy Statementx = ya = t1
Unconditional Jumpgoto Lgoto L1
Conditional Jumpif x relop y goto Lif a < b goto L2
Indexed Assignmentx = y[i] / x[i] = yt3 = arr[i]
Address & Pointerx = &y / x = *y / *x = yp = &a
Procedure Callparam x / call p,nparam a; call f,1
Example — Expression to TAC

For a = b * −c + b * −c:

t1 = −c t2 = b * t1 t3 = −c t4 = b * t3 t5 = t2 + t4 a = t5

09. Three Address Code for Various Control Structures HIGH — MOST ASKED

Definition

Generating TAC for control structures (if-else, while, for) involves using conditional and unconditional jumps, along with compiler-generated labels, to translate the high-level control flow into a sequence of TAC statements that achieve the same branching behaviour.

TAC for if-then-else EXAM HOT

Source: if (B) S1 else S2

code for B (true → L1, false → L2) L1: code for S1 goto L3 L2: code for S2 L3: (next statement)

TAC for while Loop EXAM HOT

Source: while (B) S

L1: code for B (true → L2, false → L3) L2: code for S goto L1 L3: (next statement)

TAC for for Loop

Source: for (i=init; i<limit; i++) S — translated by rewriting as an equivalent while-loop pattern:

i = init L1: if i < limit goto L2 goto L3 L2: code for S i = i + 1 goto L1 L3: (next statement)

Fig 2: Control flow for while-loop TAC — L1 tests condition, L2 is the body, L3 is exit

10. Representing TAC Using Triples & Quadruples HIGH — MOST ASKED

Definition

Quadruples and Triples are two record-structure implementations used to physically store three-address code statements internally within the compiler. A Quadruple has 4 fields (operator, arg1, arg2, result); a Triple has only 3 fields (operator, arg1, arg2) and refers to the result of a triple by its position/index, rather than storing it as a named temporary.

🇮🇳 Hinglish
Compiler ke andar TAC ko actually store karne ke 2 main tarike hain — Quadruple aur Triple. Quadruple mein 4 columns hote hain (operator, operand1, operand2, result), jisme result ko ek naam diya jaata hai (temporary variable). Triple mein sirf 3 columns hote hain — result ko naam nahi diya jaata, balki uska reference us statement ke position number (index) se diya jaata hai.

Quadruple Representation EXAM HOT

For a = b * −c + b * −c, the quadruples are:

#oparg1arg2result
0uminusc—t1
1*bt1t2
2uminusc—t3
3*bt3t4
4+t2t4t5
5=t5—a

Triple Representation EXAM HOT

Same expression using triples (result referred to by statement number in parentheses, not a named temporary):

#oparg1arg2
0uminusc—
1*b(0)
2uminusc—
3*b(2)
4+(1)(3)
5=a(4)

Quadruple vs Triple EXAM HOT — Comparison Guaranteed

FeatureQuadrupleTriple
Number of Fields4 (op, arg1, arg2, result)3 (op, arg1, arg2)
Result ReferenceNamed temporary variablePosition/index of the statement
Rearranging StatementsEasy — temporaries are named, order-independentHard — moving a statement changes its index, breaking references
Memory UsageHigher (extra result field + temp names)Lower (no named temporaries needed)

Indirect Triples (Improvement over Triples)

Indirect Triples add a separate list of pointers to triples, listed in the desired execution order. This allows statement reordering (for optimization) by simply rearranging the pointer list, without modifying the triples themselves — combining the compactness of triples with the reorderability of quadruples.

11. Boolean Expressions and Control Structures HIGH

Definition

Translation of Boolean expressions can be done in two ways: (a) Numerical representation — encoding true as 1 and false as 0, evaluating left-to-right like an arithmetic expression; or (b) Flow-of-control (short-circuit) translation — representing the value of a Boolean expression implicitly by the position reached in the program (i.e., which branch of code executes), generating jump instructions instead of explicitly computing 1/0.

🇮🇳 Hinglish
Boolean expressions ko translate karne ke 2 tarike hain. Pehla: simple — true/false ko 1/0 maan kar normal arithmetic expression jaisa treat karo. Dusra (zyada efficient): "short-circuit" tarika — jaha hum value ko explicitly calculate nahi karte, balki seedha jump instructions generate karte hain jo decide karte hain ki code kis path pe jayega — yeh tarika compilers mein zyada use hota hai kyunki yeh fast hai aur unnecessary evaluation avoid karta hai.

Short-Circuit (Jumping) Code for Boolean Operators EXAM HOT

ExpressionTranslation Strategy
B1 && B2If B1 is false, jump directly to false-label (skip evaluating B2). Only evaluate B2 if B1 is true.
B1 || B2If B1 is true, jump directly to true-label (skip evaluating B2). Only evaluate B2 if B1 is false.
!BSimply swap the true-label and false-label targets of B.
Example — TAC for if (a<b && c<d) x=1; else x=0;
if a < b goto L1 goto L3 L1: if c < d goto L2 goto L3 L2: x = 1 goto L4 L3: x = 0 L4:

Notice how c<d is only checked if a<b is true — this is the short-circuit behaviour, achieved purely through jump targets, with no Boolean value ever explicitly stored.

⚠ Important

The flow-of-control translation method is preferred in real compilers (used in if/while statements) because it produces more efficient code by avoiding evaluation of the right operand when the left operand already determines the result — this is precisely "short-circuit evaluation" as seen in C/C++/Java (&&, ||).

Hinglish Trick

SDD Types: S-Attributed = Sirf Children se value aati hai (Bottom-Up/Synthesized). L-Attributed = Parent aur Left siblings se value aati hai (Left-to-Right DFS).
TAC Forms: Quadruples = 4 dabbe (op, arg1, arg2, res) (Shift karna easy). Triples = 3 dabbe (op, arg1, arg2) (Result index ban jata hai, move karna mushkil!).

1. Syntax Directed Definitions

  • Synthesized (S): Computed from children values (Bottom-Up)
  • Inherited (I): Computed from parent & left siblings
  • S-Attributed: Uses synthesized only → Evaluated in Post-order / LR
  • L-Attributed: Synthesized + Left-restricted Inherited → Evaluated in Depth-First / LL

2. Intermediate Code Forms

  • Postfix: Operators follow operands (Reverse Polish)
  • DAG: Directed Acyclic Graph — eliminates common sub-expressions
  • Three-Address Code (TAC): At most 3 operands per instruction `x = y op z`

3. TAC Representations & Control

  • Quadruples: (op, arg1, arg2, result) — Easy to optimize/relocate
  • Triples: (op, arg1, arg2) — Result referenced by position index
  • Short-Circuit: Jumps generated directly for `&&` and `||` logic

❓ RTU Exam Q&A Bank — Unit 4 EXAM GOLD

Q1 · 5 MARKS
5 MARKS
What is a Syntax Directed Definition (SDD)? Differentiate between synthesized and inherited attributes.

An SDD is a context-free grammar augmented with attributes for grammar symbols and semantic rules for productions, specifying both syntax and meaning/translation together. Synthesized attributes are computed from a node's children (bottom-up flow), e.g. E.val = E1.val + T.val. Inherited attributes are computed from a node's parent and/or left siblings (top-down/left-to-right flow), e.g. passing a declared type down to identifiers in a declaration list.

Q2 · 10 MARKS
10 MARKS
Define S-Attributed and L-Attributed definitions. Differentiate between them with examples.

An SDD is S-Attributed if it uses only synthesized attributes — values are computed entirely bottom-up, suitable for LR (bottom-up) parsers, evaluated during a single post-order traversal. An SDD is L-Attributed if every inherited attribute of a symbol depends only on attributes of symbols to its left in the production (or the parent's inherited attributes) — never on symbols to its right. This restriction allows evaluation in a single left-to-right depth-first traversal, making L-attributed SDDs usable with both top-down (LL) and bottom-up parsers. Every S-attributed SDD is also L-attributed, but not vice versa, since L-attributed permits inherited attributes flowing left-to-right while S-attributed allows only synthesized (bottom-up) flow.

Q3 · 5 MARKS
5 MARKS
What is a syntax tree? How does it differ from a parse tree?

A syntax tree (abstract syntax tree) is a compact representation of a program's structure where operators are interior nodes and operands are their children — it omits the unnecessary grammar-rule detail present in a full parse tree (e.g. chain productions, parentheses tokens). A parse tree shows every step of the derivation according to the grammar (verbose), while a syntax tree shows only the essential semantic structure (compact), making it more suitable for further compiler phases like code generation.

Q4 · 10 MARKS
10 MARKS
What is Three Address Code? Explain its various statement forms with examples.

Three Address Code (TAC) is an intermediate representation where each statement has at most three addresses (two operands + one result) and at most one operator, in the general form x = y op z. Common forms: assignment with binary/unary operator (t1=a+b, t2=−a), copy statement (a=t1), unconditional jump (goto L), conditional jump (if a<b goto L), indexed assignment (t=arr[i]), address/pointer operations (p=&a, x=*p), and procedure call sequences (param a; call f,1). TAC breaks complex expressions into a sequence of simple, single-operation steps, close to assembly but still machine-independent.

Q5 · 10 MARKS
10 MARKS
Generate Three Address Code for an if-then-else statement and a while loop.

if(B) S1 else S2: code for B with (true→L1, false→L2); L1: code for S1; goto L3; L2: code for S2; L3: (next statement). while(B) S: L1: code for B with (true→L2, false→L3); L2: code for S; goto L1; L3: (next statement). In both cases, the Boolean expression B is translated using jumps to the appropriate labels rather than computing an explicit true/false value, and labels mark the start/end points of each control path.

Q6 · 10 MARKS
10 MARKS
What are Triples and Quadruples? Represent the expression a = b*−c + b*−c using both.

A Quadruple is a 4-field record (op, arg1, arg2, result) used to store a TAC statement, where the result is a named temporary. A Triple is a 3-field record (op, arg1, arg2) where the result is referred to by the statement's position/index, not a name. For a=b*−c+b*−c: Quadruples — (0)uminus,c,−,t1; (1)*,b,t1,t2; (2)uminus,c,−,t3; (3)*,b,t3,t4; (4)+,t2,t4,t5; (5)=,t5,−,a. Triples — (0)uminus,c,−; (1)*,b,(0); (2)uminus,c,−; (3)*,b,(2); (4)+,(1),(3); (5)=,a,(4).

Q8 · 5 MARKS
5 MARKS
What is postfix notation? Convert the infix expression (a+b)*(c−d) to postfix.

Postfix notation places the operator immediately after its operands, eliminating the need for parentheses since operator order is implicit. It's evaluated using a stack — push operands, and on encountering an operator, pop the required operands, apply the operation, and push the result back. For (a+b)*(c−d): postfix = a b + c d − *.

Q9 · 5 MARKS
5 MARKS
Explain how Boolean expressions are translated using flow-of-control (short-circuit) translation.

In flow-of-control translation, a Boolean expression's value is represented implicitly by which branch of the generated code is reached, rather than computing an explicit true/false value. For B1 && B2: if B1 is false, the code jumps directly to the false-label without evaluating B2 (short-circuit); only if B1 is true is B2 evaluated. For B1 || B2: if B1 is true, the code jumps directly to the true-label, skipping B2. This matches the short-circuit evaluation behaviour of &&/|| in languages like C/C++/Java and produces more efficient generated code.

Q10 · 5 MARKS
5 MARKS
What is a DAG? How is it used as an intermediate code form? Differentiate it from a syntax tree.

A DAG (Directed Acyclic Graph) represents an expression with operators as interior nodes and operands as leaves, but UNLIKE a syntax tree, identical sub-expressions are represented by a single SHARED node (multiple parents), directly exposing common sub-expressions. A syntax tree, by contrast, creates a separate duplicate subtree for every occurrence of a repeated expression. For example, in a=(b+c)*(b+c), a syntax tree builds two separate b+c subtrees, while a DAG builds only one, referenced twice — reducing both memory usage and redundant computation.
