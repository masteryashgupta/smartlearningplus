Experiment 8: User registration

A registration form. When it is submitted, control transfers to a second page that shows the entered details.

Before you start

  • Tomcat 9 must be extracted (for example C:\apache-tomcat-9.0.123). JSP files need no compiling: put them in a folder under webapps.
  • If Tomcat is already running from an earlier experiment, you do not need to start it again. It picks up new folders by itself.

Set the paths

Change both paths to match the lab PC. Find the JDK with where javac. Use the path that ends in \bin\javac.exe, without that ending, and ignore the Common Files\Oracle\Java\javapath line.

Command Prompt
set JAVA_HOME=C:\Program Files\Java\jdk-26
set TOMCAT=C:\apache-tomcat-9.0.123

Step 1: Create the app folder and files

Click Yes when Notepad asks to create each file. Check that neither file is saved as .txt.

Command Prompt
mkdir %TOMCAT%\webapps\Registration
notepad %TOMCAT%\webapps\Registration\registration.html
Command Prompt
notepad %TOMCAT%\webapps\Registration\register.jsp

<html>

If the examiner wants a servlet

The aim says servlet, but the manual uses JSP. As a backup, use a servlet for the second page. Change the form line to action="register", then follow Experiment 7: put this web.xml in WEB-INF and compile into WEB-INF\classes.

Command Prompt
mkdir %TOMCAT%\webapps\Registration\WEB-INF\classes
notepad %TOMCAT%\webapps\Registration\WEB-INF\web.xml
web.xml
<?xml version="1.0" encoding="UTF-8"?>
<web-app xmlns="http://xmlns.jcp.org/xml/ns/javaee"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://xmlns.jcp.org/xml/ns/javaee
         http://xmlns.jcp.org/xml/ns/javaee/web-app_4_0.xsd"
         version="4.0">
    <servlet>
        <servlet-name>RegisterServlet</servlet-name>
        <servlet-class>RegisterServlet</servlet-class>
    </servlet>
    <servlet-mapping>
        <servlet-name>RegisterServlet</servlet-name>
        <url-pattern>/register</url-pattern>
    </servlet-mapping>
</web-app>
Command Prompt
cd %USERPROFILE%\Desktop
notepad RegisterServlet.java
RegisterServlet.java
import java.io.*;
import javax.servlet.*;
import javax.servlet.http.*;

public class RegisterServlet extends HttpServlet {
    protected void doPost(HttpServletRequest request, HttpServletResponse response)
            throws ServletException, IOException {
        response.setContentType("text/html");
        PrintWriter out = response.getWriter();
        out.println("<html><body>");
        out.println("First name is : " + request.getParameter("fname") + "<br>");
        out.println("Last name is : " + request.getParameter("lname") + "<br>");
        out.println("User name is : " + request.getParameter("uname") + "<br>");
        out.println("Email is : " + request.getParameter("email") + "<br>");
        out.println("Address is : " + request.getParameter("add") + "<br>");
        out.println("</body></html>");
    }
}
Command Prompt
javac -cp "%TOMCAT%\lib\servlet-api.jar" -d %TOMCAT%\webapps\Registration\WEB-INF\classes RegisterServlet.java

After adding web.xml, run shutdown.bat and startup.bat so Tomcat loads it.

When you finish

Stop Tomcat from the same Command Prompt.

Command Prompt
%TOMCAT%\bin\shutdown.bat

How it works

  • The form line action="register.jsp" is what transfers control to the second page.
  • method="post" sends the data in the request body, not the URL.
  • request.getParameter("fname") reads the form field whose name is fname. The names must match exactly.
  • In JSP, request and out are implicit objects, so you do not declare them.
  • Printing the password is only for the lab demo. A real application would never do that.

Viva answers

  • How is JSP better than servlet? JSP is HTML with Java embedded, so pages are easier to write and need no manual compiling or web.xml mapping. The server converts it into a servlet.
  • How many objects of a servlet are created? One instance. Each request is handled by a separate thread.
  • Servlet lifecycle: init() once, service() for every request, destroy() once.
  • When is the servlet object created? On the first request, or at server startup if load-on-startup is set.
  • GET vs POST: GET puts data in the URL (visible, size-limited, bookmarkable). POST puts it in the body (hidden, no size limit, used for forms and passwords).
