5.1 Assignment Problem — Formulation EXAM HOT

📖 Definition

The Assignment Problem is a combinatorial optimization problem that requires assigning n agents to n tasks, one-to-one (a bijection), such that the total cost (or total profit) of the assignment is minimized (or maximized), given a cost matrix C where C[i][j] is the cost of assigning agent i to task j.

🗣️ Hinglish Explanation

Assignment Problem mein humare paas n workers aur n jobs hoti hain, aur har worker-job pair ka ek defined cost hota hai. Hume har worker ko exactly ek job aur har job ko exactly ek worker assign karna hai (one-to-one mapping) is tarah ki total cost minimum ho jaaye. Yeh ek special case hai transportation problem ka, jaha supply aur demand dono hamesha 1-1 hoti hain.

Mathematical Formulation

Minimize: Σᵢ Σⱼ C[i][j]·x[i][j] Subject to: Σⱼ x[i][j] = 1 for every agent i (each agent gets exactly 1 task) Σᵢ x[i][j] = 1 for every task j (each task gets exactly 1 agent) x[i][j] ∈ {0,1} (binary decision variable)

where x[i][j]=1 if agent i is assigned to task j, and 0 otherwise. This is a special case of the Linear (0/1 Integer) Programming problem, commonly solved using the Hungarian Method in O(n³) time.

💡 Example

Given 3 workers and 3 jobs with a 3×3 cost matrix, the assignment problem finds which single job each worker should be assigned so that exactly one worker per job and one job per worker is chosen, minimizing the sum of selected cell costs — e.g., assigning Worker1→Job2, Worker2→Job1, Worker3→Job3 if that combination yields the lowest total cost among all 3! = 6 possible assignments.

📌 Brute force vs Hungarian Method: Checking all n! possible assignments is infeasible for large n; the Hungarian Method solves the assignment problem optimally in polynomial time, O(n³).

5.2 Quadratic Assignment Problem (QAP) EXAM HOT

📖 Definition

The Quadratic Assignment Problem generalizes the assignment problem by also accounting for interaction costs between pairs of assigned facilities — given n facilities and n locations, with a flow matrix F (flow between facility pairs) and a distance matrix D (distance between location pairs), QAP finds the assignment of facilities to locations that minimizes the total cost of flow × distance over all facility pairs.

🗣️ Hinglish

Normal Assignment Problem mein sirf ek-ek pair ka individual cost important hota hai, lekin QAP mein iske saath-saath yeh bhi matter karta hai ki do facilities ek dusre se kitni "interact" karti hain (flow) aur unke locations ke beech ki distance kya hai. Jaise factory floor planning mein, jo machines aapas mein zyada material transfer karti hain unhe paas-paas rakhna chahiye taaki total (flow × distance) cost minimum ho. QAP, Assignment Problem se kahin zyada hard hai — yeh NP-Hard problem hai.

Mathematical Formulation

Minimize: Σᵢ Σⱼ Σₖ Σₗ F[i][k]·D[j][l]·x[i][j]·x[k][l] where: F[i][k] = flow between facility i and facility k D[j][l] = distance between location j and location l x[i][j] = 1 if facility i is placed at location j, else 0

Unlike the linear (standard) Assignment Problem, the objective function here is quadratic in the decision variables (a product of two assignment variables x[i][j]·x[k][l]), making QAP NP-Hard — no known polynomial-time algorithm solves it optimally for large n.

💡 Example

In hospital department layout planning, departments (e.g., Emergency, Radiology, Surgery) have known patient/staff "flow" frequencies between each pair, and candidate room locations have known pairwise distances; QAP finds the layout assignment of departments to rooms that minimizes total (flow × distance), reducing overall patient/staff travel.

Solution methodHungarian MethodHeuristics, approximation, branch & bound (exact only for small n)
Real-world useWorker-job allocationFacility layout, circuit board design

5.3 Randomized Algorithms — Concept FOUNDATION

📖 Definition

A Randomized Algorithm is an algorithm that uses a source of random numbers as part of its logic to make decisions during execution, so that its behavior (running time and/or correctness) can vary across different runs on the same input, often achieving simpler logic or better expected performance than the best known deterministic algorithm.

🗣️ Hinglish

Randomized algorithms apne decisions lene ke liye randomness (random numbers) use karte hain — isliye same input par bhi different runs mein different behavior dikh sakta hai. Yeh do main types ke hote hain: Las Vegas (jo hamesha correct answer dete hain, sirf time vary karta hai) aur Monte Carlo (jo fixed time mein chalte hain, lekin kabhi-kabhi galat answer de sakte hain — chance se).

Two Main Categories

  • 🎰 Las Vegas Algorithms: Always produce a correct result; only the running time is a random variable.
  • 🎲 Monte Carlo Algorithms: Have a fixed (bounded) running time; the correctness of the result is probabilistic (may occasionally be wrong).

5.4 Las Vegas Algorithms EXAM HOT

📖 Definition

A Las Vegas Algorithm is a randomized algorithm that always produces a correct answer whenever it terminates, but its running time is a random variable that may vary between executions, depending on the random choices made.

🗣️ Hinglish

Las Vegas algorithm "Bet hamesha jeetegi, sirf time pata nahi kitna lagega" — yeh hamesha correct answer dega, bas execution time har baar alag ho sakta hai (random choices ki wajah se). Classic example hai Randomized Quick Sort — pivot randomly choose hota hai, isliye average case O(n log n) milta hai (worst case bahut rarely hota hai), lekin sort result hamesha 100% correct hota hai.

Example: Randomized Quick Sort

Instead of always picking a fixed pivot (e.g., the last element), the pivot is chosen uniformly at random from the sub-array at each recursive call. This makes the worst-case O(n²) behavior (caused by adversarial/sorted input) extremely unlikely, giving an expected time complexity of O(n log n) regardless of input arrangement, while the sort result is always correct.

5.5 Monte Carlo Algorithms EXAM HOT

📖 Definition

A Monte Carlo Algorithm is a randomized algorithm that runs in a fixed (deterministic or tightly bounded) running time, but whose output may be incorrect with some small, bounded probability; repeating the algorithm multiple times can reduce the error probability to an arbitrarily small value.

🗣️ Hinglish

Monte Carlo algorithm "Time fixed hai, but answer galat bhi ho sakta hai (chhoti probability se)" — yeh hamesha ek fixed time mein result de dega, lekin kabhi-kabhi (kam probability se) galat answer aa sakta hai. Agar algorithm ko baar-baar (independently) repeat karke majority/consistent answer liya jaaye, toh error probability bahut chhoti ho jaati hai. Primality testing (Miller-Rabin test) is iska classic example hai.

Example: Miller-Rabin Primality Test

To test if a number n is prime, the algorithm picks random "witness" values and performs modular exponentiation checks; if n fails a check, it is definitely composite, but if n passes all checks, it is only probably prime (with a tiny chance of error). Running the test with k independent random witnesses reduces the error probability to at most 1/4^k, making it practically reliable for very large k.

Las Vegas vs Monte Carlo

BasisLas VegasMonte Carlo
CorrectnessAlways correctMay be incorrect (with bounded probability)

Improving reliabilityN/A — already always correctRepeat multiple times to reduce error probability

5.6 Randomized Algorithm for Min-Cut (Karger's Algorithm) MOST IMPORTANT — 10 MARK

📖 Definition

The Min-Cut problem asks for the minimum number of edges whose removal disconnects a connected, undirected graph into two parts. Karger's randomized algorithm is a Monte Carlo algorithm that finds a min-cut by repeatedly choosing a random edge and contracting it (merging its two endpoint vertices) until only 2 "super-vertices" remain — the edges between them form a candidate cut.

🗣️ Hinglish

Min-Cut problem mein humein graph ke saare vertices ko 2 groups mein todhna hota hai aise ki dono groups ke beech minimum edges cross hों. Karger's algorithm bahut simple idea use karta hai: ek random edge choose karo, uske dono endpoints ko merge (contract) kar do ek single vertex mein (multi-edges allowed, self-loops remove kar dete hain), aur yeh repeat karte raho jab tak sirf 2 vertices na bach jaayein — bachi hui edges hi candidate min-cut hain. Kyunki random hai, yeh hamesha sahi min-cut nahi deta, isliye algorithm ko multiple baar run karke best (smallest) result lete hain.

Algorithm (Karger's Contraction Algorithm)

KargerMinCut(G): while G has more than 2 vertices: pick a random edge (u, v) from G contract u and v into a single super-vertex (remove resulting self-loops; keep parallel/multi-edges) return the count of edges between the final 2 super-vertices as the candidate min-cut Repeat the whole process many times (e.g., O(n² log n) times) and return the smallest cut found across all runs.

Success Probability & Complexity

Probability a single run finds the true min-cut: ≥ 2 / (n(n-1)) Repeating O(n² log n) times boosts success probability close to 1 Single run time: O(n²); with repetitions: O(n⁴ log n)
💡 Example

For a small graph, repeatedly contracting random edges may, in one run, merge vertices in a way that leaves 3 edges between the final two super-vertices, while another independent run might luckily contract edges in an order that leaves only the true minimum of 2 edges — running the algorithm many times and keeping the smallest cut observed converges to the correct global min-cut with high probability.

5.7 Randomized Algorithm for 2-SAT EXAM HOT

📖 Definition

The 2-SAT (2-Satisfiability) problem asks whether a Boolean formula in conjunctive normal form, where every clause has exactly 2 literals, can be satisfied by some assignment of TRUE/FALSE to its variables. A randomized algorithm for 2-SAT repeatedly picks an unsatisfied clause and randomly flips the value of one of its two variables, converging to a satisfying assignment (if one exists) with high probability in polynomial expected time.

🗣️ Hinglish

2-SAT mein har clause mein exactly 2 literals hote hain (jaise (x1 OR ¬x2)), aur humein dhoondhna hai ki kya saari clauses ko ek saath TRUE banaya ja sakta hai. Randomized approach: kisi bhi random variable assignment se start karo; jab tak koi clause unsatisfied hai, randomly ek unsatisfied clause choose karo, uske 2 variables mein se koi ek randomly flip kar do. Yeh process surprisingly fast (expected O(n²) steps) mein converge ho jaata hai ek satisfying assignment tak, agar koi exist karta hai — yeh ek random-walk based technique hai.

Algorithm

Randomized2SAT(formula, n): assign random TRUE/FALSE to each of the n variables repeat up to O(n²) times: if all clauses are satisfied: return "SATISFIABLE", assignment pick any currently UNSATISFIED clause randomly flip the value of ONE of its 2 variables return "UNSATISFIABLE" (with high confidence, if loop exhausted)

This works because flipping a variable from an unsatisfied clause moves the current assignment, in expectation, one step closer (in Hamming distance) to a true satisfying assignment — modeled as a random walk on a line, which is known to converge in O(n²) expected steps.

💡 Example

For formula (x1∨x2)∧(¬x1∨x2)∧(x1∨¬x2), starting from a random assignment that fails one clause, the algorithm picks that unsatisfied clause and randomly flips one of its two variables; this random-walk process is repeated until all three clauses are simultaneously satisfied (e.g., x1=TRUE, x2=TRUE works here), or the formula is declared unsatisfiable if no assignment exists.

5.8 Multicommodity Flow Problem — Definition 5-MARK

📖 Definition

The Multicommodity Flow Problem generalizes the single-commodity max-flow problem to multiple distinct commodities (k different source-sink pairs) that must simultaneously flow through a shared network, where each edge has a capacity constraint that limits the combined flow of all commodities passing through it.

🗣️ Hinglish

Normal max-flow problem mein sirf ek hi commodity (jaise paani ya data) ek source se ek sink tak bhejni hoti hai. Multicommodity flow mein multiple alag-alag commodities (different source-sink pairs) hoti hain jo same shared network use karti hain — har edge ki ek total capacity hoti hai jo saari commodities ke combined flow ko limit karti hai. Telecom networks (multiple calls), road networks (multiple origin-destination traffic pairs) is type ke real-world examples hain. Yeh problem Linear Programming se model kiya jaata hai aur single-commodity flow se kahin zyada complex hai.

Formulation (High-Level)

Given: graph G=(V,E) with edge capacities c(e) k commodities, each with (source sᵢ, sink tᵢ, demand dᵢ) Find: a flow fᵢ for each commodity i such that: - fᵢ satisfies flow conservation (except at sᵢ, tᵢ) - For every edge e: Σᵢ fᵢ(e) ≤ c(e) (shared capacity constraint) - Each commodity's demand dᵢ is routed from sᵢ to tᵢ

Unlike single-commodity max-flow (solvable exactly and efficiently via Ford-Fulkerson/Edmonds-Karp), multicommodity flow with integer flow requirements is generally NP-Hard; the fractional (LP relaxation) version is solvable in polynomial time.

5.9 Flow Shop Scheduling Problem — Definition 5-MARK

📖 Definition

The Flow Shop Scheduling Problem requires scheduling n jobs, each of which must be processed through the same sequence of m machines (in identical order for every job), to optimize an objective such as minimizing the total completion time (makespan) of all jobs.

🗣️ Hinglish

Flow Shop Scheduling mein saari jobs same order mein, same machines se guzarti hain (jaise factory assembly line — Machine1 → Machine2 → Machine3, har job isi order mein process hoti hai). Goal hota hai jobs ko aise order mein schedule karna ki total makespan (sabse aakhri job ka completion time) minimum ho jaaye. Yeh classic operations research / scheduling problem hai, jiska 2-machine case Johnson's Algorithm se optimally solve hota hai, lekin 3+ machines ke liye general case NP-Hard ho jaata hai.

Problem Formulation (High-Level)

Given: n jobs, m machines processing time p[i][j] = time job i takes on machine j all jobs follow the SAME machine order: M1 → M2 → ... → Mm Find: a job sequence (permutation) that minimizes Makespan = completion time of the LAST job on the LAST machine

For the special case of 2 machines, Johnson's Algorithm gives an optimal O(n log n) solution; for 3 or more machines, the problem is generally NP-Hard and solved via heuristics or branch & bound for small instances.

5.10 Network Capacity Assignment Problem — Definition 5-MARK

📖 Definition

The Network Capacity Assignment Problem requires assigning capacity values to each link (edge) of a communication/transportation network — subject to a total cost or budget constraint — so as to optimize a network performance objective, typically minimizing total delay/congestion or maximizing the achievable throughput while satisfying given traffic demand requirements.

🗣️ Hinglish

Network Capacity Assignment mein humein decide karna hota hai ki network ke har link (edge) par kitni capacity (bandwidth) assign ki jaaye, ek fixed total budget/cost ke andar rehte hue, taaki overall network performance best ho — jaise minimum delay/congestion ya maximum throughput. Yeh telecom aur computer network design mein use hota hai, jahan zyada traffic wale links ko zyada capacity di jaati hai cost-effective tarike se.

Problem Formulation (High-Level)

Given: network graph G=(V,E), traffic demand matrix between node pairs, cost function cost(e, capacity) for assigning capacity to edge e, total available budget B Find: capacity c(e) for every edge e such that: - Σₑ cost(e, c(e)) ≤ B (budget constraint) - All traffic demands can be routed within assigned capacities - A performance objective (e.g., average delay) is optimized

This problem is closely related to multicommodity flow (since traffic demands between many node pairs must be routed) and is typically solved using nonlinear/convex optimization techniques or heuristic search for large networks.

5.12 RTU Exam Questions & Answers (Importance-Wise)

Q1
Formulate the Assignment Problem mathematically and explain how it differs from the Quadratic Assignment Problem. 10 Marks

The Assignment Problem is formulated as minimizing Σᵢ Σⱼ C[i][j]·x[i][j] subject to each agent being assigned exactly one task and each task receiving exactly one agent, with x[i][j] as a 0/1 decision variable, and is solvable optimally in O(n³) time via the Hungarian Method. The Quadratic Assignment Problem extends this by adding a flow-times-distance term over all facility pairs, making the objective quadratic in the decision variables rather than linear, which pushes QAP into the NP-Hard complexity class with no known efficient exact algorithm for large instances.

Q2
Explain Las Vegas and Monte Carlo randomized algorithms with suitable examples. Differentiate between them. 10 Marks

A Las Vegas algorithm always produces a correct result but has a running time that varies randomly between executions, exemplified by Randomized Quick Sort, where random pivot selection avoids worst-case behavior in expectation while always producing a correctly sorted output. A Monte Carlo algorithm instead runs in a fixed/bounded time but may produce an incorrect result with some small probability, exemplified by the Miller-Rabin primality test, where repeating the test with more random witnesses reduces the error probability — the fundamental difference being that Las Vegas trades variable time for guaranteed correctness, while Monte Carlo trades occasional incorrectness for predictable running time.

Q3
Explain Karger's randomized algorithm for the Min-Cut problem with its working and success probability. 10 Marks

Karger's algorithm repeatedly picks a random edge in the graph and contracts its two endpoints into a single super-vertex (removing resulting self-loops but keeping parallel edges), continuing until only two super-vertices remain, at which point the number of edges between them is returned as a candidate min-cut. Since a single run finds the true minimum cut with probability at least 2/(n(n−1)), the algorithm is repeated O(n² log n) times and the smallest cut observed across all runs is returned, boosting the overall success probability close to 1 while keeping the total expected running time polynomial.

Q4
Explain the randomized algorithm for 2-SAT and why it converges efficiently. 10 Marks

The randomized 2-SAT algorithm starts with an arbitrary truth assignment to all variables, and as long as some clause remains unsatisfied, it picks any such clause and randomly flips the value of one of its two variables, repeating this for up to O(n²) iterations. This process behaves like a random walk on a line representing the Hamming distance to a satisfying assignment (if one exists), and because each flip moves the current assignment one step closer to a true satisfying assignment with probability at least 1/2, the expected number of steps needed to reach a satisfying assignment is O(n²), making the algorithm efficient despite its randomness.

Q5
Define and explain the problems of Multicommodity Flow, Flow Shop Scheduling, and Network Capacity Assignment. 10 Marks

The Multicommodity Flow problem routes multiple distinct source-sink commodity pairs simultaneously through a shared network, where every edge's capacity must accommodate the combined flow of all commodities passing through it, generally NP-Hard for integer flows though efficiently solvable in its fractional (LP relaxation) form. Flow Shop Scheduling schedules n jobs through the same fixed sequence of m machines to minimize the overall makespan, optimally solvable in O(n log n) for two machines via Johnson's Algorithm but NP-Hard for three or more machines. Network Capacity Assignment determines how much capacity to allocate to each link of a network under a total budget constraint so as to optimize a performance metric such as delay or throughput while meeting all traffic demands, typically solved using convex optimization or heuristic methods.

Q6
What is a randomized algorithm? Explain its two main categories. 5 Marks

A randomized algorithm incorporates random choices into its execution, so its behavior can differ across runs on identical input, often used to achieve simpler logic or better expected performance than the best deterministic alternative. Its two main categories are Las Vegas algorithms, which always give a correct result but have variable running time, and Monte Carlo algorithms, which run in fixed/bounded time but may occasionally return an incorrect result, with error probability reducible through repetition.

Q7
Explain the formulation of the Assignment Problem as a linear/integer programming problem. 5 Marks

The Assignment Problem is formulated to minimize the total cost Σᵢ Σⱼ C[i][j]·x[i][j], subject to each agent i being assigned to exactly one task (Σⱼ x[i][j]=1) and each task j receiving exactly one agent (Σᵢ x[i][j]=1), with each x[i][j] restricted to binary values 0 or 1. This 0/1 integer programming formulation, despite its combinatorial nature, can be solved optimally in polynomial time using the Hungarian Method due to the special structure of the constraint matrix.

Q8
Why is the Quadratic Assignment Problem considered NP-Hard while the standard Assignment Problem is polynomial-time solvable? 5 Marks

The standard Assignment Problem has a linear objective function (a sum of independent individual pairing costs), which gives the underlying constraint matrix a special totally-unimodular structure that the Hungarian Method exploits to find the optimum in O(n³) time. The Quadratic Assignment Problem's objective instead involves products of pairs of assignment variables (flow between facilities times distance between their assigned locations), destroying this special structure and making the problem combinatorially much harder, placing it in the NP-Hard complexity class with no known polynomial-time exact algorithm.

Q9
Explain the Flow Shop Scheduling problem and state how the 2-machine case is solved optimally. 5 Marks

Flow Shop Scheduling requires sequencing n jobs that must all pass through the same fixed order of m machines, with the goal of minimizing the makespan (the completion time of the last job on the last machine). For the special case of exactly 2 machines, Johnson's Algorithm provides an optimal O(n log n) solution by a specific job-ordering rule based on each job's processing times on the two machines, though for 3 or more machines the general problem becomes NP-Hard.

Q10
Explain the Multicommodity Flow problem and why it is generally harder than the single-commodity max-flow problem. 5 Marks

Multicommodity Flow requires simultaneously routing several distinct source-sink commodity pairs through a shared network where each edge's capacity bounds the combined flow of all commodities together, unlike single-commodity max-flow which only routes one source-sink pair. This shared-capacity coupling between commodities means the elegant exact polynomial-time techniques (like Ford-Fulkerson) used for single-commodity flow do not directly extend, making the integer multicommodity flow problem NP-Hard in general, even though its fractional (LP-relaxed) version remains solvable in polynomial time.
