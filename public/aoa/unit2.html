2.1 Review of Algorithm FOUNDATION

📖 Definition

An algorithm is a finite, well-defined sequence of unambiguous instructions that takes some input, processes it through a series of well-defined steps, and produces an output in a finite amount of time, used to solve a specific computational problem. It is a purely conceptual, language-independent description of a solution.

🗣️ Hinglish Explanation

Algorithm ek step-by-step recipe hai kisi problem ko solve karne ke liye — jaise khana banane ki recipe mein steps fixed hote hain. Har algorithm ka ek input hota hai, kuch defined steps (jo clear aur unambiguous hone chahiye), aur ek output. Algorithm hamesha finite steps mein khatam hona chahiye — infinite loop nahi chal sakta. Yeh sirf ek "idea" hai, kisi bhi language mein likhi ja sakti hai (C, Java, Python) — isliye algorithm khud koi programming language nahi hai.

Properties (Characteristics) of an Algorithm

  • 🎯 Input: Zero or more well-defined inputs, supplied externally.
  • 📤 Output: At least one well-defined output, related to the input.
  • 🔢 Finiteness: Must terminate after a finite number of steps — no algorithm may run forever.
  • ✅ Definiteness: Every step must be precisely and unambiguously defined — no room for interpretation.
  • ⚙️ Effectiveness: Every step must be basic enough to be carried out, in principle, by a person using pen and paper (i.e., feasible/executable).
  • 🌍 Generality (Language Independence): The same algorithm should be applicable to a class of similar problems, not just one specific instance, and should not depend on any particular programming language.

Algorithm Design Tools — Pseudocode & Flowchart

Before an algorithm is coded in an actual programming language, it is usually expressed using one of two tools:

  • Pseudocode: An informal, English-like structured notation (using keywords like if, while, for, return) that describes the logic of the algorithm without worrying about exact language syntax.
  • Flowchart: A graphical/diagrammatic representation of the algorithm's logic using standard symbols — oval (start/end), rectangle (process), diamond (decision), parallelogram (input/output), and arrows (flow of control).
A simple flowchart representing a loop that processes each array element — the graphical counterpart of pseudocode

A Priori vs A Posteriori Analysis

A Priori Analysis

Analyzing an algorithm's efficiency before it is implemented/run on any machine, by mathematically counting the number of basic operations as a function of input size n. This gives a machine-independent measure and is what "asymptotic complexity" refers to.

A Posteriori Analysis (Profiling)

Measuring an algorithm's actual running time and memory usage after implementing and executing it on a real machine, typically using timers/profilers. This is machine and implementation dependent (affected by compiler, hardware, OS load).

📌 Algorithm vs Program: An algorithm is a language-independent, conceptual solution (pseudocode/flowchart), whereas a program is its concrete implementation in a specific programming language. RTU exams frequently ask this exact 2–3 mark distinction.

2.2 Complexity & Calculating Complexity EXAM HOT — NUMERICAL

📖 Definition

The complexity of an algorithm is a measure of the amount of time (time complexity) and memory/space (space complexity) it requires to run, expressed as a function of the input size n, independent of the machine or implementation.

🗣️ Hinglish

Complexity batati hai ki input size (n) badhne par algorithm kitna time/memory lega. Hum machine-specific actual seconds nahi count karte, balki basic operations (comparisons, additions) ki count karte hain as a function of n. Time complexity zyada important hai exams mein, especially loops ke through calculate karna.

Steps to Calculate Time Complexity

  • 1️⃣ Identify the basic operation (comparison, assignment, arithmetic op) that is executed most frequently.
  • 2️⃣ Count how many times this operation executes as a function of input size n.
  • 3️⃣ A single loop running n times → O(n); nested loop (n × n) → O(n²); loop that halves each time → O(log n); two separate (sequential) loops → added (not multiplied) → still O(n) overall (dominant term kept).
  • 4️⃣ Keep only the highest-order (dominant) term and drop constants — this gives the asymptotic complexity.
💡 Example

For nested loops for(i=0;i<n;i++) for(j=0;j<n;j++) sum++; the inner statement executes n×n = n² times → Time Complexity = O(n²). For a loop where i doubles each time (i=i*2) until i<n, it runs log₂n times → O(log n).

Space Complexity

Space Complexity is the total amount of memory an algorithm needs, made up of two parts:

S(n) = Fixed Part + Variable Part Fixed Part → space for constants, simple variables, program code (independent of n) Variable Part → space for dynamically allocated structures, recursion stack, input-dependent arrays (depends on n)

For example, an iterative factorial function uses only O(1) extra space, while a recursive factorial function uses O(n) extra space due to n stacked function-call frames on the call stack.

2.3 Asymptotic (Order) Notations MUST KNOW

📖 Definition

Asymptotic notations are mathematical tools (Big-O, Big-Omega, Big-Theta, and their strict counterparts small-o and small-omega) used to describe the growth rate of an algorithm's running time as the input size n approaches infinity, allowing comparison of algorithms independent of hardware or constant factors.

🗣️ Hinglish

Asymptotic notations ek tarah se "upper bound", "lower bound" aur "tight bound" batate hain algorithm ki growth rate ki — bina exact constant factors ki chinta kiye. Yeh humein bade n (input size) ke liye algorithm ka behavior samajhne mein madad karte hain.

Five Asymptotic Notations

NotationBound TypeMathematical DefinitionMeaning
O (Big-Oh)Upper bound (≤)f(n) ≤ c·g(n) for n≥n₀Worst-case growth rate (most commonly used)
Ω (Omega)Lower bound (≥)f(n) ≥ c·g(n) for n≥n₀Best-case growth rate
Θ (Theta)Tight bound (=)c₁·g(n) ≤ f(n) ≤ c₂·g(n)Exact (average) growth rate, both bounds match
o (small-oh)Strict upper bound (<)f(n) < c·g(n) for all c>0f(n) grows strictly slower than g(n)
ω (small-omega)Strict lower bound (>)f(n) > c·g(n) for all c>0f(n) grows strictly faster than g(n)

Big-O/Ω allow the case where f(n) and g(n) grow at exactly the same rate (non-strict, "≤"/"≥"); small-o/ω are strict versions ("<"/">") that exclude equality of growth rate — a subtle but favorite viva/theory question.

Big-O (upper), Big-Omega (lower) and Big-Theta (tight) bounds on growth rate

2.5 Divide and Conquer Method + Master Theorem EXAM HOT

📖 Definition

The Divide and Conquer technique solves a problem by (1) dividing it into smaller sub-problems of the same type, (2) recursively conquering (solving) each sub-problem, and (3) combining the sub-solutions to form the solution to the original problem.

🗣️ Hinglish

Divide and Conquer ka idea simple hai — bade problem ko chhote-chhote independent sub-problems mein todo, har sub-problem ko recursively solve karo (chhote hote hote base case tak), aur phir un sub-solutions ko combine karke final answer banao. Merge Sort, Quick Sort, Binary Search isi technique par based hain.

Three Steps of D&C

  • ✂️ Divide: Break the problem into smaller sub-problems of the same type.
  • ⚔️ Conquer: Solve the sub-problems recursively; if small enough, solve directly (base case).
  • 🔗 Combine: Merge the sub-problem solutions to get the solution of the original problem.

General Recurrence Relation

T(n) = a·T(n/b) + f(n) where a = number of sub-problems, n/b = size of each sub-problem, f(n) = cost of divide+combine

Solved using the Master Theorem, recursion tree method, or substitution method to get the closed-form time complexity.

The Master Theorem — All 3 Cases EXAM HOT — MOST ASKED

For a recurrence of the form T(n) = a·T(n/b) + f(n), where a≥1, b>1, compare f(n) with nlogba:

CaseConditionResult
Case 1f(n) = O(nlogba − ε) for some ε>0 (f(n) grows polynomially slower)T(n) = Θ(nlogba)
Case 2f(n) = Θ(nlogba) (f(n) grows at the same rate)T(n) = Θ(nlogba · log n)
Case 3f(n) = Ω(nlogba + ε) for some ε>0, and a·f(n/b) ≤ c·f(n) (regularity condition), (f(n) grows polynomially faster)T(n) = Θ(f(n))
💡 Worked Examples — One Per Case

Case 1: T(n) = 8T(n/2) + n² → a=8, b=2, nlog₂8=n³. Since f(n)=n² grows slower than n³ → T(n) = Θ(n³).

Case 2: T(n) = 2T(n/2) + n → a=2, b=2, nlog₂2=n. Since f(n)=n matches n exactly → T(n) = Θ(n log n) (this is exactly Merge Sort's recurrence!).

Case 3: T(n) = 3T(n/4) + n² → a=3, b=4, nlog₄3 ≈ n0.79. Since f(n)=n² grows faster → T(n) = Θ(n²).

Recursion Tree Method (Alternative to Master Theorem)

The recursion tree method solves a recurrence by drawing out each level of recursive calls, computing the total work done at each level, then summing across all levels.

Recursion tree for T(n)=2T(n/2)+n (Merge Sort): every level costs n, and there are log₂n levels

2.6 Binary Search EXAM HOT — NUMERICAL

📖 Definition

Binary Search is a Divide and Conquer searching algorithm that finds a target value in a sorted array by repeatedly comparing the target with the middle element and discarding the half of the array that cannot contain it.

🗣️ Hinglish

Binary search sirf sorted array par kaam karta hai. Hum middle element check karte hain — agar target usse chhota hai toh left half mein search karo, bada hai toh right half mein, equal hai toh mil gaya. Har step par array aadha ho jaata hai, isliye yeh bahut fast hai.

Algorithm — Iterative

BinarySearch(A, low, high, key): while low <= high: mid = (low + high) / 2 if A[mid] == key: return mid else if A[mid] < key: low = mid + 1 else: high = mid - 1 return -1 (not found)

Algorithm — Recursive

BinarySearchRec(A, low, high, key): if low > high: return -1 mid = (low + high) / 2 if A[mid] == key: return mid else if A[mid] < key: return BinarySearchRec(A, mid+1, high, key) else: return BinarySearchRec(A, low, mid-1, key)

Recurrence & Complexity

T(n) = T(n/2) + O(1) → T(n) = O(log n) [Master Theorem: a=1, b=2, f(n)=O(1)=n⁰, log₂1=0, Case 2]
CaseComplexity
Best CaseO(1) (found at first middle)
Worst/Average CaseO(log n)
Space ComplexityO(1) iterative / O(log n) recursive (call stack)
PreconditionArray MUST already be sorted
💡 Example

Search key=23 in sorted array [4,8,15,16,23,42,56]: low=0,high=6,mid=3→A[3]=16<23→low=4; mid=5→A[5]=42>23→high=4; mid=4→A[4]=23 → Found at index 4 in just 3 comparisons (vs up to 7 for linear search).

2.8 Merge Sort MUST KNOW — 10 MARK

📖 Definition

Merge Sort is a stable, Divide and Conquer sorting algorithm that recursively splits the array into two halves, sorts each half independently, and then merges the two sorted halves into a single sorted array.

🗣️ Hinglish

Merge Sort array ko baar-baar aadha-aadha todhta hai jab tak single element na bach jaaye (jo already sorted hai), phir un chhote sorted pieces ko jodte (merge) hue wapas badi sorted array banata hai. Merging step mein dono sorted halves ko compare karke ek-ek element nikal kar final array banti hai.

Algorithm

MergeSort(A, low, high): if low < high: mid = (low+high)/2 MergeSort(A, low, mid) MergeSort(A, mid+1, high) Merge(A, low, mid, high) Merge(A, low, mid, high): Copy A[low..mid] and A[mid+1..high] into temp arrays L and R Repeatedly pick the smaller front element of L/R into A, in order Copy any remaining elements of L or R into A

Recurrence & Complexity

T(n) = 2T(n/2) + O(n) → T(n) = O(n log n) (by Master Theorem, Case 2)
CaseTime Complexity
Best / Average / WorstO(n log n) — same in all cases
Space ComplexityO(n) — needs extra array for merging
StabilityStable (preserves relative order of equal elements)
Merge sort: split into halves recursively, then merge sorted halves back together
💡 Full Dry-Run: Sort [38,27,43,3,9,82,10]

Splitting continues until single elements: [38],[27],[43],[3],[9],[82],[10]. Merging bottom-up:

Merge [38] & [27] → [27,38] Merge [43] & [3] → [3,43] Merge [27,38] & [3,43] → [3,27,38,43] Merge [9] & [82] → [9,82] Merge [9,82] & [10] → [9,10,82] Merge [3,27,38,43] & [9,10,82] → [3,9,10,27,38,43,82] (final sorted array)

2.9 Quick Sort EXAM HOT — NUMERICAL

📖 Definition

Quick Sort is a Divide and Conquer sorting algorithm that selects a pivot element, partitions the array so all elements smaller than the pivot go to its left and all larger elements go to its right, and then recursively sorts the two partitions.

🗣️ Hinglish

Quick Sort ek pivot element choose karta hai (often last element), aur array ko is tarah rearrange karta hai ki pivot se chhote elements left mein aur bade elements right mein chale jaayein — yeh process "partitioning" kehlata hai. Phir dono partitions ko recursively quick-sort kiya jaata hai. In-place hone ki wajah se yeh memory-efficient hai, lekin worst case mein slow ho sakta hai (already sorted array par bad pivot choice se).

Algorithm (Lomuto Partition Scheme)

QuickSort(A, low, high): if low < high: pi = Partition(A, low, high) QuickSort(A, low, pi-1) QuickSort(A, pi+1, high) Partition(A, low, high): pivot = A[high] i = low - 1 for j = low to high-1: if A[j] < pivot: i = i+1; swap(A[i], A[j]) swap(A[i+1], A[high]) return i+1

Hoare Partition Scheme (Alternative)

The original scheme proposed by Tony Hoare uses two pointers moving toward each other from both ends, swapping out-of-place pairs, and is generally more efficient (fewer swaps) than Lomuto's scheme, though slightly trickier to implement correctly.

HoarePartition(A, low, high): pivot = A[low] i = low - 1; j = high + 1 loop: do i++ while A[i] < pivot do j-- while A[j] > pivot if i >= j: return j swap(A[i], A[j])

Pivot Selection Strategies

  • First/Last Element: Simplest, but gives O(n²) worst case on already-sorted or reverse-sorted input.
  • Random Pivot: Picking a random index as pivot makes worst-case behaviour extremely unlikely in practice, giving expected O(n log n).
  • Median-of-Three: Choosing the median of the first, middle, and last elements as the pivot — avoids the worst case for sorted/nearly-sorted inputs, commonly used in production sort libraries.

Complexity Analysis

CaseConditionTime Complexity
Best CasePivot always divides array into two equal halvesO(n log n)
Average CaseRandom pivot positionsO(n log n)
Worst CaseAlready sorted/reverse-sorted array + poor pivot choice (always smallest/largest)O(n²)

Space Complexity: O(log n) average (recursion stack) for in-place partitioning; Quick Sort is not stable by default.

💡 Numerical Example: Partition [10,80,30,90,40,50,70], pivot=70 (last element)

Scan j=0..5, swap whenever A[j]<70: i tracks boundary of "smaller" zone.

j=0: 10<70 → i=0, swap(A[0],A[0]) → [10,80,30,90,40,50,70] j=1: 80≥70 → skip j=2: 30<70 → i=1, swap(A[1],A[2]) → [10,30,80,90,40,50,70] j=3: 90≥70 → skip j=4: 40<70 → i=2, swap(A[2],A[4]) → [10,30,40,90,80,50,70] j=5: 50<70 → i=3, swap(A[3],A[5]) → [10,30,40,50,80,90,70] Final: swap(A[4],A[6]) → [10,30,40,50,70,90,80]; pivot 70 placed at index 4

2.11 Strassen's Matrix Multiplication EXAM HOT — 10 MARK

📖 Definition

Strassen's Algorithm is a Divide and Conquer method to multiply two n×n matrices using only 7 multiplications (instead of the conventional 8) of n/2 × n/2 sub-matrices, by cleverly combining sums and differences of sub-matrices, reducing the overall time complexity below the conventional O(n³).

🗣️ Hinglish

Normal matrix multiplication mein har 2×2 block-multiplication ke liye 8 multiplications lagti hain, jisse O(n³) complexity aati hai. Strassen ne ek clever trick nikala jisse sirf 7 multiplications (aur extra additions/subtractions) se kaam ho jaata hai. Multiplication, addition se zyada costly operation maana jaata hai, isliye multiplications kam karne se overall complexity improve ho jaati hai → O(n^2.81).

Conventional Method (Recap)

For two n×n matrices, the conventional definition-based method computes each output element as a dot product of a row and a column, requiring n multiplications per element across n² elements:

C[i][j] = Σ (A[i][k] × B[k][j]) for k=1 to n Total operations = n × n × n = n³ → O(n³)

Strassen's 7 Multiplications

For 2×2 matrices A and B divided into sub-matrices A11,A12,A21,A22 and B11,B12,B21,B22:

M1 = (A11+A22)(B11+B22) M2 = (A21+A22)·B11 M3 = A11·(B12−B22) M4 = A22·(B21−B11) M5 = (A11+A12)·B22 M6 = (A21−A11)(B11+B12) M7 = (A12−A22)(B21+B22)

Result quadrants are then computed from these 7 products:

C11 = M1+M4−M5+M7 C12 = M3+M5 C21 = M2+M4 C22 = M1−M2+M3+M6
💡 Fully Worked Numeric Example

Multiply A = [[1,2],[3,4]] and B = [[5,6],[7,8]] using Strassen's method. Here A11=1, A12=2, A21=3, A22=4, B11=5, B12=6, B21=7, B22=8.

M1 = (1+4)(5+8) = 5×13 = 65 M2 = (3+4)×5 = 7×5 = 35 M3 = 1×(6−8) = 1×(−2) = −2 M4 = 4×(7−5) = 4×2 = 8 M5 = (1+2)×8 = 3×8 = 24 M6 = (3−1)(5+6) = 2×11 = 22 M7 = (2−4)(7+8) = (−2)×15 = −30 C11 = M1+M4−M5+M7 = 65+8−24−30 = 19 C12 = M3+M5 = −2+24 = 22 C21 = M2+M4 = 35+8 = 43 C22 = M1−M2+M3+M6 = 65−35−2+22 = 50 Result C = [[19,22],[43,50]] (matches conventional multiplication ✓)

Recurrence & Complexity

T(n) = 7T(n/2) + O(n²) → T(n) = O(n^log₂7) ≈ O(n^2.81) [Master Theorem Case 1: n^log₂7 ≈ n^2.81 > n²]

This is asymptotically faster than the conventional method's O(n³), especially noticeable for very large matrices — although the larger constant factor and additional additions make it beneficial mainly for large n in practice.

2.13 RTU Exam Questions & Answers (Importance-Wise)

Q1
Define algorithm and explain its characteristics. How is complexity of an algorithm calculated? 10 Marks

An algorithm is a finite sequence of unambiguous, well-defined steps that transforms given input into the desired output. Its key characteristics are input, output, finiteness, definiteness, effectiveness, and generality. Complexity is calculated by identifying the basic operation in the algorithm, counting its frequency as a function of input size n (e.g., a single loop gives O(n), nested loops give O(n²), a halving loop gives O(log n)), and then retaining only the dominant term while ignoring constants, to express time complexity asymptotically.

Q2
Explain Big-O, Big-Omega, and Big-Theta asymptotic notations with examples. 5 Marks

Big-O notation gives the asymptotic upper bound (worst-case growth) of a function, Big-Omega gives the asymptotic lower bound (best-case growth), and Big-Theta gives a tight bound that holds when the upper and lower bounds coincide, representing the average/exact growth rate. For example, linear search has O(n) worst case and Ω(1) best case, while binary search has Θ(log n) since its best, average, and worst cases all share the same logarithmic order.

Q3
Explain Merge Sort algorithm with example and derive its time complexity. 10 Marks

Merge Sort recursively divides the array into two halves until single-element sub-arrays remain, then repeatedly merges adjacent sorted sub-arrays by comparing their front elements until the entire array is sorted, as illustrated by sorting [38,27,43,3,9,82,10] down to single elements and merging back up. Its recurrence is T(n) = 2T(n/2) + O(n), which by the Master Theorem (Case 2) resolves to T(n) = O(n log n) in all cases (best, worst, and average), with O(n) additional space required for merging.

Q4
Write the Quick Sort algorithm and explain its best, average, and worst-case time complexity. 10 Marks

Quick Sort selects a pivot, partitions the array using a scheme such as Lomuto's (placing smaller elements before the pivot and larger ones after), and recursively sorts the two resulting partitions. When the pivot consistently splits the array into roughly equal halves, the recurrence T(n)=2T(n/2)+O(n) gives O(n log n) for best and average cases; however, if the pivot is always the smallest or largest element (e.g., on an already-sorted array), the recurrence becomes T(n)=T(n-1)+O(n), giving a worst case of O(n²).

Q5
Explain Strassen's matrix multiplication algorithm and derive its time complexity. 10 Marks

Strassen's algorithm divides each n×n matrix into four n/2×n/2 sub-matrices and computes the product using only 7 cleverly constructed multiplications (M1 through M7, combining sums/differences of sub-matrices) instead of the conventional 8, with the four result quadrants obtained by adding/subtracting these 7 products. The recurrence T(n)=7T(n/2)+O(n²) solves to T(n)=O(n^log₂7) ≈ O(n^2.81), which is asymptotically faster than the conventional O(n³) method, since multiplication is computationally costlier than addition.

Q6
Explain Binary Search algorithm and find its time complexity using recurrence relation. 5 Marks

Binary Search operates on a sorted array by comparing the target key with the middle element; if equal it returns the index, if the key is smaller it recurses on the left half, otherwise on the right half, discarding the other half each time. Since each step reduces the problem size to n/2 with constant extra work, its recurrence is T(n)=T(n/2)+O(1), which resolves to T(n)=O(log n).

Q7
Differentiate between Merge Sort and Quick Sort. 5 Marks

Merge Sort guarantees O(n log n) time in all cases and is stable, but requires O(n) extra space for merging, making it well suited for linked lists and external sorting. Quick Sort sorts in-place with only O(log n) extra space and is typically faster in practice due to lower constant factors, but is not stable and can degrade to O(n²) in the worst case (e.g., poor pivot selection on sorted data).

Q8
Explain the Divide and Conquer strategy with its general structure and recurrence relation. 5 Marks

Divide and Conquer solves a problem by dividing it into smaller sub-problems of the same type, recursively conquering (solving) each sub-problem down to a base case, and combining the sub-solutions into the final answer. Its general time complexity follows the recurrence T(n) = a·T(n/b) + f(n), where a is the number of sub-problems, n/b is each sub-problem's size, and f(n) is the cost of dividing and combining; this is typically solved using the Master Theorem.

Q9
What are best case, worst case, and average case complexity? Explain with an example. 5 Marks

Best case complexity is the minimum running time over all possible inputs of a given size (the most favorable scenario), worst case is the maximum running time (least favorable scenario), and average case is the expected running time averaged over all possible inputs. For linear search, the best case is O(1) when the key is found at the first position, the worst case is O(n) when it is at the last position or absent, and the average case is also O(n).

Q10
Sort the array [10,80,30,90,40,50,70] using Quick Sort, showing the partition steps. 10 Marks

Using the last element 70 as pivot, the Lomuto partition scan compares each element to 70 and swaps smaller elements into the front region: 10 stays, 80 is skipped, 30 swaps into position, 90 is skipped, 40 and 50 swap into position, finally placing the pivot at index 4, giving [10,30,40,50,70,90,80]. The algorithm then recursively quick-sorts the left partition [10,30,40,50] and the right partition [90,80], eventually producing the fully sorted array [10,30,40,50,70,80,90].

Q11
State the Master Theorem with all three cases and solve T(n) = 2T(n/2) + n log n. 10 Marks

For T(n) = aT(n/b) + f(n): Case 1 applies when f(n) = O(n^(log_b a − ε)), giving T(n) = Θ(n^log_b a); Case 2 applies when f(n) = Θ(n^log_b a), giving T(n) = Θ(n^log_b a · log n); and Case 3 applies when f(n) = Ω(n^(log_b a + ε)) with a regularity condition, giving T(n) = Θ(f(n)). For T(n) = 2T(n/2) + n log n: a=2, b=2, so n^log_b a = n. Since f(n) = n log n grows faster than n by more than a polynomial factor of log n (technically a boundary case between Case 2 and 3, solved via the extended/Akra-Bazzi form), the result is T(n) = Θ(n log²n).

Q12
Explain space complexity with an example comparing iterative and recursive implementations. 5 Marks

Space complexity is the total memory an algorithm needs, consisting of a fixed part (constants, simple variables, code) and a variable part (dynamic allocations, recursion stack, input-dependent structures) that grows with input size n. An iterative factorial function uses only a constant number of variables regardless of n, giving O(1) space, whereas a recursive factorial function creates a new stack frame for each recursive call down to the base case, requiring O(n) space on the call stack.
