3.1 Greedy Method — Concept FOUNDATION

📖 Definition

The Greedy Method is a problem-solving strategy that builds up a solution piece by piece, at each step choosing the option that looks locally optimal (best at that moment), without reconsidering earlier choices, in the hope that this sequence of local choices leads to a globally optimal solution.

🗣️ Hinglish Explanation

Greedy approach mein hum har step par "abhi ke liye sabse best" choice lete hain, bina yeh soche ki future mein iska kya effect hoga, aur kabhi bhi piche jaakar decision change nahi karte. Yeh fast aur simple hota hai, lekin hamesha optimal (sabse best) answer nahi deta — sirf un problems ke liye guaranteed optimal hota hai jinme "greedy choice property" aur "optimal substructure" hoti hai.

Key Requirements for Greedy to Work

  • 🎯 Greedy Choice Property: A globally optimal solution can be reached by making a locally optimal (greedy) choice at each step.
  • 🧩 Optimal Substructure: An optimal solution to the problem contains optimal solutions to its sub-problems.

General Structure of a Greedy Algorithm

  1. Candidate Set: Identify the full set of candidates/inputs from which the solution will be built (items, jobs, edges, files, etc.).
  2. Selection Function / Heuristic: Define an ordering rule — e.g. sort by profit/weight ratio, by deadline, by edge weight, by file size.
  3. Feasibility Check: At each step, test whether adding the next-best candidate still keeps the partial solution valid (does not violate the capacity/deadline/cycle constraint).
  4. Objective Function: The function being maximised/minimised (total profit, total cost, total weight).
  5. Solution Function: Tests whether a complete solution has been reached (all vertices covered, all slots tried, capacity exhausted).
Fig 3.1 — General flow of any Greedy Algorithm: sort → pick best → check feasibility → loop until candidates exhausted.

Advantages, Limitations & Real-World Uses

✅ Advantages

Simple to design and implement, usually runs in polynomial time (often O(n log n) due to sorting), needs very little extra memory, and gives exact optimal answers for a well-defined class of problems (matroid-structured problems).

⚠ Limitations

Never reconsiders a decision once made, so it can get trapped in a locally-optimal but globally-suboptimal solution (classic failure: 0/1 Knapsack). It must be proved correct for each problem separately — there is no universal correctness guarantee.

📌 Real-life analogy: Giving minimum currency notes/coins for change (coin-change with standard denominations), Huffman encoding for compression, Dijkstra's shortest path, and network routing protocols all use the greedy strategy.

3.2 Fractional Knapsack Problem (Greedy) EXAM HOT — NUMERICAL

📖 Definition

The Fractional Knapsack Problem requires filling a knapsack of capacity W with items (each having a weight and a profit/value) — items can be broken into fractions — to maximize the total profit, solved optimally by the greedy strategy of picking items in decreasing order of profit/weight ratio.

🗣️ Hinglish

Fractional Knapsack mein item ko todha (fraction mein liya) ja sakta hai — jaise sona ka kuch gram le lo. Strategy simple hai: har item ka profit/weight ratio nikalo, sabse high ratio wale item ko poora utha lo, fir agla, jab tak bag bhar na jaaye — agar last item poora nahi aata toh uska fraction le lo. Yeh greedy approach hamesha optimal solution deta hai is problem ke liye.

Algorithm

1. Compute ratio[i] = profit[i] / weight[i] for every item 2. Sort items in decreasing order of ratio 3. For each item (in sorted order): if weight[i] <= remaining capacity: take it fully else: take fraction = remaining_capacity / weight[i]; STOP

🖥️ Step-by-Step Simulation

💡 Numerical Example: W=50, Items (profit,weight): (60,10),(100,20),(120,30)

Ratios: 60/10=6, 100/20=5, 120/30=4 → sort by ratio: Item1(6), Item2(5), Item3(4).

Why Greedy is Provably Optimal Here

This can be proved by an exchange argument: suppose an optimal solution does not pick items in decreasing ratio order. Then two adjacent items can be swapped (moving more of the higher-ratio item in, and less of the lower-ratio item) without decreasing total profit — because fractions are allowed, there is no "wasted" leftover capacity, so the greedy choice never costs anything.

📌 Complexity: Sorting dominates — O(n log n) time, O(1) extra space (in-place greedy scan after sort).

3.3 Job Sequencing with Deadlines (Greedy) EXAM HOT

📖 Definition

Job Sequencing with Deadlines is the problem of scheduling a set of jobs, each with a deadline and a profit, on a single processor (one job per unit time slot) to maximize total profit, where profit is earned only if a job completes within its deadline.

🗣️ Hinglish

Har job ek deadline aur profit ke saath aati hai. Hum jobs ko profit ke decreasing order mein sort karte hain, aur har job ko uske deadline se ek slot pehle, sabse late available free slot mein fit karne ki koshish karte hain (taaki earlier slots dusri jobs ke liye free rahein). Agar koi free slot nahi milta deadline tak, toh job skip kar di jaati hai.

Algorithm

1. Sort all jobs in decreasing order of profit 2. Let max deadline = d_max; create d_max empty time slots 3. For each job (in sorted order): Find the latest free slot available before (or at) its deadline If found: place job in that slot Else: reject the job

3.4 Optimal Merge Patterns (Greedy) 5-MARK

📖 Definition

The Optimal Merge Pattern problem finds the order in which a set of sorted files (of given sizes) should be pairwise merged so that the total number of record comparisons (cost) across all merges is minimized, solved greedily by always merging the two smallest files/lists available at each step.

🗣️ Hinglish

Jab humein multiple sorted files ko ek single sorted file mein merge karna hota hai, toh order important hai — galat order se zyada comparisons lagte hain. Greedy strategy: hamesha do sabse chhoti files ko pehle merge karo, unka result wapas list mein daalo, aur phir se do sabse chhoti uthao. Yeh exactly Huffman coding jaisi technique hai aur min-heap se efficiently implement hoti hai.

Algorithm

1. Put all file sizes into a min-priority-queue (min-heap) 2. While more than 1 file remains: Extract the two smallest files, x and y Merge them: new file size = x + y; cost += (x+y) Insert merged file size back into the heap 3. Total cost = sum of all merge costs (weighted path length)

🖥️ Step-by-Step Simulation (Min-Heap Trace)

💡 Numerical Example: Files of sizes 20, 30, 10, 5

Fig 3.3 — Merge tree (identical structure to a Huffman coding tree): leaves = original file sizes, internal nodes = merge costs.
📌 Complexity: With a min-heap, each extract-min/insert is O(log n) and there are (n−1) merges → total O(n log n). This is exactly the same technique used to build a Huffman coding tree.

3.5 Minimal Spanning Trees — Prim's & Kruskal's (Greedy) EXAM HOT — 10 MARK

📖 Definition

A Minimum Spanning Tree (MST) of a connected, weighted, undirected graph is a subset of its edges that connects all vertices together, without any cycles, while minimizing the total edge weight. Prim's and Kruskal's algorithms are two classic greedy methods to construct an MST.

🗣️ Hinglish

MST woh tree hai jo graph ke saare vertices ko jodta hai minimum total edge weight ke saath, bina koi cycle banaye. Prim's algorithm ek vertex se start karke tree ko grow karta hai (har baar minimum weight wala connecting edge jodte hue), jabki Kruskal's algorithm saare edges ko weight ke according sort karke, cycle avoid karte hue, sabse chhote edges choose karta hai.

Prim's Algorithm

1. Start with any single vertex in the MST set 2. Repeat (n-1) times: Find the minimum-weight edge connecting a vertex INSIDE the MST set to a vertex OUTSIDE the MST set Add that edge and the new vertex to the MST set 3. Stop when all vertices are included

Implemented efficiently using a min-priority-queue; grows the tree vertex by vertex.

Kruskal's Algorithm

1. Sort all edges of the graph in increasing order of weight 2. Initialize each vertex as its own separate set (Union-Find / Disjoint Set) 3. For each edge (u,v) in sorted order: if find(u) != find(v): // doesn't form a cycle add edge to MST union(u, v) 4. Stop when MST has (n-1) edges

Uses the Union-Find (Disjoint Set) data structure to efficiently detect cycles; grows the forest edge by edge.

📌 Prim's vs Kruskal's: Prim's works well on dense graphs (grows one connected tree), while Kruskal's works well on sparse graphs (sorts all edges globally and uses Union-Find). Both always produce a minimum-weight spanning tree, though the specific set of edges may differ if weights repeat — the total weight will not.

3.6 Dynamic Programming — Concept FOUNDATION

📖 Definition

Dynamic Programming (DP) is an optimization technique that solves complex problems by breaking them into overlapping sub-problems, solving each sub-problem only once, and storing (memoizing) its result — avoiding the re-computation that plain recursion would otherwise repeat.

🗣️ Hinglish

DP tab use hoti hai jab problem ko chhote sub-problems mein todha jaa sakta ho, aur woh sub-problems baar-baar repeat (overlap) hote hों. DP unke results ko ek table (array) mein store kar leti hai, taaki dobara calculate na karna pade — isse exponential time complexity polynomial time mein convert ho jaati hai. Do approaches hoti hain: Top-Down (Memoization, recursion + cache) aur Bottom-Up (Tabulation, iterative table filling).

Key Requirements for DP to Apply

  • 🔁 Overlapping Sub-problems: The same smaller sub-problems are solved multiple times in a naive recursive solution.
  • 🧩 Optimal Substructure: The optimal solution to the problem can be built from optimal solutions of its sub-problems.

Why Plain Recursion Fails — Fibonacci Example

Fig 3.5 — Recursion tree for naive Fibonacci F(5). Red nodes (F(3), F(2), F(1)) are recomputed multiple times — these are the "overlapping sub-problems" that DP eliminates by caching.

Top-Down (Memoization) vs Bottom-Up (Tabulation)

Top-Down (Memoization)

Recursive solution + a lookup table (cache) to store already-computed results, avoiding recomputation. Natural to write, computes only the sub-problems actually needed.

Bottom-Up (Tabulation)

Iterative approach that fills a table starting from base cases, building up to the final solution — usually more space/time efficient (no recursion/call-stack overhead).

3.7 Matrix Chain Multiplication (DP) EXAM HOT — 10 MARK

📖 Definition

The Matrix Chain Multiplication problem finds the most efficient way (i.e., the order of parenthesization) to multiply a chain of matrices, so as to minimize the total number of scalar multiplications — the matrices themselves are not actually reordered, only the placement of parentheses (which pairs to multiply first) is optimized.

🗣️ Hinglish

Matrices ka multiplication associative hota hai, lekin order of multiplication (kaunsa pehle multiply karna hai) se total scalar multiplications ki count bahut change ho sakti hai. MCM problem optimal parenthesization (bracket placement) dhoondhti hai jisse minimum multiplications lagein — DP table m[i][j] use karke saare possible split points try kiye jaate hain aur minimum cost wala choose hota hai.

DP Recurrence

m[i][i] = 0 (single matrix, no multiplication needed) m[i][j] = min over k (i<=k

3.8 Longest Common Subsequence (DP) EXAM HOT — NUMERICAL

📖 Definition

The Longest Common Subsequence (LCS) problem finds the longest sequence of characters that appears, in the same relative order (not necessarily contiguous), in both of two given strings; solved using DP by building a table of LCS lengths for all prefix-pairs of the two strings.

🗣️ Hinglish

Subsequence ka matlab hai characters same order mein hों, lekin continuous (adjacent) hona zaroori nahi — beech mein gaps ho sakte hain. LCS dono strings mein common aisa sabse lamba subsequence dhoondhta hai. DP table dp[i][j] banta hai: agar character match karta hai toh dp[i][j]=dp[i-1][j-1]+1, warna dp[i][j]=max(dp[i-1][j], dp[i][j-1]).

DP Recurrence

dp[i][0] = dp[0][j] = 0 (base case: empty string) if X[i] == Y[j]: dp[i][j] = dp[i-1][j-1] + 1 else: dp[i][j] = max(dp[i-1][j], dp[i][j-1])

3.9 0/1 Knapsack Problem (DP) MOST IMPORTANT — 10 MARK NUMERICAL

📖 Definition

The 0/1 Knapsack Problem requires selecting a subset of items (each with a weight and a profit), where each item is either taken whole or not at all (0/1, no fractions allowed), to maximize total profit without exceeding the knapsack's weight capacity W — solved optimally using Dynamic Programming (unlike the fractional version, Greedy does NOT guarantee optimality here).

🗣️ Hinglish

0/1 Knapsack mein item ko todha nahi ja sakta — ya toh poora lo ya bilkul mat lo. Isliye greedy (ratio-based) approach yahan optimal solution guarantee nahi karta, DP use karni padti hai. Hum ek 2D table dp[i][w] banate hain jisme i = items consider kiye gaye, w = capacity — har cell mein decide karte hain ki current item lena better hai ya chodhna.

DP Recurrence

dp[0][w] = 0 for all w (no items = 0 profit) dp[i][w] = dp[i-1][w] if weight[i] > w dp[i][w] = max( dp[i-1][w], profit[i] + dp[i-1][w-weight[i]] ) otherwise
Fig 3.6 — Decision made when filling each dp[i][w] cell of the 0/1 Knapsack table.

🖥️ Full Worked Example

💡 Numerical Example: W=5, Items (weight,profit): (2,3),(3,4),(4,5),(5,6)

Why Greedy Fails Here (Comparison with Fractional)

With capacity W=10 and items (profit,weight) = (10,5), (10,5), (12,8): the greedy ratio-based choice picks the (12,8) item first (ratio 1.5), leaving only 2 capacity unused — giving profit 12. DP correctly identifies that taking both (10,5) items uses exactly 10 capacity for a profit of 20, proving greedy is not optimal when items cannot be fractionally split.

📌 Complexity: O(n×W) time and O(n×W) space (pseudo-polynomial — depends on the numeric value of W, not just n). Space can be reduced to O(W) using a 1-D array updated right-to-left.

3.12 Common Exam Mistakes & Quick Tips

  • ❌ Applying greedy to 0/1 Knapsack — always solve 0/1 Knapsack with DP; greedy ratio-sorting only works for the Fractional version.
  • ❌ Forgetting to sort in Job Sequencing — jobs must first be sorted by decreasing profit, not by deadline.
  • ❌ Skipping the base row/column in DP tables — always explicitly write dp[0][*] = 0 and dp[*][0] = 0 before filling the rest; examiners award marks for this.
  • ❌ Mixing up MCM index convention — matrix Ai has dimension p[i-1] × p[i]; a chain of n matrices has (n+1) dimension values.
  • ❌ Forgetting the (n-1) edges rule for MST — a spanning tree on n vertices always has exactly n−1 edges; stop as soon as that count is reached.
  • ✅ Always show the trace table (not just the final answer) for 10-mark numericals — RTU awards significant step-marks for the working shown.
Hinglish Trick

Greedy vs DP: Greedy = "Aankh band karke abhi ka best lelo" (No regret, fast). DP = "Har option ka chart banao, purana yaad rakho" (Overlapping + Table look-up, guaranteed best!).

3. Classical DP Problems

  • 0/1 Knapsack: dp[i][w] = max(exclude, include) → O(nW)
  • MCM: m[i][j] = min_k(m[i][k]+m[k+1][j]+p[i-1]p[k]p[j]) → O(n³)
  • LCS: Match: +1 from diagonal; Mismatch: max(left, top) → O(mn)

Q1
Solve the 0/1 Knapsack problem using Dynamic Programming for W=5 and items (weight,profit): (2,3),(3,4),(4,5),(5,6). Show the DP table. 10 Marks

Building the dp[i][w] table row by row, where each cell takes the better of "exclude item i" (dp[i-1][w]) or "include item i" (profit[i] + dp[i-1][w-weight[i]], if it fits), the table fills as shown above, ending with maximum profit dp[4][5] = 7, achieved by choosing items (2,3) and (3,4), using total weight 5 and yielding total profit 7.

Q2
Explain Greedy Method and Dynamic Programming. Differentiate between them with examples. 10 Marks

The Greedy Method builds a solution by repeatedly making the locally best choice at each step without reconsidering past decisions, which works only when the problem has the greedy-choice property and optimal substructure (e.g., Fractional Knapsack, MST). Dynamic Programming instead solves and stores results for all relevant overlapping sub-problems, guaranteeing the global optimum whenever optimal substructure holds, at the cost of extra time/memory for the DP table (e.g., 0/1 Knapsack, Matrix Chain Multiplication, LCS).

Q3
Find the Minimum Spanning Tree of a given graph using both Prim's and Kruskal's algorithms. 10 Marks

Prim's algorithm starts from an arbitrary vertex and repeatedly adds the minimum-weight edge connecting the current tree to a new outside vertex, until all vertices are included. Kruskal's algorithm instead sorts all edges by weight and greedily adds each edge that does not form a cycle (checked via Union-Find), stopping once n−1 edges have been added. Both methods, though structurally different, always produce a spanning tree of the same total minimum weight for a given connected graph.

Q4
Solve the Matrix Chain Multiplication problem for matrices with dimensions p=[10,20,30,40] and find the minimum number of scalar multiplications. 10 Marks

For three matrices A1(10×20), A2(20×30), A3(30×40), parenthesizing as (A1A2)A3 costs (10×20×30)+(10×30×40) = 6000+12000 = 18000 multiplications, while A1(A2A3) costs (20×30×40)+(10×20×40) = 24000+8000 = 32000. The DP recurrence m[i][j] = min over k of m[i][k]+m[k+1][j]+p[i-1]p[k]p[j] confirms (A1A2)A3 as optimal, giving a minimum cost of 18000.

Q5
Find the Longest Common Subsequence of X="ABCBDAB" and Y="BDCABA" using Dynamic Programming. Show the complete DP table. 10 Marks

Using the recurrence dp[i][j]=dp[i-1][j-1]+1 when characters match, and dp[i][j]=max(dp[i-1][j],dp[i][j-1]) otherwise, the full DP table is filled across all prefixes of X and Y as shown above. The resulting longest common subsequence has length 4, with "BCBA" (or equivalently "BDAB") being one valid such subsequence found by tracing back through the table's diagonal-match cells.

Q6
Explain the Fractional Knapsack problem and solve it for W=50 and items (profit,weight): (60,10),(100,20),(120,30). 5 Marks

The greedy strategy computes the profit/weight ratio for each item (6, 5, and 4 respectively), sorts items by decreasing ratio, and takes items fully until capacity is exhausted, taking a fraction of the last item if needed. Taking item1 and item2 fully uses 30 of the 50 capacity (profit 160), and taking 2/3 of item3 (20 of its 30 weight) adds 80 more profit, giving a maximum total profit of 240.

Q7
Explain Job Sequencing with Deadlines and solve for jobs J1(d=2,p=100), J2(d=1,p=19), J3(d=2,p=27), J4(d=1,p=25), J5(d=3,p=15). 5 Marks

Jobs are sorted in decreasing order of profit, and each is greedily placed into the latest available free time slot at or before its deadline; a job is rejected if no such slot remains. Following this for the given jobs with slots [1][2][3] (max deadline = 3), J1 is placed in slot 2, J3 in slot 1, J4 and J2 are rejected (slot 1 taken, no earlier slot available), and J5 fits in slot 3, giving selected jobs J3, J1, J5 with a maximum total profit of 27+100+15 = 142.

Q8
Explain the Optimal Merge Pattern problem and find the optimal merge cost for files of sizes 20, 30, 10, 5. 5 Marks

The optimal merge pattern problem minimizes total record comparisons across all pairwise merges by always greedily combining the two currently-smallest files first, typically implemented using a min-heap. For files 5, 10, 20, 30: merging 5+10 costs 15, then merging 15+20 costs 35, then merging 30+35 costs 65, giving a total minimum merge cost of 15+35+65 = 115.

Q9
Why does the Greedy approach fail to give an optimal solution for the 0/1 Knapsack problem? Explain with an example. 5 Marks

In 0/1 Knapsack, items cannot be split, so greedily picking the item with the highest profit/weight ratio first can leave leftover capacity that cannot be efficiently used by remaining items, resulting in a sub-optimal total profit. For example, with capacity W=10 and items (profit,weight) = (10,5),(10,5),(12,8), the greedy ratio-based choice would pick the 12-profit item first (ratio 1.5), filling 8 of 10 capacity and leaving only 2 capacity unused, yielding total profit 12 — whereas picking both 10-profit items uses exactly 10 capacity for a higher total profit of 20, which DP correctly identifies but greedy does not.

Q10
Differentiate between Top-Down (Memoization) and Bottom-Up (Tabulation) approaches in Dynamic Programming. 5 Marks

Top-Down (Memoization) uses the natural recursive formulation of the problem along with a cache/lookup table to store results of sub-problems as they are computed, avoiding redundant recursive calls. Bottom-Up (Tabulation) instead iteratively fills a table starting from the smallest base-case sub-problems and builds up to the final answer, which generally avoids recursion overhead and is often more space and time efficient in practice.

Q11
What are the conditions necessary for a Greedy algorithm to produce an optimal solution? Explain with reference to any two Unit 3 problems. 5 Marks

A greedy algorithm produces a globally optimal solution only when the problem exhibits the greedy-choice property (a locally optimal choice at each step leads toward a global optimum) and optimal substructure (an optimal solution contains optimal solutions to its sub-problems). Fractional Knapsack satisfies both, since taking the highest ratio item never costs anything due to divisibility, while MST construction (Prim's/Kruskal's) satisfies both via the cut property of graphs, guaranteeing that always picking the minimum safe edge is never wrong.

Q12
Write and explain the algorithm for Prim's method of finding a Minimum Cost Spanning Tree. 5 Marks

Prim's algorithm begins with an arbitrary starting vertex placed in the MST set, and at each of the remaining n−1 steps, selects the minimum-weight edge that connects a vertex already inside the MST set to a vertex still outside it, adding both the edge and the new vertex to the set. Using a min-priority-queue keyed by edge weight, this process runs in O(E log V) time and always produces a tree spanning all vertices with minimum total edge weight, since each greedy choice respects the cut property.

Q13
Give the recurrence relation for Matrix Chain Multiplication and explain each term. 5 Marks

The recurrence m[i][j] = min over all split points k (i≤k<j) of { m[i][k] + m[k+1][j] + p[i-1]·p[k]·p[j] } computes the minimum multiplication cost for the sub-chain of matrices Ai...Aj, where m[i][k] and m[k+1][j] are the optimal costs of the two resulting sub-chains and p[i-1]·p[k]·p[j] is the cost of multiplying the two resulting product matrices together; the base case m[i][i]=0 reflects that a single matrix needs no multiplication.

Q14
What is the time and space complexity of the 0/1 Knapsack DP solution, and how can the space be optimized? 5 Marks

The standard 2-D DP table for 0/1 Knapsack takes O(n×W) time and O(n×W) space, where n is the number of items and W is the capacity. Since each row dp[i][*] only depends on the previous row dp[i-1][*], the space can be optimized to O(W) by using a single 1-D array and updating it from right to left (high capacity to low) for each item, which prevents an item from being counted more than once.
