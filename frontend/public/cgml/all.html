Experiment 1: Basic graphics: line, circle, ellipse, heart and smiley face

Aim: To draw a line, circle, ellipse, heart and smiley face using graphics functions, and to see their attributes (colour, line style, thickness, fill).

Source code

#include<stdio.h>
#include<conio.h>
#include<stdlib.h>
#include<graphics.h>

void main()
{
    int gd = DETECT, gm, err;
    int x, y, r;

    initgraph(&gd, &gm, "C:\\TURBOC3\\BGI");
    err = graphresult();
    if(err != grOk)
    {
        printf("Graphics error: %s", grapherrormsg(err));
        getch();
        exit(1);
    }

    /* 1. Line: yellow, dashed, thick */
    setcolor(YELLOW);
    setlinestyle(DASHED_LINE, 0, THICK_WIDTH);
    line(30, 150, 190, 70);
    outtextxy(80, 190, "Line");

    /* back to a normal solid line for the other shapes */
    setlinestyle(SOLID_LINE, 0, NORM_WIDTH);

    /* 2. Circle: white outline, red fill */
    setcolor(WHITE);
    circle(320, 110, 50);
    setfillstyle(SOLID_FILL, RED);
    floodfill(320, 110, WHITE);
    outtextxy(295, 190, "Circle");

    /* 3. Ellipse: green */
    setcolor(GREEN);
    ellipse(530, 110, 0, 360, 70, 40);
    outtextxy(505, 190, "Ellipse");

    /* 4. Rectangle: cyan */
    setcolor(CYAN);
    rectangle(60, 260, 160, 340);
    outtextxy(70, 400, "Rectangle");

    /* 5. Smiley face: yellow head, eyes, smile */
    setcolor(YELLOW);
    circle(320, 300, 45);
    circle(305, 288, 5);
    circle(335, 288, 5);
    arc(320, 300, 200, 340, 25);
    outtextxy(280, 400, "Smiley face");

    /* 6. Heart: two arcs and two lines */
    setcolor(RED);
    x = 530; y = 270; r = 25;
    arc(x - r, y, 0, 180, r);
    arc(x + r, y, 0, 180, r);
    line(x - 2 * r, y, x, y + 3 * r);
    line(x + 2 * r, y, x, y + 3 * r);
    setfillstyle(SOLID_FILL, RED);
    floodfill(x, y + 30, RED);
    outtextxy(505, 400, "Heart");

    getch();
    closegraph();
}

The manual's Exp 1 has separate programs for each shape (the heart program contains a stray name and drawing loop) and uses several different BGI paths. This one program draws everything, checks for graphics errors, and shows the attributes.

Before you run

These programs open a graphics screen, so they need the Turbo C++ BGI driver files. Two things to check once:

  1. BGI path: the code uses "C:\\TURBOC3\\BGI" (double backslashes are required in C). It must match the BGI folder of your Turbo C++ install, which holds files such as EGAVGA.BGI. If the program prints "Graphics error", correct this path.
  2. Graphics library: in Turbo C++ choose Options > Linker > Libraries and tick Graphics library. Without it you get "undefined symbol _initgraph" when linking.
  3. File type: save the file with the .C extension (for example EXP4.C) so Turbo C++ compiles it as a C program.

Output

A 640 x 480 graphics window opens with six labelled shapes:
  Top row:    a yellow dashed thick line, a red-filled circle, a green ellipse
  Bottom row: a cyan rectangle, a yellow smiley face, a red filled heart
Press any key to close it.

Explanation

  1. initgraph(&gd, &gm, path) starts graphics mode. DETECT lets it pick the best driver. graphresult() checks that it worked.
  2. setcolor(c) sets the drawing colour. setlinestyle(style, 0, width) sets the line style (SOLID_LINE, DASHED_LINE, DOTTED_LINE, CENTER_LINE) and thickness (NORM_WIDTH or THICK_WIDTH). These are the attributes of a line.
  3. line(x1, y1, x2, y2) draws a line between two points. circle(x, y, r) needs the centre and radius. ellipse(x, y, start, end, xr, yr) needs the centre, start and end angles (0 to 360 for a full ellipse) and the two radii. rectangle(left, top, right, bottom) needs two opposite corners.
  4. setfillstyle(SOLID_FILL, RED) chooses the fill pattern and colour. floodfill(x, y, border) fills the area around the point (x, y) up to the border colour, so the shape must be drawn in that border colour first.
  5. arc(x, y, start, end, r) draws part of a circle. Angles are measured anticlockwise from the 3 o'clock position, so 270 degrees is the bottom. The smile is an arc from 200 to 340 degrees. The heart is two upper half-circles (0 to 180) joined by two lines to the bottom point.
  6. outtextxy(x, y, text) prints a label at a screen position. getch() waits for a key and closegraph() returns to text mode.

Viva questions

How do you draw a rectangle in graphics mode?

rectangle(left, top, right, bottom). The first two values are the top-left corner and the last two are the bottom-right corner.

What are the line attributes?

Colour (setcolor), line style (solid, dotted, centre, dashed) and thickness (normal or thick), both set with setlinestyle.

What are the ellipse attributes?

Centre (x, y), start angle, end angle, x radius and y radius, plus the current colour and line style.

What are the circle attributes?

Centre (x, y) and radius, plus the current colour and line style. The inside is filled with setfillstyle and floodfill.

Why is initgraph used?

It initialises the graphics system by loading a graphics driver from disk and putting the screen into graphics mode. It also resets colours and settings to their defaults.

What is the closegraph function?

It shuts down the graphics system, frees the memory used by it and restores the screen to text mode.

What is a pixel?

The smallest addressable point of the screen. A picture is made of many pixels.

What is the putpixel function?

putpixel(x, y, color) plots one pixel at (x, y) in the given colour.

How is setpixel used?

setpixel is not a Turbo C function. It belongs to other graphics systems. In Turbo C the same job is done by putpixel.

What is a picture element?

Another name for a pixel (pix-el = picture element).

What does DETECT do?

It tells initgraph to detect the graphics card and choose the best driver and mode automatically.

What does floodfill need?

A point inside a closed shape, and the colour of the shape's border. The border must be closed or the colour leaks out.

Experiment 2: Plot a pixel in different colours

Aim: To plot a point (pixel) on the screen in different colours using graphics functions.

Source code

#include<stdio.h>
#include<conio.h>
#include<stdlib.h>
#include<graphics.h>

void main()
{
    int gd = DETECT, gm, err;
    int c, x, y;
    char msg[40];

    initgraph(&gd, &gm, "C:\\TURBOC3\\BGI");
    err = graphresult();
    if(err != grOk)
    {
        printf("Graphics error: %s", grapherrormsg(err));
        getch();
        exit(1);
    }

    /* the pixels from the manual */
    putpixel(85, 35, GREEN);
    putpixel(30, 40, RED);
    putpixel(115, 50, YELLOW);
    putpixel(135, 50, CYAN);
    putpixel(45, 60, BLUE);
    putpixel(20, 100, WHITE);
    putpixel(200, 100, LIGHTBLUE);
    putpixel(150, 100, LIGHTGREEN);
    putpixel(200, 50, YELLOW);
    putpixel(120, 70, RED);

    /* a strip of pixels in every colour from 1 to 15 */
    for(c = 1; c <= 15; c++)
    {
        for(x = 0; x < 30; x++)
        {
            for(y = 0; y < 10; y++)
            {
                putpixel(100 + c * 30 + x, 200 + y, c);
            }
        }
    }

    outtextxy(100, 180, "Pixels in colours 1 to 15");

    /* read a pixel back with getpixel */
    c = getpixel(85, 35);
    sprintf(msg, "Colour of pixel (85,35) = %d", c);
    outtextxy(100, 300, msg);

    getch();
    closegraph();
}

What is a pixel?

The smallest point on the screen that can be set to a colour. The screen is a grid of pixels.

Experiment 3: DDA line drawing algorithm

Aim: To implement the DDA algorithm for drawing a line segment between two given end points A (x1, y1) and B (x2, y2).

Source code

#include<stdio.h>
#include<conio.h>
#include<stdlib.h>
#include<math.h>
#include<graphics.h>

void main()
{
    int gd = DETECT, gm, err;
    int x1, y1, x2, y2, dx, dy, steps, k;
    float x, y, xinc, yinc;

    clrscr();
    printf("Enter first point (x1 y1): ");
    scanf("%d%d", &x1, &y1);
    printf("Enter second point (x2 y2): ");
    scanf("%d%d", &x2, &y2);

    initgraph(&gd, &gm, "C:\\TURBOC3\\BGI");
    err = graphresult();
    if(err != grOk)
    {
        printf("Graphics error: %s", grapherrormsg(err));
        getch();
        exit(1);
    }

    dx = x2 - x1;
    dy = y2 - y1;

    if(abs(dx) > abs(dy))
        steps = abs(dx);
    else
        steps = abs(dy);

    if(steps == 0)
        steps = 1;

    xinc = (float)dx / steps;
    yinc = (float)dy / steps;

    x = x1;
    y = y1;

    for(k = 0; k <= steps; k++)
    {
        putpixel((int)(x + 0.5), (int)(y + 0.5), WHITE);
        x = x + xinc;
        y = y + yinc;
    }

    getch();
    closegraph();
}

  3. File type: save the file with the .C extension (for example EXP4.C) so Turbo C++ compiles it as a C program.

(a graphics window opens and a white line is drawn from (100,100) to (300,200))

Explanation

  1. Idea: A line is drawn as a series of pixels. DDA (Digital Differential Analyzer) walks from the first point to the last in small equal steps and plots a pixel at each step.
  2. dx = x2 - x1 and dy = y2 - y1 are the changes along x and y.
  3. steps is the larger of |dx| and |dy|. Using the larger one guarantees that the line moves by at most 1 pixel in each direction per step, so there are no gaps.
  4. xinc = dx / steps and yinc = dy / steps are the amounts to add at every step. One of them is exactly 1 (or -1) and the other is the slope or a fraction.
  5. In the loop, add xinc and yinc to x and y, round them with (int)(x + 0.5), and plot. The loop runs steps + 1 times so both end points are plotted.
  6. Example: from (2, 2) to (8, 5): dx = 6, dy = 3, steps = 6, xinc = 1, yinc = 0.5. The plotted points are (2,2), (3,3), (4,3), (5,4), (6,4), (7,5), (8,5).
  7. The manual declares xi and yi as int, so dx/s is integer division and any slanted line comes out wrong (for example 0.5 becomes 0). This version uses float and casts to avoid that.

Viva questions

What is the DDA algorithm?

An incremental algorithm that draws a line by computing each next point from the previous one, adding a fixed step in x and y and rounding to the nearest pixel.

What does DDA stand for?

Digital Differential Analyzer.

Differentiate DDA and Bresenham's line algorithm.

DDA uses floating-point addition and rounding at every step. Bresenham's uses only integer addition and a decision parameter, so it is faster and more accurate (no rounding error build-up).

Why is DDA more complex (slower) than Bresenham's?

It needs floating-point arithmetic and rounding for every pixel, while Bresenham's uses only integer operations.

Why is DDA called an incremental scan conversion algorithm?

Because each point is obtained by adding an increment to the previous point instead of computing it from the line equation each time.

What operations are performed in DDA?

Compute dx and dy, find the number of steps, compute the increments, then repeat: add the increments, round, and plot.

What is the line equation?

y = mx + c, where m is the slope and c is the y-intercept.

How is the slope calculated?

m = dy / dx = (y2 - y1) / (x2 - x1).

What is a refresh buffer?

Also called the frame buffer: the memory that stores the colour of every pixel, which the display reads to refresh the screen.

What is resolution?

The number of pixels on the screen, given as columns x rows, for example 640 x 480.

Why are the larger of |dx| and |dy| used as the number of steps?

So that the line advances by one pixel along the major axis at each step and no pixel is skipped.

What happens if both end points are the same?

steps would be 0 and the division would fail, so the program sets steps to 1 and plots that one point.

Experiment 4: Bresenham's line drawing algorithm

Aim: To implement Bresenham's line drawing algorithm for drawing a line segment between two given end points A (x1, y1) and B (x2, y2).

Source code

#include<stdio.h>
#include<conio.h>
#include<stdlib.h>
#include<graphics.h>

void bresenham(int x1, int y1, int x2, int y2)
{
    int dx, dy, sx, sy, x, y, p, i;

    dx = abs(x2 - x1);
    dy = abs(y2 - y1);
    sx = (x2 >= x1) ? 1 : -1;
    sy = (y2 >= y1) ? 1 : -1;
    x = x1;
    y = y1;
    putpixel(x, y, WHITE);

    if(dx >= dy)
    {
        p = 2 * dy - dx;
        for(i = 0; i < dx; i++)
        {
            x = x + sx;
            if(p < 0)
            {
                p = p + 2 * dy;
            }
            else
            {
                y = y + sy;
                p = p + 2 * (dy - dx);
            }
            putpixel(x, y, WHITE);
        }
    }
    else
    {
        p = 2 * dx - dy;
        for(i = 0; i < dy; i++)
        {
            y = y + sy;
            if(p < 0)
            {
                p = p + 2 * dx;
            }
            else
            {
                x = x + sx;
                p = p + 2 * (dx - dy);
            }
            putpixel(x, y, WHITE);
        }
    }
}

void main()
{
    int gd = DETECT, gm, err;
    int x1, y1, x2, y2;

    clrscr();
    printf("Enter first point (x1 y1): ");
    scanf("%d%d", &x1, &y1);
    printf("Enter second point (x2 y2): ");
    scanf("%d%d", &x2, &y2);

    initgraph(&gd, &gm, "C:\\TURBOC3\\BGI");
    err = graphresult();
    if(err != grOk)
    {
        printf("Graphics error: %s", grapherrormsg(err));
        getch();
        exit(1);
    }

    bresenham(x1, y1, x2, y2);

    getch();
    closegraph();
}

Explanation

  1. Idea: At each step the line moves one pixel along x and either stays on the same row or goes up one row. The decision parameter p tells which of the two pixels is closer to the real line. Only integer additions are used.
  2. dx and dy are the absolute differences. sx and sy are +1 or -1 and give the direction, so lines in every direction work (the manual's version only works when x1 is less than x2 and the slope is between 0 and 1).
  3. Main case (dx at least dy, slope up to 1): start with p = 2*dy - dx and plot the first point.
  4. For each step x moves by one. If p < 0, y stays the same and p = p + 2*dy. Otherwise y also moves by one and p = p + 2*(dy - dx). Then the pixel is plotted.
  5. When the line is steeper (dy greater than dx), the same logic is used with the roles of x and y swapped (the else part).
  6. Example: from (0,0) to (8,3): dx = 8, dy = 3, p starts at -2. The points are (0,0), (1,0), (2,1), (3,1), (4,2), (5,2), (6,2), (7,3), (8,3).

Viva questions

Differentiate DDA and Bresenham's line algorithm.

DDA uses floating-point addition and rounding. Bresenham's uses only integer addition and a decision parameter, so it is faster and more accurate.

Explain Bresenham's line drawing algorithm.

It draws a line by moving one pixel in the major direction at each step and using a decision parameter to choose between the two nearest pixels. The parameter is updated with integer additions.

What operations are performed in Bresenham's algorithm?

Compute dx and dy, set p = 2dy - dx, then repeat: plot the pixel, move x, update p using integer addition, and move y when p is not negative.

Why is Bresenham's more accurate than DDA?

It uses only integers, so there is no rounding error that builds up along the line.

Why is Bresenham's faster and more efficient?

It avoids floating-point arithmetic, division and rounding inside the loop. Only additions and comparisons are used.

What is a decision parameter?

A value, p, that shows which of the two candidate pixels is closer to the actual line, so we can choose without calculating the exact y.

How is the decision parameter calculated?

The first value is p = 2dy - dx. After that, p = p + 2dy if p is negative, or p = p + 2(dy - dx) if p is not negative.

What are the conditions for the decision parameter?

If p < 0 the next pixel is (x + 1, y). If p >= 0 the next pixel is (x + 1, y + 1).

List the advantages of Bresenham's algorithm.

Integer arithmetic only, fast, accurate, easy to implement in hardware, and every point lies close to the true line.

List the disadvantages of Bresenham's algorithm.

It draws only straight lines in its basic form, it needs separate handling for different slopes and directions, and the lines look jagged (aliasing) because there is no anti-aliasing.

What is the slope of a line?

m = dy / dx. For slope between 0 and 1, x is the major direction.

Experiment 5: Midpoint circle generation algorithm

Aim: To implement the midpoint circle generation algorithm for a circle with centre (x, y) and radius r.

Source code

#include<stdio.h>
#include<conio.h>
#include<stdlib.h>
#include<graphics.h>

void plot8(int a, int b, int x, int y)
{
    putpixel(a + x, b + y, RED);
    putpixel(a - x, b + y, RED);
    putpixel(a + x, b - y, RED);
    putpixel(a - x, b - y, RED);
    putpixel(a + y, b + x, RED);
    putpixel(a - y, b + x, RED);
    putpixel(a + y, b - x, RED);
    putpixel(a - y, b - x, RED);
}

void main()
{
    int gd = DETECT, gm, err;
    int a, b, r, x, y, p;

    clrscr();
    printf("Enter centre (a b): ");
    scanf("%d%d", &a, &b);
    printf("Enter radius r: ");
    scanf("%d", &r);

    initgraph(&gd, &gm, "C:\\TURBOC3\\BGI");
    err = graphresult();
    if(err != grOk)
    {
        printf("Graphics error: %s", grapherrormsg(err));
        getch();
        exit(1);
    }

    x = 0;
    y = r;
    p = 1 - r;

    while(x <= y)
    {
        plot8(a, b, x, y);
        if(p < 0)
        {
            p = p + 2 * x + 3;
        }
        else
        {
            p = p + 2 * (x - y) + 5;
            y--;
        }
        x++;
    }

    getch();
    closegraph();
}

Keep the whole circle inside the screen. For centre (320, 240) the radius can be at most 239.

Output

Enter centre (a b): 320 240
Enter radius r: 100
(a graphics window opens and a red circle of radius 100 is drawn at the centre of the screen)

Explanation

  1. Idea: Start at the top of the circle, (0, r), and move along the arc one pixel at a time. At each step choose between two pixels using a decision parameter, with integer arithmetic only.
  2. 8-way symmetry: A circle has the same shape in all eight octants. So only the part where x goes from 0 to y (the first 45 degrees) is calculated, and plot8 plots the 8 matching points around the centre (a, b) for every point.
  3. The starting decision parameter is p = 1 - r.
  4. At each step plot the points. If p < 0, the midpoint is inside the circle, so y stays and p = p + 2x + 3. Otherwise y decreases by one and p = p + 2(x - y) + 5.
  5. Then x increases by one. The loop stops when x is greater than y, because the first octant is complete.
  6. The manual's program is written in C++ with a class and has several errors (Void, ! =, p=5/4)-r, repeated putpixel lines that skip points). This version is plain C and follows the algorithm given in the manual.

Viva questions

What is the midpoint circle algorithm?

An algorithm that draws a circle by calculating points in one octant and using symmetry for the rest, choosing each pixel with a decision parameter and integer arithmetic.

What is the circle equation?

x² + y² = r² for a circle with its centre at the origin. For centre (a, b): (x - a)² + (y - b)² = r².

Why do we use 8-way symmetry?

A circle is symmetric about both axes and both diagonals. Calculating one octant and reflecting it gives all 8, so the work is about 8 times less.

What is the initial value of the decision parameter?

p0 = 1 - r (the simplified integer form of 5/4 - r).

What are the update rules?

If p < 0: p = p + 2x + 3. Otherwise: p = p + 2(x - y) + 5 and y decreases by 1. In both cases x increases by 1.

Why does the loop run only while x <= y?

After x passes y we have covered the first 45 degrees (one octant). The other octants are obtained by symmetry.

How is it different from drawing a circle with the equation or with sin and cos?

The equation needs a square root and the trigonometric method needs sin and cos, which are slow. The midpoint method uses only integer additions.

What does the decision parameter tell us?

Whether the midpoint between the two candidate pixels is inside or outside the circle, which tells us which pixel is closer.

What is the difference between the midpoint and Bresenham's circle algorithm?

They give almost the same result. Bresenham's uses a decision parameter based on distances to the circle, while the midpoint method tests the midpoint of the two candidate pixels.

Experiment 6: Midpoint ellipse generation algorithm

Aim: To implement the midpoint ellipse generation algorithm for an ellipse with centre (x, y) and radii rx and ry.

Source code

#include<stdio.h>
#include<conio.h>
#include<stdlib.h>
#include<graphics.h>

void plot4(int xc, int yc, int x, int y)
{
    putpixel(xc + x, yc + y, YELLOW);
    putpixel(xc - x, yc + y, YELLOW);
    putpixel(xc + x, yc - y, YELLOW);
    putpixel(xc - x, yc - y, YELLOW);
}

void main()
{
    int gd = DETECT, gm, err;
    int xc, yc, rx, ry, x, y;
    double rx2, ry2, p;

    clrscr();
    printf("Enter centre (xc yc): ");
    scanf("%d%d", &xc, &yc);
    printf("Enter radius along x (rx): ");
    scanf("%d", &rx);
    printf("Enter radius along y (ry): ");
    scanf("%d", &ry);

    initgraph(&gd, &gm, "C:\\TURBOC3\\BGI");
    err = graphresult();
    if(err != grOk)
    {
        printf("Graphics error: %s", grapherrormsg(err));
        getch();
        exit(1);
    }

    rx2 = (double)rx * rx;
    ry2 = (double)ry * ry;
    x = 0;
    y = ry;

    /* Region 1: slope is less than 1 in magnitude */
    p = ry2 - rx2 * ry + 0.25 * rx2;
    while(ry2 * x <= rx2 * y)
    {
        plot4(xc, yc, x, y);
        x++;
        if(p < 0)
        {
            p = p + 2 * ry2 * x + ry2;
        }
        else
        {
            y--;
            p = p + 2 * ry2 * x - 2 * rx2 * y + ry2;
        }
    }

    /* Region 2: slope is greater than 1 in magnitude */
    p = ry2 * (x + 0.5) * (x + 0.5) + rx2 * (y - 1) * (y - 1) - rx2 * ry2;
    while(y >= 0)
    {
        plot4(xc, yc, x, y);
        y--;
        if(p > 0)
        {
            p = p + rx2 - 2 * rx2 * y;
        }
        else
        {
            x++;
            p = p + 2 * ry2 * x - 2 * rx2 * y + rx2;
        }
    }

    getch();
    closegraph();
}

Explanation

  1. Idea: An ellipse is symmetric in four quadrants, so only the first quadrant is calculated, starting at the top, (0, ry). plot4 plots the 4 matching points around the centre.
  2. The first quadrant is split into two regions. In Region 1 the curve is flat (slope less than 1 in magnitude), so x moves by one at every step and y sometimes goes down. In Region 2 the curve is steep, so y moves by one at every step and x sometimes goes right.
  3. Region 1 ends when ry²·x is no longer less than or equal to rx²·y, which is where the slope reaches -1.
  4. Region 1 starts with p = ry² - rx²·ry + 0.25·rx². If p is negative only x moves. Otherwise y also decreases. The update formulas are in the code.
  5. Region 2 starts with a new parameter calculated from the last point of Region 1, and runs while y is at least 0, so the curve ends on the x axis.
  6. double is used for the parameters because the squares of large radii are bigger than a Turbo C int or long can hold.
  7. The manual's program has several faults (empty else blocks that skip the parameter update, a fixed centre at (200, 200), and bad path "C:\\tc\\bgi::"). This version follows the standard algorithm and takes the centre as input.

Viva questions

Explain the ellipse function.

An ellipse centred at the origin is x²/rx² + y²/ry² = 1. The algorithm uses f(x, y) = ry²x² + rx²y² - rx²ry², which is negative inside, zero on, and positive outside the ellipse.

Explain the midpoint ellipse drawing algorithm.

It draws one quadrant in two regions. In each region it tests the midpoint between two candidate pixels with the ellipse function and uses the sign of a decision parameter to pick the nearer pixel. The other three quadrants come by symmetry.

What are the advantages of this algorithm?

It uses only additions and multiplications in the loop (no square roots or trigonometry), it is fast, and it gives smooth ellipses with good accuracy.

What are the disadvantages of this algorithm?

It is more complicated than the circle algorithm because of the two regions, it needs squares of the radii (large numbers), and it draws only ellipses aligned to the axes.

Write the properties of the midpoint ellipse algorithm.

Uses 4-way symmetry, divides the quadrant into two regions at slope -1, works with a decision parameter updated incrementally, and plots the nearest pixel to the true ellipse at each step.

Why are there two regions?

Where the curve is flat, x is the fast direction. Where it is steep, y is the fast direction. We must step by one pixel along the fast direction so no pixel is missed.

Where does Region 1 end?

Where the slope of the curve becomes -1, that is when ry²·x is greater than rx²·y.

Why 4-way symmetry for an ellipse and 8-way for a circle?

A circle is also symmetric about the diagonals, but an ellipse is symmetric only about its two axes, so its quadrants are not symmetric to each other beyond that.

What happens if rx equals ry?

The shape becomes a circle with radius rx.
