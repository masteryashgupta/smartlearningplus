Experiment 10: 0/1 Knapsack using Dynamic Programming

Aim: Implement 0/1 Knapsack problem using Dynamic Programming.

Source code

This is the program from the lab manual, unchanged. Compile it with gcc aoa_exp10.c -o exp10 and run ./exp10 (on Windows with MinGW, exp10).

#include <stdio.h>
#include <stdlib.h>
#include <time.h>
int max(int a, int b)
{
    return (a > b) ? a : b;
}
int main()
{
    int n, capacity, i, w;
    clock_t start, end;
    double cpu_time_used;
    printf("Enter number of items: ");
    scanf("%d", &n);
    int weight[n], profit[n];
    printf("Enter weight and profit of each item:\n");
    for(i = 0; i < n; i++)
    {
        printf("Item %d weight: ", i + 1);
        scanf("%d", &weight[i]);
        printf("Item %d profit: ", i + 1);
        scanf("%d", &profit[i]);
    }
    printf("Enter knapsack capacity: ");
    scanf("%d", &capacity);
    int dp[n + 1][capacity + 1];
    // Start timing
    start = clock();
    // Build DP table bottom-up
    for(i = 0; i <= n; i++)
    {
        for(w = 0; w <= capacity; w++)
        {
            if(i == 0 || w == 0)
            dp[i][w] = 0;
            else if(weight[i - 1] <= w)
            dp[i][w] = max(profit[i - 1] + dp[i - 1][w - weight[i - 1]], dp[i - 1][w]);
            else
            dp[i][w] = dp[i - 1][w];
        }
    }
    // Trace back to find selected items
    int res = dp[n][capacity];
    w = capacity;
    printf("\nItems selected (0/1 Knapsack - DP):\n");
    for(i = n; i > 0 && res > 0; i--)
    {
        if(res != dp[i - 1][w])
        {
            printf("Item (W=%d, P=%d) -> Taken\n", weight[i - 1], profit[i - 1]);
            res -= profit[i - 1];
            w -= weight[i - 1];
        }
    }
    // End timing
    end = clock();
    cpu_time_used = ((double)(end - start)) / CLOCKS_PER_SEC;
    printf("\nMaximum Profit (0/1 Knapsack DP) = %d\n", dp[n][capacity]);
    printf("\nTime Required = %f seconds\n", cpu_time_used);
    return 0;
}

Explanation (from the manual)

Concept

This is similar to the Fractional Knapsack from Experiment 7 — a bag with a fixed capacity, items with weight and profit, and the goal of maximizing total profit. But this time there's an important restriction: items cannot be broken. Either take an item completely (1), or don't take it at all (0) — hence the name "0/1 Knapsack".

The Greedy method (used in Experiment 7) does not work reliably here, because "take the best-ratio item first" doesn't always give the best possible answer when items can't be split. So this problem is solved using Dynamic Programming (DP), which systematically stores all possibilities in a table to find the best answer.

The DP idea: build a table where rows represent items and columns represent capacity (0 up to the maximum capacity). Each cell stores "the maximum profit achievable using only these items, with this much capacity available". For every item, two choices are checked — include it, or exclude it — whichever gives more profit is stored in the table. The final cell holds the overall maximum profit.

Worked Example

  4 items:
  Item 1: weight=1, profit=1
  Item 2: weight=3, profit=4
  Item 3: weight=4, profit=5
  Item 4: weight=5, profit=7
  Bag capacity = 7

  The DP table checks, for every item: if its weight exceeds the remaining capacity, skip it
  (keep the previous answer); otherwise compare "profit if taken" against "profit if not
  taken" and keep whichever is larger.

  The best combination found is: Item 2 (weight=3, profit=4) + Item 3 (weight=4, profit=5).
  Total weight = 3+4 = 7 (exactly the capacity). Total profit = 4+5 = 9.

  Maximum Profit = 9
  (Note: the Greedy method might have chosen a different combination here since it's ratio-
  based, but DP always guarantees the truly optimal answer for the 0/1 case.)

Time Complexity

The time complexity of 0/1 Knapsack DP is O(n × W), where n is the number of items and W is the bag's capacity. This can be slower than Greedy for very large capacities, but it always guarantees the optimal (correct) answer, whereas Greedy is only guaranteed optimal for the Fractional case.

What the Program Does

  1. The user enters how many items there are, along with each item's weight and profit.
  2. The user enters the bag's capacity.
  3. The program builds a DP table bottom-up (from small sub-problems to larger ones, the process above).
  4. The table is then traced back to determine which items were actually chosen, marking them "Taken".
  5. The maximum profit is printed at the end.
  6. The time taken (in seconds) is displayed.

In short: for every item, check both "take it" and "don't take it" in the table, and keep whichever gives more profit — items cannot be split.

Viva questions

What is the 0/1 Knapsack problem?

Choose items, each taken whole or not at all, so that the total weight does not exceed the capacity and the total profit is maximum.

Why is dynamic programming used?

The problem has overlapping subproblems and optimal substructure, so storing sub-results in a table avoids repeated work.

Write the recurrence.

If weight[i] <= w: K[i][w] = max(profit[i] + K[i-1][w - weight[i]], K[i-1][w]). Otherwise K[i][w] = K[i-1][w].

What is the time and space complexity?

O(n × W) for both, where n is the number of items and W the capacity.

Why is O(nW) called pseudo-polynomial?

It depends on the value of W, not only on the number of bits needed to write W.

How does the program find which items were taken?

It walks back through the table from K[n][W]: if K[i][w] differs from K[i-1][w], item i was taken and its weight is subtracted.

Compare 0/1 Knapsack with the Fractional Knapsack.

Fractional is solved by the greedy method in O(n log n). 0/1 needs dynamic programming because greedy is not optimal.

What is the answer for the sample input?

Items (W=2, P=12), (W=1, P=10) and (W=2, P=15) fit in capacity 5, for a maximum profit of 37.
