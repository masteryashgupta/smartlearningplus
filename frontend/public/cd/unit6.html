01. Basic Blocks HIGH
The fundamental unit of code optimization
Definition

A Basic Block is a maximal sequence of consecutive three-address-code statements such that control enters the block only at the first statement (no jumps into the middle of the block) and leaves only after the last statement (no jumps out except at the end), with no possibility of branching except at the entry and exit.

🇮🇳 Hinglish Explanation
Basic block code ka ek "straight-line" hissa hai — jisme koi jump ya branch beech mein nahi hota. Execution sirf shuru se start hoti hai aur end tak chalti hai, koi entry/exit point beech mein nahi hota. Jaise ek non-stop train route, bina kisi beech station ke rukne ke.

Algorithm to Find Leaders (Start of Basic Blocks) EXAM HOT

  1. The first statement of the program is a leader.
  2. Any statement that is the target of a conditional or unconditional goto/jump is a leader.
  3. Any statement that immediately follows a goto/conditional jump statement is a leader.

Each basic block consists of a leader and all statements up to (but not including) the next leader.

Example

Three-address code: 1: t1=a+b 2: t2=t1*c 3: if t2>0 goto 6 4: x=0 5: goto 7 6: x=1 7: y=x

Leaders: statement 1 (first), statement 4 (follows conditional jump), statement 6 (jump target), statement 7 (follows goto). This produces 4 basic blocks: {1,2,3}, {4,5}, {6}, {7}.

02. Control Flow Graphs (CFG) HIGH

Definition

A Control Flow Graph (CFG) is a directed graph in which each node represents a basic block, and a directed edge from block B1 to block B2 exists if control can flow from B1 directly to B2 (i.e. B2 can immediately follow B1 in some execution path).

🇮🇳 Hinglish
CFG ek graph hai jisme har node ek basic block hota hai, aur edges batate hain ki control flow kis block se kis block tak jaa sakta hai (jaise if-else ke branches, loops, etc.). Yeh compiler ko poore program ka "execution map" deta hai jisse optimization decisions liye ja sakte hain.

Fig 1: CFG showing an if-else structure — B2 branches to either B3 or B4, both merge at B5

⚠ Important

The CFG is the foundation for almost all optimization techniques — loop detection (back edges), data flow analysis, and dead code elimination all operate directly on the CFG structure.

03. DAG Representation of a Basic Block HIGH — MOST ASKED

Definition

A DAG (Directed Acyclic Graph) for a basic block is a graph representation where leaf nodes represent identifiers/constants, interior nodes represent operators, and the children of a node represent the operands — with shared sub-expressions represented by a single node having multiple parents, used to detect common sub-expressions and simplify a basic block.

🇮🇳 Hinglish
DAG basic block ko graph form mein represent karta hai jahan repeated/common calculations ko ek hi node se share kiya jata hai, instead of dobara calculate karne ke. Isse compiler ko pata chal jata hai ki kaunsi expressions already calculate ho chuki hain — unhe dobara calculate karne ki zaroorat nahi.

Steps to Construct a DAG EXAM HOT

  1. For each statement, create (or reuse, if it already exists) a leaf node for each operand.
  2. Check if an interior node already exists with the same operator and the same children (operands) — if so, reuse it instead of creating a duplicate.
  3. If no such node exists, create a new interior node labelled with the operator, with the operand nodes as its children.
  4. The node currently labelling each variable's value is updated to point to the latest assignment.
Example

Code: a=b+c
d=a-b
e=d+c
f=a-b

Since statement 4 (f=a-b) computes the same expression as statement 2 (d=a-b), the DAG reuses the same node for both d and f — this is the common sub-expression being eliminated automatically.

Fig 2: DAG for the example — node "d" is reused as "f" since both compute a−b (common sub-expression)

05. Sources of Optimization HIGH

Definition

Sources of optimization refer to the general transformations a compiler applies to improve a program's running time, code size, or power consumption, while preserving its original semantic meaning (the output for any given input remains unchanged).

🇮🇳 Hinglish
Optimization ka matlab hai code ko fast/chhota banana, bina uska meaning change kiye. Compiler kai tarah ke "tricks" use karta hai jaise repeated calculations remove karna, useless code hatana, etc.

Common Optimization Techniques EXAM HOT

TechniqueDescription
Common Sub-Expression EliminationAvoid recomputing an expression whose value is already available
Dead Code EliminationRemove statements whose results are never used
Constant FoldingEvaluate constant expressions at compile time instead of runtime, e.g. x = 2 + 3 → x = 5
Constant PropagationReplace a variable with its known constant value wherever possible
Copy PropagationReplace uses of a copied variable with the original, removing the copy where safe
Strength ReductionReplace an expensive operation with a cheaper equivalent, e.g. x*2 → x+x or a shift
Code MotionMove loop-invariant computations outside the loop body
Induction Variable EliminationSimplify/remove variables that change by a fixed amount on each loop iteration
Example

Strength Reduction: y = x * 2 is replaced by y = x + x (or a left-shift x << 1), since addition/shift is typically faster than multiplication on most hardware.

06. Loop Optimization HIGH

Definition

Loop optimization refers to a set of optimization techniques specifically targeted at loops, since loops are executed repeatedly and therefore offer the greatest potential performance improvement per line of optimized code.

🇮🇳 Hinglish
Loops program ka sabse "hot" part hote hain — same code baar-baar execute hota hai. Isiliye loops ko optimize karna sabse zyada performance improvement deta hai, kyunki ek chhota sa improvement bhi har iteration mein repeat hota hai.

Major Loop Optimization Techniques EXAM HOT

TechniqueDescription
Code Motion (Loop-Invariant Code Motion)Move computations that produce the same result every iteration outside the loop
Induction Variable EliminationRemove/simplify variables whose value changes by a constant amount each iteration, replacing expensive recomputation with simple increments
Strength ReductionReplace expensive operations (multiplication) inside the loop with cheaper ones (addition)
Loop UnrollingReplicate the loop body multiple times to reduce the overhead of loop control (test/branch) per iteration
Loop Fusion/JammingCombine two adjacent loops with the same iteration range into a single loop, reducing loop overhead

07. Global Data Flow Analysis HIGH

Definition

Global Data Flow Analysis is the process of gathering information about how data (variable values) flows through the entire control flow graph of a program (across multiple basic blocks), used to enable optimizations that require knowledge beyond a single basic block.

🇮🇳 Hinglish
Local optimization sirf ek basic block ke andar dekhta hai. Lekin kuch optimizations ke liye poore program ka pata hona chahiye ki variable ki value kaha-kaha use ho rahi hai, kaha define ho rahi hai — yeh hi global data flow analysis karta hai, poore CFG ko traverse karke.

Key Data Flow Problems

AnalysisQuestion it AnswersUsed For
Reaching DefinitionsWhich definitions of a variable can reach a given point in the program?Constant propagation, optimization safety checks
Live Variable AnalysisIs a variable's value going to be used again before being redefined?Dead code elimination, register allocation
Available ExpressionsHas an expression already been computed and not yet invalidated?Common sub-expression elimination (globally)
Busy ExpressionsWill an expression definitely be computed along every path before any operand changes?Code motion (hoisting expressions)
⚠ Important

Global data flow analysis works by solving data flow equations iteratively over the CFG until the information stabilizes (reaches a fixed point) — a classic 10-mark theory question.

08. Loop Invariant Computation MEDIUM

Definition

A loop-invariant computation is a statement inside a loop that computes the same value on every iteration of the loop — meaning it can be safely moved (hoisted) outside the loop without changing the program's behaviour, an optimization called code motion.

🇮🇳 Hinglish
Agar koi calculation loop ke andar har baar same result deta hai (operands loop ke andar change nahi hote), to use loop ke bahar nikal dena chahiye — isse loop har iteration mein unnecessary calculation repeat nahi karega.
Example

for(i=0;i<n;i++){ x = a*b; arr[i] = x+i; } — here x = a*b doesn't depend on i, so it's loop-invariant; it gets hoisted: x = a*b; for(i=0;i<n;i++){ arr[i] = x+i; } — now a*b is computed once instead of n times.

09. Peephole Optimization HIGH — MOST ASKED

Definition

Peephole Optimization is a local, machine-dependent optimization technique performed on the final generated target code, examining a small, sliding "window" (peephole) of a few consecutive instructions at a time and replacing them with shorter/faster equivalent instruction sequences.

🇮🇳 Hinglish
Peephole optimization compiler ka aakhri optimization step hota hai — yeh generated machine code ko ek chhote se "window" (jaise 2-3 instructions) mein dekhta hai aur agar koi redundant/inefficient pattern dikhe to use better instructions se replace kar deta hai. Naam "peephole" isiliye hai kyunki yeh ek chhote door ke peephole se dekhne jaisa hai — sirf paas ke instructions dikhte hain, poora code nahi.

Peephole Optimization Techniques EXAM HOT

TechniqueDescriptionExample
Redundant Instruction EliminationRemove instructions whose effect is immediately undone or unusedMOV R0,a; MOV a,R0 → second instruction removed
Flow-of-Control OptimizationEliminate unnecessary jumps, jumps to jumpsgoto L1; ... L1: goto L2; → directly goto L2;
Algebraic SimplificationSimplify expressions using algebraic identitiesx = x + 0 removed; x = x * 1 removed
Strength ReductionReplace expensive ops with cheaper equivalentsx * 2 → x << 1
Use of Machine IdiomsReplace instruction sequences with a single, equivalent target-specific instructionAuto-increment/decrement addressing modes
Dead Code EliminationRemove unreachable code (e.g. code after an unconditional return/jump)Code after return statement removed
⚠ Important

Peephole optimization is applied after code generation (on the target/assembly code), unlike most other optimizations covered in this unit which apply on intermediate code — this distinction is frequently tested.

10. Issues in the Design of a Code Generator MEDIUM

Definition

The issues in code generator design are the key decisions and constraints a compiler writer must address when building the final phase that translates intermediate representation into target machine/assembly code.

Major Issues EXAM HOT

11. A Simple Code Generator HIGH

Definition

A simple code generator is an algorithm that translates a sequence of three-address statements into target machine code, using a register descriptor (tracks what value is currently in each register) and an address descriptor (tracks where the current value of each name is stored — register, memory, or both) to make instruction-selection decisions.

🇮🇳 Hinglish
Ek simple code generator three-address code ko dekh kar machine instructions banata hai. Yeh do "descriptors" maintain karta hai: register descriptor (kaunsa register kya value rakhta hai) aur address descriptor (har variable ki current value kahan store hai — register ya memory mein). Inki madad se yeh efficient code generate karta hai.

getReg Function — Register Selection Strategy

The getReg function decides which register to use for a computation's result, following this priority order:

  1. If an operand is already in a register and not needed afterward, reuse that register.
  2. Otherwise, use an empty register if one is available.
  3. Otherwise, pick a register whose current value is already stored in memory (no extra store needed) or that holds the least-used value, and spill (store) its content first if necessary.
Example

For statement x = y + z: if y is already in register R1 and not used later, the generator emits ADD R1, z directly (reusing R1) instead of allocating a new register, minimizing register pressure and store/load instructions.

12. Code Generation from DAG HIGH

Definition

Code generation from a DAG involves choosing an evaluation order (a topological ordering of the DAG nodes) and then generating a machine instruction for each interior node, exploiting the DAG structure to minimize the number of registers used and to avoid recomputing shared sub-expressions.

🇮🇳 Hinglish
DAG se code generate karte waqt, hume decide karna hota hai ki kis order mein nodes ko evaluate karna hai (topological order), taaki minimum registers use hon aur shared nodes dobara calculate na hon.

Heuristic Ordering Algorithm

A common heuristic for choosing evaluation order is: repeatedly select a node N such that all of N's parents (if any) have already been evaluated, or N's children's values are still needed for the longest, preferring to evaluate nodes whose results free up registers soonest. This minimizes the total register count needed during code generation.

StrategyGoal
Topological SortEnsures every operator node is generated only after its operand nodes are computed
Labeling Algorithm (Sethi-Ullman)Computes the minimum number of registers required to evaluate the DAG with no extra stores, then orders subtree evaluation by register-need (larger subtree first)
⚠ Important

The Sethi-Ullman algorithm is the classic technique for generating optimal (minimum register count) code from an expression tree/DAG — frequently asked as a 10-mark numerical/theory question.

Hinglish Trick

Leader Rules: "1st, Target, Next" (1st statement, Jump ka target, Jump ke turant agla line).
Peephole Optimization: "Chhote jharokhe se jhankna" (2-3 instructions ki window dekho — redundant load/store hatao, `x*2` ko `x<<1` karo, dead jumps uda do!).

Q1 · 5 MARKS
5 MARKS
What is a Basic Block? Explain the algorithm to identify leaders.

A Basic Block is a maximal sequence of consecutive statements with a single entry point (first statement) and single exit point (last statement), with no branches in or out except at these ends. Leaders are identified by: (1) the first statement is a leader; (2) any target of a conditional/unconditional jump is a leader; (3) any statement immediately following a jump/conditional jump is a leader. Each block runs from one leader up to (but not including) the next leader.

Q2 · 10 MARKS
10 MARKS
What is a DAG? Explain its construction and advantages with an example.

A DAG (Directed Acyclic Graph) represents a basic block where leaf nodes are identifiers/constants, interior nodes are operators, and shared sub-expressions are represented by a single node with multiple parents. Construction: for each statement, reuse existing leaf/interior nodes wherever the same operator+operands already exist; otherwise create a new node. Advantages: automatic common sub-expression elimination, dead code elimination (unreachable nodes removed), determining variable usage, providing reordering information, and enabling more efficient code generation.

Q3 · 5 MARKS
5 MARKS
Explain Peephole Optimization with examples of techniques used.

Peephole optimization examines a small sliding window of target/assembly instructions and replaces inefficient patterns with better equivalents. Techniques: Redundant instruction elimination (e.g. removing a store immediately followed by a load of the same value), flow-of-control optimization (removing jumps to jumps), algebraic simplification (x=x+0 removed), strength reduction (x*2 → x<<1), use of machine idioms (auto-increment instructions), and dead code elimination (unreachable code after a return removed).

Q4 · 10 MARKS
10 MARKS
Explain different loop optimization techniques used by compilers.

Code Motion (Loop-Invariant Code Motion): hoist computations that produce the same result every iteration outside the loop. Induction Variable Elimination: simplify variables that change by a fixed amount each iteration, replacing recomputation with cheap increments. Strength Reduction: replace expensive operations (multiplication) with cheaper ones (addition/shift) inside the loop. Loop Unrolling: replicate the loop body to reduce per-iteration control overhead. Loop Fusion: merge adjacent loops with the same iteration range into one, reducing total loop overhead. Loops are prioritized for optimization since their code executes repeatedly, multiplying the benefit of any single optimization.

Q5 · 5 MARKS
5 MARKS
What is loop-invariant computation? Explain with an example.

A loop-invariant computation is a statement inside a loop whose computed value does not change across iterations (its operands are not modified within the loop). Such computations can be safely moved (hoisted) outside the loop via code motion, since recomputing them every iteration is wasted work. Example: in for(i=0;i<n;i++){x=a*b; arr[i]=x+i;}, x=a*b does not depend on i and is hoisted before the loop, computed only once instead of n times.

Q6 · 10 MARKS
10 MARKS
What is Global Data Flow Analysis? Explain the major data flow problems.

Global Data Flow Analysis gathers information about variable values across the entire control flow graph (spanning multiple basic blocks), enabling optimizations that local (single-block) analysis cannot perform. Major problems: Reaching Definitions — which definitions of a variable can reach a given program point (used for constant propagation); Live Variable Analysis — whether a variable's value will be used again before redefinition (used for dead code elimination & register allocation); Available Expressions — has an expression already been computed and not invalidated (used for global common sub-expression elimination); Busy Expressions — will an expression definitely be computed along every path (used for code motion). These are solved by iteratively applying data flow equations over the CFG until a fixed point is reached.

Q7 · 5 MARKS
5 MARKS
List and explain the major issues in the design of a code generator.

Key issues: (1) Input — form of intermediate representation accepted (3AC, DAG, postfix); (2) Target Program — output format (absolute, relocatable, or assembly code); (3) Memory Management — mapping source names to target addresses; (4) Instruction Selection — choosing which machine instructions to emit, affecting code quality; (5) Register Allocation & Assignment — deciding which values stay in limited registers vs memory; (6) Evaluation Order — order of computation can affect code efficiency.

Q10 · 5 MARKS
5 MARKS
Describe how code is generated from a DAG, mentioning register minimization.

Code generation from a DAG selects a topological evaluation order (operators only generated after their operands are ready), generating one machine instruction per interior node while reusing values represented by shared nodes instead of recomputing them. The Sethi-Ullman labeling algorithm computes the minimum number of registers needed by evaluating the subtree requiring more registers first, ensuring optimal (minimum) register usage with no unnecessary spills/stores.
