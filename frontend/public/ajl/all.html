Step 2: Code (CourseCheckbox.java)

CourseCheckbox.java
import java.awt.*;
import java.awt.event.*;

public class CourseCheckbox extends Frame implements ItemListener {
    Checkbox c1, c2, c3, c4;
    Label l1;

    CourseCheckbox() {
        setTitle("Course Selection");
        setLayout(new FlowLayout());

        c1 = new Checkbox("B.Tech");
        c2 = new Checkbox("BCA");
        c3 = new Checkbox("MCA");
        c4 = new Checkbox("MBA");
        l1 = new Label("Selected: None                              ");

        add(c1);
        add(c2);
        add(c3);
        add(c4);
        add(l1);

        c1.addItemListener(this);
        c2.addItemListener(this);
        c3.addItemListener(this);
        c4.addItemListener(this);

        addWindowListener(new WindowAdapter() {
            public void windowClosing(WindowEvent e) {
                dispose();
            }
        });

        setSize(350, 200);
        setVisible(true);
    }

    public void itemStateChanged(ItemEvent e) {
        String courses = "";
        if (c1.getState()) courses += "B.Tech ";
        if (c2.getState()) courses += "BCA ";
        if (c3.getState()) courses += "MCA ";
        if (c4.getState()) courses += "MBA ";

        if (courses.equals("")) courses = "None";
        l1.setText("Selected: " + courses);
    }

    public static void main(String[] args) {
        new CourseCheckbox();
    }
}

Step 3: Compile and run

Command Prompt
javac CourseCheckbox.java
java CourseCheckbox

Expected result: a window with four checkboxes. Tick or untick any of them and the label updates.

Selected: B.Tech MCA

The file name must match the class name exactly: CourseCheckbox.java. If the window does not appear, check that setVisible(true) is in the code.

How it works

  • extends Frame makes the class itself the window.
  • implements ItemListener lets the class handle checkbox events, so it must define itemStateChanged().
  • addItemListener(this) registers the class to be notified when a checkbox is ticked or unticked.
  • getState() returns true when a checkbox is ticked. The method rebuilds the text on every change.
  • FlowLayout places components left to right and wraps to the next row.
  • WindowAdapter is needed because AWT windows do not close on the X button by default.

Viva answers

  • What is AWT? Abstract Window Toolkit, Java’s original GUI library in java.awt. Its components use native OS widgets, so it is heavyweight and platform-dependent.
  • Hierarchy: Object, Component, Container, Window, Frame.
  • Component vs Container: a Component is anything visible on screen. A Container is a component that can hold other components.
  • Delegation event model: an event source (the checkbox) sends events to registered listeners, and the listener handles them.
  • Why WindowAdapter? WindowListener has 7 methods. The adapter lets you override only the one you need.

Likely variations

  • Add a Submit button that shows the selection only when clicked.
  • Replace the checkboxes with radio buttons using CheckboxGroup, so only one course can be selected.

Applet lifecycle

  • init(): runs once when the applet loads. Create components here.
  • start(): runs each time the applet becomes visible.
  • paint(): runs whenever the display needs redrawing.
  • stop(): runs when the user leaves the page.
  • destroy(): runs once at the end to release resources.

How it works

  • extends Applet makes the class an applet. It runs inside a browser or appletviewer, not on its own.
  • List is the AWT list component. list.getSelectedItem() returns the clicked item.
  • addItemListener(this) and itemStateChanged() follow the same event pattern as Experiment 1.
  • Version B swaps Applet for Panel and adds a main() so it can run as a normal program.

Viva answers

  • Applet vs application: an applet runs inside a browser or appletviewer, has no main(), and has security restrictions such as no local file access. An application runs standalone with main().
  • Why are applets obsolete? Browsers removed Java plugin support, and the Applet API was deprecated and then removed from the JDK.
  • Hierarchy: Object, Component, Container, Panel, Applet.
  • init() vs start(): init() is called once on load. start() is called every time the applet becomes active again.
  • Passing parameters: use the param tag in the applet tag, and read it with getParameter("name").

How it works

  • JFrame is the Swing window. Swing classes start with J and come from javax.swing.*. The listeners still come from java.awt.event.*.
  • setLayout(null) with setBounds(x, y, width, height) places each component by pixel position.
  • setDefaultCloseOperation(EXIT_ON_CLOSE) closes the program on the X button, so no WindowAdapter is needed.
  • ButtonGroup makes the radio buttons mutually exclusive. Checkboxes have no group, so any combination works.
  • JButton fires an ActionEvent (actionPerformed). JToggleButton fires an ItemEvent (itemStateChanged).
  • JOptionPane.showMessageDialog shows the popup message.

Viva answers

  • AWT vs Swing: AWT is heavyweight and platform-dependent. Swing is lightweight, pure Java and has richer components such as tables and trees.
  • Why lightweight? Swing draws its own components, so it does not depend on native OS widgets.
  • Main components: JLabel, JTextField, JButton, JToggleButton, JCheckBox, JRadioButton, JComboBox, JList, JTable, JTree. Containers: JFrame, JPanel, JDialog.
  • Button vs toggle button: a JButton fires once per click. A JToggleButton stays pressed and holds an on/off state.
  • Hierarchy: Component, Container, JComponent, AbstractButton, then JButton or JToggleButton. JCheckBox and JRadioButton extend JToggleButton.

Step 2: Code (JDBCCRUD.java)

JDBCCRUD.java
import java.sql.*;

public class JDBCCRUD {
    public static void main(String[] args) {
        String url = "jdbc:mysql://localhost:3306/CollegeDB";
        String user = "root";
        String password = "root123"; // change to your MySQL password

        try {
            Class.forName("com.mysql.cj.jdbc.Driver");
            Connection con = DriverManager.getConnection(url, user, password);
            System.out.println("Database Connected Successfully...\n");

            Statement stmt = con.createStatement();

            String createTable = "CREATE TABLE IF NOT EXISTS Student ("
                    + "id INT PRIMARY KEY, "
                    + "name VARCHAR(50), "
                    + "branch VARCHAR(30), "
                    + "marks INT)";
            stmt.executeUpdate(createTable);
            System.out.println("Table Created Successfully.");

            // INSERT
            String insert = "INSERT INTO Student(id,name,branch,marks) VALUES(?,?,?,?)";
            PreparedStatement ps = con.prepareStatement(insert);
            ps.setInt(1, 101);
            ps.setString(2, "Rahul");
            ps.setString(3, "CSE");
            ps.setInt(4, 85);
            ps.executeUpdate();
            System.out.println("Record Inserted Successfully.");

            // UPDATE
            String update = "UPDATE Student SET marks=? WHERE id=?";
            PreparedStatement ps2 = con.prepareStatement(update);
            ps2.setInt(1, 95);
            ps2.setInt(2, 101);
            ps2.executeUpdate();
            System.out.println("Record Updated Successfully.");

            // SELECT
            ResultSet rs = stmt.executeQuery("SELECT * FROM Student");
            System.out.println("\nStudent Records");
            System.out.println("-------------------------------");
            while (rs.next()) {
                System.out.println("ID      : " + rs.getInt("id"));
                System.out.println("Name    : " + rs.getString("name"));
                System.out.println("Branch  : " + rs.getString("branch"));
                System.out.println("Marks   : " + rs.getInt("marks"));
                System.out.println("-------------------------------");
            }

            // DELETE
            String delete = "DELETE FROM Student WHERE id=?";
            PreparedStatement ps3 = con.prepareStatement(delete);
            ps3.setInt(1, 101);
            ps3.executeUpdate();
            System.out.println("Record Deleted Successfully.");

            rs.close();
            ps.close();
            ps2.close();
            ps3.close();
            stmt.close();
            con.close();
            System.out.println("\nConnection Closed.");
        } catch (Exception e) {
            System.out.println(e);
        }
    }
}

Common errors

  • ClassNotFoundException: the jar is not in the -cp path.
  • Access denied for user root: wrong password in the code.
  • Unknown database: CREATE DATABASE CollegeDB was skipped.
  • Duplicate entry 101: an earlier run stopped before the DELETE. Run DELETE FROM Student; in MySQL and rerun.

How it works

  • Five steps: load the driver, get a Connection, create a Statement, execute, close.
  • executeUpdate() is for INSERT, UPDATE, DELETE and CREATE. It returns the number of rows affected.
  • executeQuery() is for SELECT and returns a ResultSet. rs.next() moves to the next row.
  • Each ? in a PreparedStatement is filled by position, starting from 1.

Viva answers

  • Statement vs PreparedStatement: PreparedStatement is precompiled, faster when repeated, and prevents SQL injection.
  • Four driver types: Type 1 JDBC-ODBC bridge, Type 2 Native API, Type 3 Network Protocol, Type 4 Thin (pure Java, used by MySQL).
  • ResultSet: the rows returned by a query, read one at a time with a cursor.
  • execute() vs executeQuery() vs executeUpdate(): execute() runs any SQL and returns a boolean. The other two are as above.

Step 2: Code

Server.java
import java.io.*;
import java.net.*;

public class Server {
    public static void main(String[] args) {
        try {
            ServerSocket ss = new ServerSocket(5000);
            System.out.println("Server is waiting for client...");

            Socket s = ss.accept();
            System.out.println("Client Connected!");

            DataInputStream dis = new DataInputStream(s.getInputStream());
            String msg = dis.readUTF();
            System.out.println("Message from Client: " + msg);

            DataOutputStream dos = new DataOutputStream(s.getOutputStream());
            dos.writeUTF("Hello Client, Message Received!");

            dis.close();
            dos.close();
            s.close();
            ss.close();
        } catch (Exception e) {
            System.out.println(e);
        }
    }
}
Client.java
import java.io.*;
import java.net.*;

public class Client {
    public static void main(String[] args) {
        try {
            Socket s = new Socket("localhost", 5000);

            DataOutputStream dos = new DataOutputStream(s.getOutputStream());
            dos.writeUTF("Hello Server");

            DataInputStream dis = new DataInputStream(s.getInputStream());
            String reply = dis.readUTF();
            System.out.println("Server Reply: " + reply);

            dos.close();
            dis.close();
            s.close();
        } catch (Exception e) {
            System.out.println(e);
        }
    }
}

How it works

  • The server opens port 5000 with new ServerSocket(5000).
  • accept() blocks until a client connects, then returns a Socket.
  • The client connects with new Socket("localhost", 5000). Use the server IP address for two different computers.
  • getOutputStream() sends data and getInputStream() receives it. writeUTF() and readUTF() send and read a text string.
  • Both programs must use the same port. Address already in use means an old server is still running.

Viva answers

  • Socket: an endpoint for communication between two machines.
  • Socket vs ServerSocket: ServerSocket waits for connections on the server. Socket is the actual connection, used by the client and returned by accept().
  • What does accept() do? It waits for a client and returns a Socket for talking to it.
  • TCP vs UDP: Socket and ServerSocket use TCP (connection-oriented, reliable). DatagramSocket and DatagramPacket use UDP (connectionless).
  • Port number: identifies which application on a machine receives the data. Ports 0 to 1023 are reserved.

Likely variations

Step 2: Code

Calculator.java
import java.rmi.*;

public interface Calculator extends Remote {
    double calculate(double a, double b, char op) throws RemoteException;
}
CalculatorImpl.java
import java.rmi.*;
import java.rmi.server.*;

public class CalculatorImpl extends UnicastRemoteObject implements Calculator {

    public CalculatorImpl() throws RemoteException {
        super();
    }

    public double calculate(double a, double b, char op) throws RemoteException {
        switch (op) {
            case '+':
                return a + b;
            case '-':
                return a - b;
            case '*':
                return a * b;
            case '/':
                if (b != 0)
                    return a / b;
                else {
                    System.out.println("Division by zero not possible.");
                    return 0;
                }
            default:
                System.out.println("Invalid Operator");
                return 0;
        }
    }
}
Server.java
import java.rmi.*;
import java.rmi.registry.*;

public class Server {
    public static void main(String args[]) {
        try {
            CalculatorImpl obj = new CalculatorImpl();
            Registry registry = LocateRegistry.createRegistry(1099);
            registry.rebind("CalculatorService", obj);
            System.out.println("RMI Server Started...");
        } catch (Exception e) {
            System.out.println(e);
        }
    }
}
Client.java
import java.rmi.registry.*;
import java.util.Scanner;

public class Client {
    public static void main(String args[]) {
        try {
            Registry registry = LocateRegistry.getRegistry("localhost", 1099);
            Calculator obj = (Calculator) registry.lookup("CalculatorService");

            Scanner sc = new Scanner(System.in);
            System.out.print("Enter First Number : ");
            double a = sc.nextDouble();
            System.out.print("Enter Operator (+,-,*,/) : ");
            char op = sc.next().charAt(0);
            System.out.print("Enter Second Number : ");
            double b = sc.nextDouble();

            double result = obj.calculate(a, b, op);
            System.out.println("Result = " + result);
        } catch (Exception e) {
            System.out.println(e);
        }
    }
}

How it works

  • Remote interface (Calculator) extends Remote. Every method throws RemoteException.
  • Implementation (CalculatorImpl) extends UnicastRemoteObject and holds the real logic.
  • Server creates the object, starts the registry on port 1099 and registers it with rebind().
  • Client looks the object up by name and receives a stub (proxy). Calling a method on the stub runs it on the server.
  • Flow: client, stub, network, server object, result back to the client.

Viva answers

  • RMI: Remote Method Invocation. It lets a program call a method on an object in another JVM as if it were local.
  • Stub and skeleton: the stub is the client-side proxy. The skeleton was the server-side helper in old versions and is now handled automatically.
  • RMI registry: a naming service where servers register remote objects and clients look them up. Default port 1099.
  • Why extends Remote? It marks the interface as callable from another JVM.
  • Why RemoteException? Network calls can fail, so every remote method must declare it.
  • bind vs rebind: bind throws an error if the name is already used. rebind replaces the old binding.
  • RMI vs sockets: sockets send raw data over a protocol you design. RMI lets you call methods directly.

Common errors

  • 404 Not Found: wrong URL, web.xml not saved correctly, or the .class file is not in WEB-INF\classes.

How it works

  • A servlet is a Java class that runs inside a web container (Tomcat) and answers browser requests.
  • doGet() runs when the browser sends a GET request, which is what typing a URL does.
  • setContentType("text/html") tells the browser the reply is HTML. getWriter() gives the stream that writes the response.
  • web.xml is the deployment descriptor. It maps the URL /hello to the class HelloServlet.

Viva answers

  • Servlet: a Java program on the server that handles client requests and generates dynamic responses.
  • Servlet container: software that runs servlets and manages their lifecycle, for example Tomcat.
  • Lifecycle: init() once, service() for every request (calls doGet or doPost), destroy() once.
  • doGet vs doPost: GET sends data in the URL (visible, size-limited). POST sends it in the request body (hidden, used for forms and passwords).
  • web.xml: the deployment descriptor that maps URLs to servlets.
  • Servlet vs CGI: a servlet runs as a thread inside one JVM, so it is faster. CGI starts a new process for every request.
