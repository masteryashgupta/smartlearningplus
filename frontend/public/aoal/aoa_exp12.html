Experiment 12: Matrix Chain Multiplication using Dynamic Programming

Aim: Implement Matrix Chain Multiplication problem using Dynamic Programming.

Source code

This is the program from the lab manual, unchanged. Compile it with gcc aoa_exp12.c -o exp12 and run ./exp12 (on Windows with MinGW, exp12).

#include <stdio.h>
#include <limits.h>
#include <time.h>
int main()
{
    int n, i, j, k, L;
    clock_t start, end;
    double cpu_time_used;
    printf("Enter number of matrices: ");
    scanf("%d", &n);
    int p[n + 1];
    printf("Enter dimensions (p0 p1 ... p%d) such that matrix i has dimension p[i-1] x p[i]:\n", n);
    for(i = 0; i <= n; i++)
    {
        printf("p%d: ", i);
        scanf("%d", &p[i]);
    }
    int dp[n + 1][n + 1];
    int s[n + 1][n + 1];    // to store split points for parenthesization
    // Start timing
    start = clock();
    // Cost is zero when multiplying one matrix
    for(i = 1; i <= n; i++)
    dp[i][i] = 0;
    // L is chain length
    for(L = 2; L <= n; L++)
    {
        for(i = 1; i <= n - L + 1; i++)
        {
            j = i + L - 1;
            dp[i][j] = INT_MAX;
            for(k = i; k < j; k++)
            {
                int cost = dp[i][k] + dp[k + 1][j] + p[i - 1] * p[k] * p[j];
                if(cost < dp[i][j])
                {
                    dp[i][j] = cost;
                    s[i][j] = k;
                }
            }
        }
    }
    // End timing
    end = clock();
    cpu_time_used = ((double)(end - start)) / CLOCKS_PER_SEC;
    printf("\nMinimum number of multiplications = %d\n", dp[1][n]);
    printf("\nTime Required = %f seconds\n", cpu_time_used);
    return 0;
}

Explanation (from the manual)

Concept

Given several matrices to multiply together, e.g. A×B×C×D, the final result is always the same regardless of how the brackets are arranged (e.g. (A×B)×C or A×(B×C)) — but the number of scalar multiplications required can differ hugely depending on the bracket order. Every matrix has a shape (rows × columns), and multiplying two matrices together requires a number of multiplications determined by these dimensions. The goal of this problem is to find the cheapest bracket order (fewest multiplications), without actually performing any of the multiplications.

This is solved with Dynamic Programming: compute the optimal cost for small chain lengths first (2 matrices, then 3, then 4, and so on), and combine these results to compute the optimal cost for larger chains.

Worked Example

  6 matrices with dimensions p = [30, 35, 15, 5, 10, 20, 25], meaning:
  Matrix 1: 30×35, Matrix 2: 35×15, Matrix 3: 15×5, Matrix 4: 5×10, Matrix 5: 10×20, Matrix
  6: 20×25

  The DP table is filled starting with small chains (pairs of matrices) and building up to
  the full 6-matrix chain, checking at each step the best point to split the chain into two
  parts to minimize total cost.

  Result: Minimum number of multiplications = 15125

  (A naive left-to-right bracketing order, e.g. ((((A×B)×C)×D)×E)×F, could require many times
  more multiplications — the correct order in this example achieves the minimum of 15125.)

Time Complexity

Matrix Chain Multiplication DP has a time complexity of O(n³), where n is the number of matrices. A brute- force approach (trying every possible bracketing) would take exponential time, which becomes impractically slow for larger n — which is exactly why the DP approach matters here.

What the Program Does

  1. The user enters how many matrices there are.
  2. The user enters their dimensions (p0, p1, ..., pn, where matrix i has shape p[i−1] × p[i]).
  3. The program builds a DP table computing minimum cost from small chains up to the full chain (the process above).
  4. The minimum number of multiplications is printed at the end.
  5. The time taken (in seconds) is displayed.

In short: find the best cost for small matrix-chains first, then combine them to find the best cost for larger chains, until the full chain's answer is found.

Viva questions

What is the Matrix Chain Multiplication problem?

Given a chain of matrices, find the order of multiplication (parenthesization) that needs the fewest scalar multiplications.

Why does the order matter?

Matrix multiplication is associative, so the result is the same, but the number of operations changes a lot with the order.

Write the recurrence.

m[i][j] = minimum over k from i to j-1 of m[i][k] + m[k+1][j] + p[i-1]·p[k]·p[j], with m[i][i] = 0.

What are the time and space complexities?

O(n³) time and O(n²) space.

What is the cost of multiplying a p×q matrix by a q×r matrix?

p × q × r scalar multiplications.

What does the program output for the dimensions 40 20 30 10 30?

26000, the minimum number of scalar multiplications for 4 matrices.

Does the program multiply the matrices?

No. It only finds the minimum number of multiplications.

How many ways are there to parenthesize n matrices?

The (n-1)th Catalan number, which grows exponentially, so trying all of them is too slow.
