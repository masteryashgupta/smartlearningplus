Experiment 14: Naive String-Matching Algorithm

Aim: Implement Naive String-Matching Algorithm to match a pattern with the string.

Source code

This is the program from the lab manual, unchanged. Compile it with gcc aoa_exp14.c -o exp14 and run ./exp14 (on Windows with MinGW, exp14).

#include <stdio.h>
#include <string.h>
#include <time.h>
int main()
{
    char text[200], pattern[100];
    int n, m, i, j, found = 0;
    clock_t start, end;
    double cpu_time_used;
    printf("Enter the text string: ");
    scanf("%s", text);
    printf("Enter the pattern to search: ");
    scanf("%s", pattern);
    n = strlen(text);
    m = strlen(pattern);
    // Start timing
    start = clock();
    printf("\nMatching positions (Naive String Matching):\n");
    // Slide the pattern over text one by one
    for(i = 0; i <= n - m; i++)
    {
        for(j = 0; j < m; j++)
        {
            if(text[i + j] != pattern[j])
            break;
        }
        if(j == m)
        {
            printf("Pattern found at index %d\n", i);
            found = 1;
        }
    }
    // End timing
    end = clock();
    cpu_time_used = ((double)(end - start)) / CLOCKS_PER_SEC;
    if(!found)
    printf("Pattern not found in the text\n");
    printf("\nTime Required = %f seconds\n", cpu_time_used);
    return 0;
}

Explanation (from the manual)

Concept

Given a large text string, e.g. "AABAACAADAABAABA" , and a smaller pattern string to search for within it, e.g. "AABA" , the goal is to find every position where the pattern matches inside the text.

The "naive" (i.e. straightforward, no clever tricks) approach: slide the pattern over the text one position at a time, and at each position check character-by-character whether the pattern matches that portion of the text.

Process:

  1. Place the pattern at the start (index 0) of the text.
  2. Compare characters one by one — if all of them match, report a match at this position.
  3. If any mismatch occurs, stop comparing and slide the pattern one position forward.
  4. Repeat this until the end of the text is reached.

It is called "naive" because it doesn't use any smart shortcuts (like the KMP or Boyer–Moore algorithms do) — it simply tries every position directly.

Worked Example

  Text: "AABAACAADAABAABA"
  Pattern: "AABA"

  Index 0: text[0..3] = "AABA" → MATCH! (position 0)
  Index 1: text[1..4] = "ABAA" → does not match "AABA"
  Index 2: text[2..5] = "BAAC" → no match
  … (continue checking every position) …
  Index 9: text[9..12] = "AABA" → MATCH! (position 9)
  Index 12: text[12..15] = "AABA" → MATCH! (position 12)

  Result: Pattern "AABA" found at indices 0, 9, and 12.

Time Complexity

Naive String Matching has a worst-case time complexity of O(n × m), where n is the text length and m is the pattern length, since the entire pattern may need to be checked character-by-character at every position. This can be slow for large texts, which is why real-world applications (text editors, search engines) use smarter algorithms (KMP, Boyer–Moore, Rabin–Karp) that avoid repeated comparisons. Even so, the naive method is the easiest to understand and works perfectly fine for small texts.

What the Program Does

  1. The user enters a text string and a pattern string.
  2. The program slides the pattern over every possible position in the text, checking character-by-character (the process above).
  3. Every position where the full pattern matches is printed.
  4. If no match is found anywhere, "Pattern not found" is printed.
  5. The time taken (in seconds) is displayed.

In short: slide the pattern one position at a time over the text, compare character-by-character at each position, and report every position where it fully matches.

Viva questions

What is the Naive String-Matching algorithm?

It slides the pattern over the text one position at a time and checks the pattern character by character at each position.

What is its time complexity?

Worst case O(m × (n - m + 1)), that is O(nm). Best case O(n) when the first character mismatches every time.

When does the worst case happen?

For example text AAAAAAAB and pattern AAAB, where almost all characters match before a mismatch.

Name a faster string matching algorithm.

KMP takes O(n + m). Rabin-Karp uses hashing and Boyer-Moore skips characters.

What are n and m?

n is the length of the text and m is the length of the pattern.

How many shifts are checked?

n - m + 1 positions.

What does the program print for ABABDABACDABABCABAB and ABABCABAB?

Pattern found at index 10 (positions start from 0).

Can the pattern overlap itself in matches?

Yes. The naive method checks every position, so overlapping matches are also found.
