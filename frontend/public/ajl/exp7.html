Experiment 7: Servlet (Hello World)

Write a servlet that displays Hello World in the browser, running on Tomcat 9.

Before you start

  • Use Tomcat 9 (64-bit Windows zip), extracted to C:\apache-tomcat-9.0.123. Tomcat 10 and newer will not work with javax.servlet.
  • Carry the extracted Tomcat folder on a pendrive in case the lab PC does not have it.

Set the paths

Change both paths to match the lab PC. Find the JDK with where javac. Use the path that ends in \bin\javac.exe, without that ending, and ignore the Common Files\Oracle\Java\javapath line.

Command Prompt
set JAVA_HOME=C:\Program Files\Java\jdk-26
set TOMCAT=C:\apache-tomcat-9.0.123

Step 1: Create the app folders

Command Prompt
mkdir %TOMCAT%\webapps\HelloServlet\WEB-INF\classes

Step 2: Create web.xml

Command Prompt
notepad %TOMCAT%\webapps\HelloServlet\WEB-INF\web.xml

Click Yes to create the file, paste the code below, save and close. Check that it is not saved as web.xml.txt.

web.xml
<?xml version="1.0" encoding="UTF-8"?>
<web-app xmlns="http://xmlns.jcp.org/xml/ns/javaee"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://xmlns.jcp.org/xml/ns/javaee
         http://xmlns.jcp.org/xml/ns/javaee/web-app_4_0.xsd"
         version="4.0">
    <servlet>
        <servlet-name>HelloServlet</servlet-name>
        <servlet-class>HelloServlet</servlet-class>
    </servlet>
    <servlet-mapping>
        <servlet-name>HelloServlet</servlet-name>
        <url-pattern>/hello</url-pattern>
    </servlet-mapping>
</web-app>

Step 3: Create HelloServlet.java

Command Prompt
cd %USERPROFILE%\Desktop
notepad HelloServlet.java
HelloServlet.java
import java.io.*;
import javax.servlet.*;
import javax.servlet.http.*;

public class HelloServlet extends HttpServlet {
    protected void doGet(HttpServletRequest request,
                         HttpServletResponse response)
            throws ServletException, IOException {
        response.setContentType("text/html");
        PrintWriter out = response.getWriter();
        out.println("<html>");
        out.println("<body>");
        out.println("<h1>Hello World</h1>");
        out.println("</body>");
        out.println("</html>");
    }
}

Step 4: Compile straight into Tomcat

The -d option puts HelloServlet.class directly into the classes folder. No output means no errors.

Command Prompt
javac -cp "%TOMCAT%\lib\servlet-api.jar" -d %TOMCAT%\webapps\HelloServlet\WEB-INF\classes HelloServlet.java

Step 5: Start Tomcat

A new Tomcat window opens. Leave it open.

Command Prompt
%TOMCAT%\bin\startup.bat

Step 6: Open the browser

Wait about 10 seconds. First check http://localhost:8080 shows the Tomcat page, then open this address.

Command Prompt
http://localhost:8080/HelloServlet/hello
Hello World

The address is the app folder plus the url-pattern: /HelloServlet + /hello.

When you finish

Stop Tomcat from the same Command Prompt.

Command Prompt
%TOMCAT%\bin\shutdown.bat

Common errors

  • 404 Not Found: wrong URL, web.xml not saved correctly, or the .class file is not in WEB-INF\classes.
  • Tomcat window closes at once: JAVA_HOME is not set. Run the set commands first.
  • Port 8080 already in use: an earlier Tomcat is still running. Run shutdown.bat and start again.
  • Changed web.xml: run shutdown.bat and then startup.bat again.

How it works

  • A servlet is a Java class that runs inside a web container (Tomcat) and answers browser requests.
  • doGet() runs when the browser sends a GET request, which is what typing a URL does.
  • setContentType("text/html") tells the browser the reply is HTML. getWriter() gives the stream that writes the response.
  • web.xml is the deployment descriptor. It maps the URL /hello to the class HelloServlet.

Viva answers

  • Servlet: a Java program on the server that handles client requests and generates dynamic responses.
  • Servlet container: software that runs servlets and manages their lifecycle, for example Tomcat.
  • Lifecycle: init() once, service() for every request (calls doGet or doPost), destroy() once.
  • doGet vs doPost: GET sends data in the URL (visible, size-limited). POST sends it in the request body (hidden, used for forms and passwords).
  • web.xml: the deployment descriptor that maps URLs to servlets.
  • Servlet vs CGI: a servlet runs as a thread inside one JVM, so it is faster. CGI starts a new process for every request.
