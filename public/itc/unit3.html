📙 UNIT 3 — Source Coding Schemes for Data Compaction

Prefix Code · Huffman Code · Shannon-Fano Code · Lempel-Ziv Coding · Channel Capacity · Channel Coding Theorem · Shannon Limit  |  Hours: 05

1. Data Compaction — Recap Low ⭐ — intro

English

Data compaction (source coding) is the process of encoding source symbols using codewords of variable length, such that symbols with higher probability get shorter codewords and rarer symbols get longer codewords — reducing the average number of bits/symbol close to the source entropy H(X).

Hinglish

Simple idea: jo letter/symbol zyada baar aata hai usko chhota code do, jo kam aata hai usko lamba code do. Isse average length kam ho jaati hai — yahi compression ka core idea hai (Morse code mein bhi 'E' ek dot hai kyunki English mein sabse common letter hai!).

2. Prefix Code (Instantaneous Code) High ⭐⭐⭐

English

A prefix code (instantaneous code) is a variable-length code in which no codeword is a prefix of any other codeword. This property allows the receiver to decode each symbol the moment its complete codeword is received — without needing to look ahead at future bits.

Hinglish

Prefix code ka matlab — koi bhi chhota codeword kisi bade codeword ka "starting part" nahi hona chahiye. Isse decoding karte waqt confusion nahi hota — jaise hi codeword complete hota hai, turant pata chal jaata hai ki symbol kya hai, aage ke bits dekhne ki zarurat nahi (isiliye "instantaneous" kehte hain).

Example

Valid prefix code: A=0, B=10, C=110, D=111 → no code is prefix of another ✓

Invalid (not prefix-free): A=0, B=01, C=011 → here '0' (code for A) is a prefix of '01' (code for B) ✗ — decoding becomes ambiguous.

Fig 3.1 — Binary Code Tree for prefix code A=0,B=10,C=110,D=111: only leaf nodes carry symbols, so no codeword can be a prefix of another

3. Huffman Coding High ⭐⭐⭐⭐⭐ (Most Important — numerical guaranteed)

English

Huffman coding is an optimal variable-length prefix coding technique that builds a binary tree bottom-up by repeatedly combining the two least-probable symbols/nodes into a new node, until a single root remains. It achieves the minimum possible average codeword length for a given symbol probability distribution (among all prefix codes).

Hinglish

Huffman coding ka logic — har step pe sabse 2 kam probability wale symbols/nodes ko utha ke unko jod do (ek naya combined node bana do), aur ye repeat karte raho jab tak sirf ek root node na bach jaaye. Ye process "optimal" code deta hai — matlab sabse kam possible average length.

Huffman Coding Algorithm High — write this step-by-step in exam

  1. List all symbols with their probabilities in descending order.
  2. Take the two symbols with lowest probability; combine them into a new node with probability = sum of the two.
  3. Assign bit '0' to one branch and '1' to the other (convention).
  4. Re-sort the list (treating combined node as a new "symbol") and repeat steps 2-3 until only one node (probability = 1) remains — this is the root.
  5. The codeword for each original symbol = the sequence of 0s/1s read from root to that leaf.
Full Worked Example — most common numerical pattern

Symbols: A(0.4), B(0.2), C(0.2), D(0.1), E(0.1). Construct Huffman code and find average code length & efficiency.

Step-by-step combination:
Step 1: D(0.1)+E(0.1) → DE(0.2)
Step 2: Now: A(0.4), B(0.2), C(0.2), DE(0.2) → combine two lowest: C(0.2)+DE(0.2) → CDE(0.4)
Step 3: Now: A(0.4), B(0.2), CDE(0.4) → combine B(0.2)+CDE(0.4) → BCDE(0.6)
Step 4: Now: A(0.4), BCDE(0.6) → combine → root(1.0)

Resulting codewords (one valid assignment):

SymbolProbabilityCodewordLength
A0.401
B0.2102
C0.21103
D0.111104
E0.111114

Average code length:
Lavg = Σ Pᵢlᵢ = 0.4(1)+0.2(2)+0.2(3)+0.1(4)+0.1(4) = 0.4+0.4+0.6+0.4+0.4 = 2.2 bits/symbol

Entropy: H(X) = −Σ Pᵢlog₂Pᵢ = 0.4(1.32)+0.2(2.32)+0.2(2.32)+0.1(3.32)+0.1(3.32) ≈ 2.122 bits/symbol

Efficiency: η = H(X)/Lavg = 2.122/2.2 = 96.5%  |  Redundancy = 1−0.965 = 3.5%

4. Shannon-Fano Coding High ⭐⭐⭐⭐

English

Shannon-Fano coding is a top-down variable-length prefix coding technique that recursively splits a probability-sorted symbol list into two parts with (as nearly as possible) equal total probabilities, assigning '0' to one part and '1' to the other, and repeating on each sub-part until every symbol is isolated.

Hinglish

Huffman "bottom-up" (chhote nodes jodke upar jaate hain) hai, Shannon-Fano "top-down" hai — pehle sabko probability ke order mein rakho, fir list ko 2 roughly-equal-probability groups mein divide karo (top group=0, bottom group=1), aur har group ko fir se divide karte raho jab tak ek-ek symbol na bach jaaye.

Shannon-Fano Algorithm Medium

  1. Arrange symbols in descending order of probability.
  2. Divide the list into two parts such that the sum of probabilities in each part is as close to equal as possible.
  3. Assign '0' to the upper part and '1' to the lower part.
  4. Recursively repeat the division process on each part until each part contains only a single symbol.
Full Worked Example (same symbol set, for direct comparison with Huffman)

Symbols: A(0.4), B(0.2), C(0.2), D(0.1), E(0.1)

Split 1: {A(0.4)} | {B,C,D,E(0.6)} → A=0, rest start with 1
Split 2 (within 0.6 group): {B(0.2)} | {C,D,E(0.4)} → B=10, rest start with 11
Split 3 (within 0.4 group): {C(0.2)} | {D,E(0.2)} → C=110, rest start with 111
Split 4: {D(0.1)} | {E(0.1)} → D=1110, E=1111

Lavg = 2.2 bits/symbol (same as Huffman in this particular example — but Huffman is guaranteed optimal in general, Shannon-Fano is not always).

5. Lempel-Ziv (LZ) Coding High ⭐⭐⭐

English

Lempel-Ziv coding is a dictionary-based / adaptive universal lossless compression technique that does not require prior knowledge of source symbol probabilities. It works by building a dictionary of previously-seen substrings/patterns and replacing repeated occurrences with shorter references (pointers) to dictionary entries.

Hinglish

Huffman/Shannon-Fano ke liye tumhe symbol probabilities pehle se pata honi chahiye. LZ coding mein aisi koi zarurat nahi — ye "on-the-fly" data ke patterns ko dekh ke khud dictionary banata hai, aur jab wahi pattern repeat ho, to use ek short "pointer/code" se replace kar deta hai. Isi liye LZ ko "universal" / "adaptive" coding kehte hain — ye file ke type pe depend nahi karta (text, image, sab pe chal jaata hai). ZIP, GIF, PNG sab LZ-family algorithms use karte hain!

LZ77 — Sliding Window Approach Medium ⭐⭐

LZ77 uses a sliding window over the data, split into a "search buffer" (already encoded text) and "look-ahead buffer" (upcoming text). For each position, it searches the search buffer for the longest match to the upcoming data, and outputs a triple:

(offset, length, next_character)

where offset = how far back the match starts, length = how many characters matched, and next_character = the character following the match (that breaks the match).

Simplified Example

Input string: ABABABA

Encoding: A(0,0,A) → B(0,0,B) → AB seen before at offset 2, length 2 → match → (2,2,A) → remaining 'BA' matches at offset 2 → (2,2, end)

Output (conceptually): (0,0,A)(0,0,B)(2,2,A)(2,2,-) — repeated "AB" pattern is replaced by short back-references instead of repeating raw characters, hence compression.

Fig 3.2 — LZ77 sliding window: matches found in search buffer are replaced with (offset,length) back-references

6. Channel Capacity (Continuous Channel) High ⭐⭐⭐⭐⭐ — Shannon-Hartley theorem

English

For a continuous, band-limited channel corrupted by additive white Gaussian noise (AWGN), the Shannon-Hartley Theorem gives the channel capacity — the maximum rate at which information can be transmitted with arbitrarily low error probability:

C = B · log₂(1 + S/N)   [bits/second]

where B = channel bandwidth (Hz), S = average received signal power, N = average noise power, S/N = signal-to-noise ratio (SNR).

Hinglish

Ye formula batata hai ki ek channel ki maximum reliable speed uske bandwidth aur signal-to-noise ratio pe depend karti hai. Zyada bandwidth ya zyada SNR (kam noise) → zyada capacity. Yahi formula bataata hai ki tumhare WiFi/4G ki max possible speed kitni ho sakti hai given uska bandwidth aur signal quality.

Example

A channel has bandwidth B=3000 Hz and SNR=1000 (≈30dB, typical telephone line). Find channel capacity.

Solution:
C = 3000 × log₂(1+1000) = 3000 × log₂(1001) ≈ 3000 × 9.97 ≈ 29,910 bits/sec ≈ 29.9 kbps

Properties of Channel Capacity Medium

  1. Capacity increases with bandwidth B (linearly) and with log of SNR (diminishing returns at high SNR).
  2. Even with infinite bandwidth, capacity approaches a finite limit: C∞ = (S/N₀)·log₂e ≈ 1.44·S/N₀ (where N₀ = noise power spectral density) — this is the absolute limit imposed by noise power alone.
  3. Trade-off: the same capacity can be achieved with high bandwidth + low SNR, or low bandwidth + high SNR.

7. Channel Coding Theorem (Shannon's Second Theorem) High ⭐⭐⭐⭐⭐ — extremely important theory

English

Shannon's Channel Coding Theorem states: For a discrete memoryless channel with capacity C, if the information transmission rate R is less than or equal to C (R ≤ C), then there exists a coding scheme such that the probability of error can be made arbitrarily small (approaching zero) by increasing the code block length, while keeping R fixed. Conversely, if R > C, reliable (error-free) transmission is not possible, no matter how clever the code.

Hinglish

Yeh Information Theory ka sabse important result hai! Iska matlab — agar tum data ko channel capacity C se kam ya equal rate pe bhejo, to (achha encoding/decoding scheme use karke) error-probability ko almost zero tak le ja sakte ho — bina speed kam kiye! Lekin agar capacity C se zyada rate pe bhejne ki koshish karo, to error-free transmission kabhi possible nahi, chahe kitna bhi smart code design karo. Ye theorem hi batata hai ki error-correcting codes (jo Unit 4/5 mein padhenge) kyu kaam karte hain.

Significance / Key Takeaways High

  • It proves that reliable communication is possible even over noisy channels — as long as R ≤ C, which was a revolutionary (and initially counter-intuitive) result in 1948.
  • It does NOT tell us how to construct such a code — only that one exists. The theorem is a pure existence proof.
  • It establishes capacity C as a sharp threshold: below it, arbitrarily reliable communication is achievable; above it, it is fundamentally impossible.
  • This motivated decades of research into practical error-correcting codes (Linear Block, Cyclic, Convolutional, Turbo, LDPC) that try to approach the Shannon limit.

8. Shannon Limit High ⭐⭐⭐⭐

English

The Shannon Limit is the theoretical maximum data rate (= channel capacity C) at which information can be transmitted over a given channel with an arbitrarily low (→0) probability of error. It represents the ultimate boundary on communication efficiency dictated by the channel's bandwidth and noise — no real coding scheme can exceed it.

Hinglish

Shannon Limit = wo "ultimate speed limit" jo ek channel apni bandwidth aur noise ki wajah se allow karta hai. Iske aage koi bhi coding scheme — chahe kitna bhi advanced ho — error-free data nahi bhej sakta. Modern codes (Turbo codes, LDPC codes — jo 4G/5G/WiFi mein use hote hain) is limit ke bahut close (0.5dB ke andar!) pohoch chuke hain — yehi unki achievement hai.

❓ Unit 3 — Q&A (RTU Exam Pattern)

Q1. Define prefix code. Why is it also called an instantaneous code? ★★★ 5 Marks
A code where no codeword is a prefix of another. Called "instantaneous" because the receiver can decode each symbol the instant its codeword is complete, without waiting for further bits. Example given above with valid/invalid cases.
Q2. Explain Huffman coding algorithm. Construct Huffman code for given symbol probabilities and find efficiency. ★★★★★ 10 Marks — guaranteed numerical every year
Algorithm: sort by probability, repeatedly combine two lowest-probability nodes, assign 0/1 to branches, repeat till root. Full worked example with A(0.4),B(0.2),C(0.2),D(0.1),E(0.1) → Lavg=2.2 bits, η=96.5% given above — practice this exact pattern with different probability sets.
Q3. Explain Shannon-Fano coding algorithm with a suitable example. ★★★★ 7 Marks
Top-down recursive splitting into roughly-equal-probability halves, assigning 0/1 at each split. Full example with same 5-symbol set given above for direct Huffman comparison.
Q4. Differentiate between Huffman coding and Shannon-Fano coding. ★★★★ 5 Marks — very frequently asked
Huffman = bottom-up, always optimal. Shannon-Fano = top-down, not always optimal. Full comparison table given above (approach, optimality, tree construction, efficiency, practical use).
Q5. Explain Lempel-Ziv coding technique. How is it different from Huffman/Shannon-Fano coding? ★★★★ 7 Marks
LZ is dictionary-based/adaptive — no prior probability knowledge needed, builds dictionary of repeated patterns on the fly and replaces them with back-references (offset, length, next char in LZ77). Differs from Huffman/SF which require known symbol probabilities and compress individual symbols, not sequences. Comparison table given above.
Q6. Explain LZ77 sliding-window compression with an example. ★★★ 5 Marks
Uses search buffer (past data) + look-ahead buffer (upcoming data); finds longest match in search buffer, outputs (offset, length, next_character) triple instead of raw repeated characters. Example with "ABABABA" given above.
Q7. State and derive the Shannon-Hartley theorem for channel capacity of a continuous channel. ★★★★★ 7-10 Marks
C = B log₂(1+S/N) bits/sec for an AWGN band-limited channel. Explain B=bandwidth, S/N=SNR. Mention that capacity grows linearly with B but only logarithmically with SNR (diminishing returns).
Q8. Numerical: A channel has B=3 kHz, SNR=1000. Find its channel capacity. ★★★★ 5 Marks numerical
C = 3000×log₂(1001) ≈ 29.9 kbps. Full solution above.
Q9. State and explain Shannon's Channel Coding Theorem (Shannon's Second Theorem). ★★★★★ 10 Marks — most important theory question in whole unit
If R≤C, a code exists making error probability arbitrarily small with increasing block length; if R>C, reliable transmission is impossible. It's an existence proof (doesn't construct the code). Full explanation + significance points given above.
Q10. What is meant by the "Shannon Limit"? Why can no practical system exceed it? ★★★ 5 Marks
Shannon Limit = the channel capacity C itself — the absolute maximum reliable data rate given the channel's bandwidth and noise. No coding scheme, however clever, can communicate reliably above this rate because it is a fundamental information-theoretic bound, not an engineering limitation. Modern codes (Turbo/LDPC) approach it within ~0.5dB.
Q11. Explain the relationship between channel capacity, channel coding theorem, and Shannon limit. ★★★ 5 Marks — conceptual linking question
Channel capacity C is the maximum rate (Shannon-Hartley gives formula for continuous channels). Channel coding theorem proves that reliable transmission is achievable for any R≤C. "Shannon limit" is the practical/colloquial name for this same capacity boundary — the three concepts describe the same underlying limit from definition → proof → practical naming.
