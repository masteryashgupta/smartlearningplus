Experiment 9: Minimum Cost Spanning Tree using Kruskal's Algorithm

Aim: Find Minimum Cost Spanning Tree of a given undirected graph using Kruskal's algorithm.

Source code

This is the program from the lab manual, unchanged. Compile it with gcc aoa_exp9.c -o exp9 and run ./exp9 (on Windows with MinGW, exp9).

#include <stdio.h>
#include <stdlib.h>
#include <time.h>
struct Edge
{
    int u, v, weight;
};
int parent[100];
// Find function with path compression
int find(int i)
{
    if(parent[i] == i)
    return i;
    return parent[i] = find(parent[i]);
}
// Union function
void unionSet(int a, int b)
{
    int rootA = find(a);
    int rootB = find(b);
    if(rootA != rootB)
    parent[rootA] = rootB;
}
// Function to sort edges by weight (ascending)
void sortEdges(struct Edge edges[], int e)
{
    int i, j;
    struct Edge temp;
    for(i = 0; i < e - 1; i++)
    {
        for(j = 0; j < e - i - 1; j++)
        {
            if(edges[j].weight > edges[j + 1].weight)
            {
                temp = edges[j];
                edges[j] = edges[j + 1];
                edges[j + 1] = temp;
            }
        }
    }
}
int main()
{
    int n, e, i;
    clock_t start, end;
    double cpu_time_used;
    printf("Enter number of vertices: ");
    scanf("%d", &n);
    printf("Enter number of edges: ");
    scanf("%d", &e);
    struct Edge edges[e];
    printf("Enter edges (u v weight):\n");
    for(i = 0; i < e; i++)
    {
        printf("Edge %d: ", i + 1);
        scanf("%d %d %d", &edges[i].u, &edges[i].v, &edges[i].weight);
    }
    // Initialize parent array (Union-Find)
    for(i = 0; i < n; i++)
    parent[i] = i;
    // Start timing
    start = clock();
    // Sort edges by weight (Greedy choice)
    sortEdges(edges, e);
    int mstEdgeCount = 0;
    int totalCost = 0;
    printf("\nEdges in Minimum Cost Spanning Tree (Kruskal's Algorithm):\n");
    for(i = 0; i < e && mstEdgeCount < n - 1; i++)
    {
        int rootU = find(edges[i].u);
        int rootV = find(edges[i].v);
        if(rootU != rootV)
        {
            printf("Edge %d: (%d -> %d) cost = %d\n", mstEdgeCount + 1, edges[i].u, edges[i].v, edges[i].weight);
            totalCost += edges[i].weight;
            unionSet(rootU, rootV);
            mstEdgeCount++;
        }
    }
    // End timing
    end = clock();
    cpu_time_used = ((double)(end - start)) / CLOCKS_PER_SEC;
    printf("\nMinimum Cost of Spanning Tree = %d\n", totalCost);
    printf("\nTime Required = %f seconds\n", cpu_time_used);
    return 0;
}

Explanation (from the manual)

Concept

Like Prim's Algorithm, this also computes the Minimum Cost Spanning Tree (MST) — connecting all cities with the smallest possible total cost, keeping every city connected, without forming a cycle. However, Kruskal's approach works differently.

Prim's grows one connected group step by step from a starting point. Kruskal's instead takes all roads (edges), sorts them from cheapest to most expensive, and then picks edges one at a time starting with the cheapest. The only rule: if an edge would form a cycle (i.e., its two endpoints are already connected through previously chosen edges), skip it. Otherwise, take it — continue until (n−1) edges have been chosen (where n is the number of cities).

Checking whether two cities are already connected uses a technique called Union-Find.

Worked Example

  5 cities (0 to 4), edges sorted cheapest to costliest:
  0-1=2, 1-2=3, 1-4=5, 0-3=6, 1-3=8, 2-4=7, 3-4=9
  Step 1: 0-1 (cost=2) → no cycle, take it. Connected: {0,1}
  Step 2: 1-2 (cost=3) → no cycle, take it. Connected: {0,1,2}
  Step 3: 1-4 (cost=5) → no cycle, take it. Connected: {0,1,2,4}
  Step 4: 0-3 (cost=6) → no cycle, take it. Connected: {0,1,2,3,4} — all connected!
  (If 1-3=8 had been tried next, it would be skipped, since 1 and 3 are already connected —
  adding it would create a cycle.)

  Total minimum cost = 2+3+5+6 = 16 — the same result Prim's Algorithm found on this graph.

  Both algorithms correctly find an MST; they simply take different paths to get there.

Time Complexity

Most of the time in Kruskal's Algorithm is spent sorting the edges, which takes O(E log E), where E is the total number of edges. Kruskal's tends to perform better than Prim's when a graph has relatively few edges compared to vertices (a "sparse" graph).

What the Program Does

  1. The user enters the number of vertices (cities) and edges (roads).
  2. The user enters every edge (its two endpoints and the cost between them).
  3. The program sorts all edges from cheapest to costliest.
  4. Edges are then taken one by one — kept if they don't form a cycle, skipped otherwise (checked using the Union-Find technique).
  5. Each chosen edge is printed, along with its cost.
  6. The total minimum cost is printed at the end.
  7. The time taken (in seconds) is displayed.

In short: sort all roads from cheapest to costliest, take them one at a time skipping any that would form a cycle, until every city is connected.

Viva questions

Explain Kruskal’s algorithm.

Sort all edges by weight. Take them in increasing order and add an edge if it does not form a cycle, until V - 1 edges are chosen.

How is a cycle detected in this program?

With the disjoint set (union-find) functions find and a union step: an edge is added only if its two ends have different parents.

What is the time complexity of Kruskal’s algorithm?

O(E log E), which is dominated by sorting the edges.

Which technique does it use?

The greedy method.

When is Kruskal better than Prim?

For sparse graphs, where the number of edges is small.

What does path compression do in find()?

It makes every visited node point directly to the root (parent[i] = find(parent[i])), which speeds up later searches.

What happens if the graph is not connected?

The algorithm finds a minimum spanning forest, with fewer than V - 1 edges.

How many edges does the tree have?

V - 1, here 4 edges for 5 vertices.
