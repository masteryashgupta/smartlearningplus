01. Storage Allocation HIGH
How does a compiler decide WHERE in memory each variable lives at runtime?
Definition

Storage Allocation is the process performed by a compiler/runtime system of assigning memory addresses to the data objects (variables, arrays, procedure activation records) of a program, so that the values can be stored and retrieved correctly during execution.

🇮🇳 Hinglish Explanation
Jab bhi tum koi variable declare karte ho (jaise int x;), compiler ko decide karna padta hai ki yeh variable RAM mein kahan store hoga aur kab tak rahega. Storage allocation isi process ka naam hai — compiler memory ko organize karta hai taaki har variable ko sahi jagah, sahi time pe milta rahe.

Run-Time Memory Layout

Fig 1: Typical run-time memory layout — Code, Static Data, Heap (grows down), Stack (grows up)

Memory Regions Explained

RegionPurposeLifetime
Code/Text SegmentStores the compiled machine instructionsFixed, entire program run
Static/Global DataGlobal variables, static variables, string literalsEntire program run
HeapDynamically allocated memory (malloc/new)Until explicitly freed
StackActivation records of procedures (local vars, parameters, return address)Only while procedure is active

02. Storage Allocation Strategies HIGH

Definition

A storage allocation strategy defines the rule by which memory is assigned to (and reclaimed from) program variables, based on when and how long the variable needs to exist.

🇮🇳 Hinglish
Different variables ka lifetime different hota hai — kuch poore program mein zinda rehte hain, kuch sirf ek function call ke liye, aur kuch jab tak tum khud delete na karo. Inhe handle karne ke liye 3 strategies hain: Static, Stack, aur Heap allocation.

Types of Storage Allocation Strategies EXAM HOT

StrategyHow it WorksUsed For
Static AllocationMemory address is bound at compile time and fixed for the entire program executionGlobal variables, static variables, constants
Stack AllocationMemory allocated/deallocated in LIFO order as procedures are called/return; managed via activation records on a runtime stackLocal variables, parameters, recursive function calls
Heap AllocationMemory allocated/deallocated in any order at runtime, as requested by the program; not LIFODynamic data structures (linked lists, objects via malloc/new)
⚠ Important

Stack allocation does NOT support recursive procedures whose local data must survive after the call returns (e.g. a function returning a pointer to a local variable) — that data must instead be placed on the heap.

Example

In C: int g; (global) → static allocation. void f(){int x;} → x is stack-allocated, created when f() is called, destroyed when f() returns. int *p = malloc(4); → heap-allocated, persists until free(p) is called.

03. Activation Records HIGH — MOST ASKED

Definition

An Activation Record (AR), also called a stack frame, is a contiguous block of memory pushed onto the runtime stack each time a procedure is called, containing all the information needed to manage that single execution (activation) of the procedure.

🇮🇳 Hinglish
Jab bhi koi function call hota hai, ek "packet" of memory stack pe banta hai jisme us function ke saare local variables, parameters, aur control info store hoti hai. Yeh packet hi Activation Record kehlata hai. Jab function return karta hai, yeh packet stack se pop ho jaata hai.

Fields of a Typical Activation Record EXAM HOT — Draw the diagram!

Fig 2: Layout of an Activation Record (bottom-to-top order may vary by implementation)

FieldPurpose
Actual ParametersValues/addresses passed by the caller to the callee
Return ValueSpace reserved for the value the procedure will return to the caller
Control Link (Dynamic Link)Pointer to the activation record of the caller — used to restore stack pointer on return
Access Link (Static Link)Pointer to the activation record of the lexically enclosing (statically surrounding) procedure — used to access non-local names
Saved Machine StatusRegister values, program counter, and other machine state to restore when control returns to caller
Local DataStorage for the local variables declared in the procedure
TemporariesStorage for intermediate values generated while evaluating expressions
⚠ Control Link vs Access Link — Frequently Confused!

Control Link = "who called me?" (caller's AR, used for returning). Access Link = "who is my parent scope?" (used for finding non-local variables in nested/lexically-scoped languages like Pascal).

04. Accessing Local & Non-Local Names in a Block-Structured Language HIGH

Definition

In a block-structured language (where procedures can be nested inside other procedures, like Pascal), a local name refers to a variable declared within the currently executing procedure, while a non-local name refers to a variable declared in an enclosing (outer) procedure's scope.

🇮🇳 Hinglish
Local variable matlab jo us function ke andar hi declare hua hai. Non-local variable matlab jo function ke bahar, kisi enclosing/parent function mein declare hua hai, lekin phir bhi accessible hai because of nested scoping (jaise Pascal mein hota hai, C mein generally nahi).

Method: Access Links (Static Links) EXAM HOT

To access a non-local name, the compiler generates code that follows the chain of access links from the current activation record, going up through enclosing procedures' activation records, by a number of hops equal to the difference in nesting depth between the use and the declaration.

nesting_depth_difference = depth(current procedure) − depth(declaring procedure)
Example

If procedure C (nested at depth 3) wants to access a variable declared in procedure A (at depth 1), the generated code follows 2 access links upward from C's AR to reach A's AR.

Method: Display (Alternative to Access Links)

MethodDescriptionAccess Time
Access Link ChasingFollow a chain of pointers, one hop per nesting levelO(nesting depth) — slower for deep nesting
Display ArrayMaintain a global array of pointers, one per nesting level, always pointing to the most recent AR at that levelO(1) — direct array lookup

05. Parameter Passing HIGH

Definition

Parameter passing refers to the mechanism by which arguments (actual parameters) supplied by the caller are communicated to the formal parameters of the called procedure, determining whether the callee can modify the caller's original variables.

🇮🇳 Hinglish
Parameter passing decide karta hai ki jab tum function ko value bhejte ho, to function us original variable ko change kar sakta hai ya sirf uski copy use karta hai. Yeh alag-alag tareeke (call by value, call by reference, etc.) se ho sakta hai.

Parameter Passing Methods EXAM HOT — Comparison guaranteed

MethodHow it WorksCan Modify Caller's Variable?
Call by ValueA copy of the actual parameter's value is passed; callee works on the copyNo
Call by Reference (Address)The address (location) of the actual parameter is passed; callee directly accesses caller's memoryYes
Call by Copy-Restore (Value-Result)Value copied in at call time; on return, the final value is copied back to the actual parameterYes (only after return)
Call by NameActual parameter is textually substituted for the formal parameter (like macro expansion); re-evaluated every useYes (indirectly)
⚠ Important

Call by Reference can produce aliasing — if two formal parameters end up referring to the same actual variable, unexpected side-effects can occur. This is a classic 5-mark RTU question.

Example

C uses call by value by default (pass &x to simulate reference). C++ supports true call by reference using & in parameter declarations. Pascal's var parameters are call by reference.

06. Symbol Table Organization HIGH

Definition

A Symbol Table is a data structure maintained and used by the compiler throughout the compilation process to store information about identifiers (variables, functions, classes) appearing in the source program — such as their type, scope, memory location, and other attributes.

🇮🇳 Hinglish
Symbol table ek tarah ki "directory" hai jisme compiler har variable/function ka record rakhta hai — uska naam, type, kahan declare hua, scope kya hai, kitni memory chahiye, etc. Compiler ke har phase (lexical analysis se code generation tak) is table ko use karta hai.

Information Stored in a Symbol Table Entry

AttributeDescription
NameIdentifier name as it appears in source code
TypeData type (int, float, array, function, etc.)
ScopeBlock/function in which the identifier is visible
Memory Location (Offset)Relative address within its activation record/storage area
SizeNumber of bytes required for storage
Line NumberLine of declaration, used for error reporting
Other Attributese.g. is it a constant? array dimensions? parameter list for functions

Operations on a Symbol Table

  • Insert(name, attributes): Add a new identifier with its attributes
  • Lookup(name): Search for an identifier and retrieve its attributes
  • Delete/Exit Scope: Remove identifiers when their scope ends (block exit)
  • Update: Modify attributes once more information becomes known (e.g. type after declaration)

Symbol Table Organization for Block-Structured Languages

ApproachDescription
Single Global TableOne flat table for all names — simple but cannot handle scoping/shadowing correctly
Stack of Tables (per scope)A new table is pushed for each new block/scope; popped when block ends. Lookup searches from innermost to outermost table

07. Data Structures Used in Symbol Tables MEDIUM

Definition

The choice of underlying data structure for implementing a symbol table determines the time complexity of insertion and lookup operations — a critical performance factor since the symbol table is accessed extremely frequently during compilation.

🇮🇳 Hinglish
Symbol table ko implement karne ke liye alag-alag data structures use ho sakte hain — har ek ka apna trade-off hai speed aur memory usage ke beech.

Comparison of Symbol Table Implementations EXAM HOT

Data StructureInsert TimeLookup TimeNotes
Linear List (Array/Linked List)O(1)O(n)Simple, but slow lookup for large programs
Sorted Array (Binary Search)O(n)O(log n)Faster lookup, but costly insertion (must maintain order)
Hash TableO(1) avgO(1) avgMost commonly used in real compilers — fastest on average
Binary Search Tree (BST)O(log n) avgO(log n) avgGood balance; degrades to O(n) if unbalanced
⚠ Important

Hash tables are the most widely used in real-world compilers (GCC, LLVM) because they offer the best average-case performance for the insert/lookup-heavy workload of symbol table management.

Example

A hash table symbol table uses a hash function h(name) to compute a bucket index; collisions are resolved using chaining (linked list per bucket) — allowing O(1) average insert and lookup even for thousands of identifiers.

Hinglish Trick

Activation Record Fields: "Rahul Passed Compiler And Scored Lot of Time" (Return value, Parameters, Control link [Dynamic], Access link [Static], Saved machine status, Local variables, Temporaries).
Control vs Access Link: Control (Dynamic) = Kisne mujhe call kiya (Caller). Access (Static) = Mera baap kaun hai (Enclosing lexical parent scope)!

Q1 · 10 MARKS
10 MARKS
What is an Activation Record? Explain its fields with a neat diagram.

An Activation Record (AR) is a block of memory allocated on the runtime stack for each invocation of a procedure, containing: Actual Parameters, Return Value space, Control Link (pointer to caller's AR), Access Link (pointer to lexically enclosing procedure's AR), Saved Machine Status, Local Data, and Temporaries. It is created when the procedure is called and destroyed when it returns. (Refer to the AR diagram above for the exam — draw it exactly.)

Q3 · 5 MARKS
5 MARKS
Explain the different storage allocation strategies used by compilers.

Static Allocation: address fixed at compile time, used for global/static variables. Stack Allocation: LIFO allocation/deallocation matching procedure call/return, used for locals & parameters. Heap Allocation: arbitrary-order allocation/deallocation at runtime, used for dynamic data structures (malloc/new), required when data must outlive the procedure that created it.

Q4 · 10 MARKS
10 MARKS
How are local and non-local names accessed in a block-structured language? Explain with access links.

Local names are accessed directly via offsets within the current activation record. Non-local names (declared in an enclosing procedure) are accessed by following the chain of access links (static links) from the current AR upward through enclosing procedures' ARs, a number of hops equal to the difference in nesting depth between the usage and declaration points. An alternative is the Display technique — a global array of pointers (one per nesting level) giving O(1) access instead of chasing a chain of links, trading extra maintenance overhead on call/return for faster lookup.

Q5 · 5 MARKS
5 MARKS
Explain the different parameter passing methods with examples.

Call by Value: a copy of the value is passed; changes inside the function don't affect the caller (default in C, Java for primitives). Call by Reference: the address is passed; changes directly affect the caller's variable (C++ references, Pascal var parameters). Call by Copy-Restore: value copied in, copied back out at return. Call by Name: textual substitution of the argument expression, re-evaluated at each use (rare, historic — Algol).

Q6 · 5 MARKS
5 MARKS
What is a Symbol Table? What information does it store?

A Symbol Table is a data structure used by the compiler to store information about every identifier in the source program. It stores: name, data type, scope, memory location/offset, size, line number of declaration, and other attributes (e.g. parameter list for functions, dimensions for arrays). It supports operations Insert, Lookup, Delete and Update, and is consulted/updated throughout all phases of compilation.

Q8 · 5 MARKS
5 MARKS
Why is stack allocation insufficient for all variables? When is heap allocation necessary?

Stack allocation works in strict LIFO order matching procedure call/return — but it cannot handle data that must outlive the procedure that created it (e.g. a function returning a pointer to a local array, or dynamically-sized data structures like linked lists). In such cases, heap allocation is required, since heap memory can be allocated and freed in any order, independent of the call stack's structure.

Q9 · 5 MARKS — Short Note
5 MARKS
Write a short note on the run-time memory layout of a program.

A typical run-time memory layout consists of four regions: the Code/Text Segment (compiled instructions, fixed), Static/Global Data (global & static variables, fixed for program lifetime), the Heap (dynamically allocated memory, conventionally grows downward toward the stack), and the Stack (activation records of active procedures, conventionally grows upward toward the heap). This layout allows the heap and stack to share the remaining address space flexibly.

Q10 · 5 MARKS
5 MARKS
What is aliasing in the context of call by reference parameter passing?

Aliasing occurs when two or more formal parameters (or a formal parameter and a global variable) end up referring to the same memory location, typically because the same variable was passed as multiple arguments under call-by-reference. This can cause unexpected side effects, since a write through one parameter name silently changes the value seen through the other name, making program behaviour harder to predict and debug.
