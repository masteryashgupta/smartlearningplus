Experiment 1: Quick Sort

Aim: Sort a given set of elements using the Quick Sort method and determine the time required to sort the elements. The elements can be read from a file or can be generated using the random number generator.

Source code

This is the program from the lab manual, unchanged. Compile it with gcc aoa_exp1.c -o exp1 and run ./exp1 (on Windows with MinGW, exp1).

/* program to sort elements of an array using Quick Sort */
#include <stdio.h>
#include <stdlib.h>
#include <time.h>
// Function to swap two elements
void swap(int *a, int *b)
{
    int temp = *a;
    *a = *b;
    *b = temp;
}
// Partition function
int partition(int arr[], int low, int high)
{
    int pivot = arr[high];
    int i = low - 1;
    for (int j = low; j < high; j++)
    {
        if (arr[j] < pivot)
        {
            i++;
            swap(&arr[i], &arr[j]);
        }
    }
    swap(&arr[i + 1], &arr[high]);
    return (i + 1);
}
// Quick Sort function
void quickSort(int arr[], int low, int high)
{
    if (low < high)
    {
        int pi = partition(arr, low, high);
        quickSort(arr, low, pi - 1);
        quickSort(arr, pi + 1, high);
    }
}
// Display array
void printArray(int arr[], int n)
{
    for (int i = 0; i < n; i++)
    printf("%d ", arr[i]);
    printf("\n");
}
int main()
{
    int n;
    printf("Enter number of elements: ");
    scanf("%d", &n);
    int arr[n];
    // Generate random numbers
    srand(time(NULL));
    for (int i = 0; i < n; i++)
    arr[i] = rand() % 1000;
    printf("\nUnsorted Array:\n");
    printArray(arr, n);
    // Start timer
    clock_t start = clock();
    quickSort(arr, 0, n - 1);
    // Stop timer
    clock_t end = clock();
    double time_taken = ((double)(end - start)) / CLOCKS_PER_SEC;
    printf("\nSorted Array:\n");
    printArray(arr, n);
    printf("\nExecution Time = %lf seconds\n", time_taken);
    return 0;
}

Explanation (from the manual)

Concept

Quick Sort is a sorting algorithm based on the divide-and-conquer strategy. Given an array of random numbers, e.g. [10, 7, 8, 9, 1, 5] , the goal is to arrange them in ascending order.

The idea is simple: choose one element as the pivot (usually the last element), and split the remaining elements into two groups:

  • Elements smaller than the pivot → left side
  • Elements larger than the pivot → right side

After this step, the pivot lands in its correct final sorted position (everything to its left is smaller, everything to its right is larger). The same process is then applied recursively to the left group and the right group, and so on, until every group has only 0 or 1 element left (already sorted).

Worked Example

  [10, 7, 8, 9, 1, 5] , pivot = 5
  Smaller values (1) go left, larger values (10, 7, 8, 9) go right:
  [1] 5 [10, 7, 8, 9]
  5 is now fixed in its correct place. The left group has only 1 element, already sorted. The
  right group [10, 7, 8, 9] goes through the same process again:
  pivot = 9 → [10, 7, 8] 9 []
  Then on [10, 7, 8] : pivot = 8 → [7] 8 [10]
  Putting it all together: [1, 5, 7, 8, 9, 10] — sorted!

Time Complexity

In most cases, Quick Sort is quite fast — O(n log n), meaning even large arrays sort quickly. However, in an unlucky case (e.g. the array is already sorted and the pivot always ends up being the smallest or largest element), it can slow down to O(n²), because each partition step separates off only one element at a time instead of splitting the array evenly.

What the Program Does

  1. The user is asked how many numbers to sort.
  2. Random numbers (0–999) are generated and displayed as the "Unsorted Array".
  3. Quick Sort runs using the process described above, while a timer is running.
  4. Once sorting is complete, the "Sorted Array" is printed.
  5. The time taken to sort (in seconds) is displayed.

In short: pick a pivot, split into smaller/larger groups, and repeat until everything is sorted.

Viva questions

What is Quick Sort?

A divide-and-conquer sorting algorithm. It picks a pivot, puts smaller elements on its left and larger ones on its right, then sorts the two sides the same way.

What is a pivot, and which element is the pivot here?

The element the array is split around. This program uses the last element, arr[high].

What does the partition function return?

The final index of the pivot, i + 1, after the pivot has been placed in its correct sorted position.

Give the best, average and worst case time of Quick Sort.

Best and average O(n log n). Worst O(n²), when the pivot is always the smallest or largest element, for example on an already sorted array.

How can the worst case be avoided?

By choosing the pivot randomly or as the median of three elements instead of always taking the last one.

Is Quick Sort stable? Is it in place?

It is in place (only the recursion stack, about O(log n), is extra) but it is not stable.

How does the program measure the time taken?

It calls clock() before and after sorting and divides the difference by CLOCKS_PER_SEC to get seconds.

Why is srand(time(NULL)) used?

It seeds the random number generator with the current time so that different numbers are produced on every run.

Compare Quick Sort and Merge Sort.

Quick Sort is in place and usually faster in practice but has an O(n²) worst case. Merge Sort is always O(n log n) and stable but needs extra O(n) memory.

Experiment 2: Merge Sort

Aim: Implement Merge Sort algorithm to sort a given set of elements and determine the time required to sort the elements. The elements can be read from a file or can be generated using the random number generator.

Source code

#include <stdio.h>
#include <stdlib.h>
#include <time.h>
// Function to merge two subarrays
void merge(int arr[], int left, int mid, int right)
{
    int i, j, k;
    int n1 = mid - left + 1;
    int n2 = right - mid;
    int L[n1], R[n2];
    // Copy data to temporary arrays
    for (i = 0; i < n1; i++)
    L[i] = arr[left + i];
    for (j = 0; j < n2; j++)
    R[j] = arr[mid + 1 + j];
    i = 0;
    j = 0;
    k = left;
    // Merge the temporary arrays
    while (i < n1 && j < n2)
    {
        if (L[i] <= R[j])
        {
            arr[k] = L[i];
            i++;
        }
        else
        {
            arr[k] = R[j];
            j++;
        }
        k++;
    }
    // Copy remaining elements of L[]
    while (i < n1)
    {
        arr[k] = L[i];
        i++;
        k++;
    }
    // Copy remaining elements of R[]
    while (j < n2)
    {
        arr[k] = R[j];
        j++;
        k++;
    }
}
// Merge Sort function
void mergeSort(int arr[], int left, int right)
{
    if (left < right)
    {
        int mid = left + (right - left) / 2;
        mergeSort(arr, left, mid);
        mergeSort(arr, mid + 1, right);
        merge(arr, left, mid, right);
    }
}
int main()
{
    int n, i;
    clock_t start, end;
    double cpu_time_used;
    printf("Enter the number of elements: ");
    scanf("%d", &n);
    int arr[n];
    // Generate random numbers
    srand(time(NULL));
    printf("\nGenerated Elements:\n");
    for (i = 0; i < n; i++)
    {
        arr[i] = rand() % 1000;
        printf("%d ", arr[i]);
    }
    // Start timing
    start = clock();
    mergeSort(arr, 0, n - 1);
    // End timing
    end = clock();
    cpu_time_used = ((double)(end - start)) / CLOCKS_PER_SEC;
    printf("\n\nSorted Elements:\n");
    for (i = 0; i < n; i++)
    {
        printf("%d ", arr[i]);
    }
    printf("\n\nTime Required = %f seconds\n", cpu_time_used);
    return 0;
}

Explanation (from the manual)

Concept

Merge Sort also follows divide-and-conquer, but does not use a pivot. Instead, the array is repeatedly split in half (divide) until each piece contains only a single element (a single element is always "sorted" by definition). The small sorted pieces are then combined back together in sorted order (merge) — this merging step is where the real work happens.

Two steps:

  • Divide — keep splitting the array into halves
  • Merge — combine sorted pieces into a larger sorted piece

Worked Example

  [38, 27, 43, 3, 9, 82, 10]
  Divide: [38, 27, 43] and [3, 9, 82, 10]
  Divide further: [38] [27, 43] and [3, 9] [82, 10]
  Divide until single elements: [38] [27] [43] and [3] [9] [82] [10]
  Now merge back in sorted order:  [27, 43]  (from [27] and [43]);  [3, 9]  and  [10, 82]  from
  their pairs.
  Merge one level up: [27, 38, 43] and [3, 9, 10, 82]
  Final merge: [3, 9, 10, 27, 38, 43, 82] — sorted!

  While merging, the smallest remaining element from each of the two groups is always
  compared, and the smaller one is placed first into the result — that is how the fully
  sorted array is built.

Time Complexity

Merge Sort always takes O(n log n) time, regardless of whether the input is already sorted, reverse sorted, or random — its performance stays consistent. This makes it more predictable than Quick Sort, which can degrade to O(n²) in the worst case. The trade-off is that Merge Sort needs extra memory for the temporary arrays used during merging, whereas Quick Sort can sort within the same array.

What the Program Does

  1. The user is asked how many elements to sort.
  2. Random numbers (0–999) are generated and shown as "Generated Elements".
  3. Merge Sort runs (the divide-and-merge process above), while a timer is running.
  4. Once complete, the "Sorted Elements" are printed.
  5. The time taken to sort (in seconds) is displayed.

In short: keep splitting the array until only single elements remain, then merge them back together in sorted order.

Viva questions

What is Merge Sort?

A divide-and-conquer algorithm that splits the array into halves, sorts each half recursively and then merges the two sorted halves.

What is the time complexity of Merge Sort?

O(n log n) in the best, average and worst cases, from the recurrence T(n) = 2T(n/2) + n.

What is its space complexity?

O(n), because the merge step uses temporary arrays.

Is Merge Sort stable?

Yes, if equal elements are taken from the left half first during the merge.

What does the merge function do?

It combines two already sorted parts into one sorted part by repeatedly copying the smaller of the two front elements.

Why is Merge Sort good for linked lists and external sorting?

It reads data sequentially and does not need random access, so it works well on lists and on files too large for memory.

What is the main disadvantage of Merge Sort?

It needs extra memory and is slower than in-place sorts like Quick Sort on small arrays.

What are the two steps of Merge Sort?

Divide the array into two halves (down to single elements), then merge the sorted halves back together.

Explanation (from the manual)

Concept

Bubble Sort is the simplest sorting technique. It repeatedly walks through the array from left to right, comparing each pair of adjacent elements. If the left element is larger than the right one, they are swapped. Every full pass pushes the largest remaining element towards the end of the array — much like an air bubble rising to the surface of water, which is where the name comes from. This process repeats until no more swaps are needed, meaning the array is fully sorted.

Worked Example

  [5, 1, 4, 2, 8]
  Pass 1 (compare left to right):
  5,1 → swap → [1, 5, 4, 2, 8]
  5,4 → swap → [1, 4, 5, 2, 8]
  5,2 → swap → [1, 4, 2, 5, 8]
  5,8 → no swap → [1, 4, 2, 5, 8] (8 was the largest, now fixed at the end)
  Pass 2: 1,4 no swap; 4,2 → swap → [1, 2, 4, 5, 8]; 4,5 no swap (5 now fixed)
  Pass 3: 1,2 no swap; 2,4 no swap (no swaps at all — array is sorted)
  Final: [1, 2, 4, 5, 8] — sorted!

Time Complexity

Bubble Sort is easy to understand but slow — both the average and worst case take O(n²) time, because every element may need to be compared repeatedly with its neighbour. It is fine for small arrays, but for larger data sets, Quick Sort or Merge Sort are much faster choices.

What the Program Does

  1. The user is asked how many elements to sort.
  2. Random numbers (0–999) are generated and shown as "Generated Elements".
  3. Bubble Sort runs (the adjacent compare-and-swap process above), with a timer running.
  4. Once complete, the "Sorted Elements" are printed.
  5. The time taken to sort (in seconds) is displayed.

In short: compare neighbouring elements, push the larger one forward (swap), and repeat until everything is sorted.

Viva questions

What is Bubble Sort?

A simple sort that repeatedly compares adjacent elements and swaps them if they are in the wrong order, so the largest elements move to the end like bubbles.

How many passes and comparisons does it need?

At most n - 1 passes and n(n - 1)/2 comparisons in total.

What is its time complexity?

O(n²) in the average and worst cases. In this program there is no early-exit flag, so even the best case is O(n²). With a flag that stops when no swap happens, the best case becomes O(n).

Is Bubble Sort stable and in place?

Yes, both. Equal elements are never swapped, and only O(1) extra space is used.

What is the space complexity?

O(1) auxiliary space.

How does Bubble Sort compare with Selection and Insertion Sort?

All three are O(n²). Bubble Sort makes the most swaps, Selection Sort the fewest, and Insertion Sort is faster on nearly sorted data.

When is Bubble Sort used?

Mostly for teaching and for very small data sets, because it is simple but slow.

After the first pass, where is the largest element?

At the last position, which is its final sorted place.

{
    int n, i, key, pos = -1;

Explanation (from the manual)

Concept

Linear Search is the simplest way to search for a value. Given an array, e.g. [70, 206, 592, 194, 912, 40] , we want to know whether a specific number (the "key", e.g. 194) exists in it, and if so, at which position.

The method: start from the beginning of the array and check each element one by one. As soon as the target value is found, stop and report its position. If the entire array is checked and the value is never found, report "not found". It is called "linear" because it scans through the data in a straight line, one step at a time, without taking any shortcuts.

Worked Example

  Array: [70, 206, 592, 194, 912, 40] , searching for: 194
  Step 1: index 0 → 70 (not a match)
  Step 2: index 1 → 206 (not a match)
  Step 3: index 2 → 592 (not a match)
  Step 4: index 3 → 194 → found!
  Result: "Element 194 found at position 4"

  If we searched for 500 (which is not in the array), the program would check the entire
  array and then report "Element 500 not found in the array".

Time Complexity

Linear Search has a time complexity of O(n) — in the worst case (the element is at the end, or not present at all), the entire array must be checked. In the best case (the element is found immediately), it only takes O(1). It works fine for small arrays, but for large sorted data sets, Binary Search (the next experiment) is much faster.

What the Program Does

  1. The user is asked how many elements are in the array.
  2. Random numbers (0–999) are generated and shown as "Generated Elements".
  3. The user is asked which number to search for (the search key).
  4. A timer starts, and the array is scanned one element at a time (the process above).
  5. If found, its position is reported; otherwise "not found" is printed.
  6. The time taken to search (in seconds) is displayed.

In short: check elements one by one from the start, and stop as soon as a match is found.

Viva questions

What is Linear Search?

A search that checks the elements one by one from the start until the key is found or the array ends.

What is its time complexity?

Best case O(1) (key is first), average and worst case O(n).

Does the array have to be sorted?

No. Linear Search works on unsorted data.

What are the advantages of Linear Search?

It is simple, needs no sorting, and works on any list, even a linked list.

What are its disadvantages?

It is slow for large data because it may check every element.

What is a sentinel linear search?

A version that puts the key at the end of the array as a sentinel, so the loop needs only one comparison per element.

Compare Linear Search and Binary Search.

Linear is O(n) and works on unsorted data. Binary is O(log n) but needs sorted data.

What does this program report if the key occurs twice?

It stops at the first match, so only the first position is reported.

Experiment 5: Binary Search

Aim: Implement Binary Search algorithm to search a value from a given set of elements. The elements can be read from a file or can be generated using the random number generator.

Source code

This is the program from the lab manual, unchanged. Compile it with gcc aoa_exp5.c -o exp5 and run ./exp5 (on Windows with MinGW, exp5).

#include <stdio.h>
#include <stdlib.h>
#include <time.h>
// Function to sort array (needed before binary search)
void sortArray(int arr[], int n)
{
    int i, j, temp;
    for(i = 0; i < n - 1; i++)
    {
        for(j = 0; j < n - i - 1; j++)
        {
            if(arr[j] > arr[j + 1])
            {
                temp = arr[j];
                arr[j] = arr[j + 1];
                arr[j + 1] = temp;
            }
        }
    }
}
// Binary Search function
int binarySearch(int arr[], int n, int key)
{
    int low = 0, high = n - 1, mid;
    while(low <= high)
    {
        mid = low + (high - low) / 2;
        if(arr[mid] == key)
        return mid;
        else if(arr[mid] < key)
        low = mid + 1;
        else
        high = mid - 1;
    }
    return -1;
}
int main()
{
    int n, i, key, pos;
    clock_t start, end;
    double cpu_time_used;
    printf("Enter the number of elements: ");
    scanf("%d", &n);
    int arr[n];
    // Generate random numbers
    srand(time(NULL));
    for(i = 0; i < n; i++)
    arr[i] = rand() % 1000;
    // Sort the array first (Binary Search needs sorted data)
    sortArray(arr, n);
    printf("\nGenerated (Sorted) Elements:\n");
    for(i = 0; i < n; i++)
    printf("%d ", arr[i]);
    printf("\n\nEnter the element to search: ");
    scanf("%d", &key);
    // Start timing
    start = clock();
    pos = binarySearch(arr, n, key);
    // End timing
    end = clock();
    cpu_time_used = ((double)(end - start)) / CLOCKS_PER_SEC;
    if(pos != -1)
    printf("\nElement %d found at position %d\n", key, pos + 1);
    else
    printf("\nElement %d not found in the array\n", key);
    printf("\nTime Required = %f seconds\n", cpu_time_used);
    return 0;
}

Explanation (from the manual)

Concept

Binary Search is considerably faster than Linear Search — but it requires the array to already be sorted. Instead of scanning the whole array, it checks the middle element directly:

If the middle element equals the target → found, done. If the target is smaller than the middle → it can only be in the left half, so the right half is discarded entirely. If the target is larger than the middle → it can only be in the right half, so the left half is discarded entirely.

Each step throws away half of the remaining array, which is why this method is so fast even for large arrays.

Worked Example

  Array: [12, 166, 241, 740, 758, 881] (indices 0 to 5), searching for: 740
  Step 1: low=0, high=5, mid=2 → array[2]=241. 740>241, discard left half, low=3
  Step 2: low=3, high=5, mid=4 → array[4]=758. 740<758, discard right half, high=3
  Step 3: low=3, high=3, mid=3 → array[3]=740 → match found!
  Result: "Element 740 found at position 4" — found in just 3 steps, compared to 5 steps a
  Linear Search would need starting from index 0.

Time Complexity

Binary Search has a time complexity of O(log n) — even with 1000 elements, the answer is found in roughly 10 steps, because half of the data is discarded at every step. This is far faster than Linear Search's O(n), but remember the key condition: the array must ALWAYS be sorted first, otherwise Binary Search can give an incorrect result.

What the Program Does

  1. The user is asked how many elements are in the array.
  2. Random numbers are generated and then sorted (Binary Search requires sorted data) — shown as "Generated (Sorted) Elements".
  3. The user is asked which number to search for.
  4. A timer starts, and the search proceeds by repeatedly narrowing the low-high-mid range (the process above).
  5. If found, its position is reported; otherwise "not found" is printed.
  6. The time taken to search (in seconds) is displayed.

In short: check the middle element, keep only the half where the target could be, and discard the other half — repeat until found.

Viva questions

What is Binary Search?

A search on a sorted array that compares the key with the middle element and discards half of the array each time.

What is the main requirement of Binary Search?

The array must be sorted. On unsorted data the result is wrong.

What is its time complexity?

Worst and average O(log n), best O(1). About 10 comparisons are enough for 1000 elements.

Why is mid written as low + (high - low) / 2?

To avoid integer overflow that (low + high) / 2 could cause for very large indexes.

What do low, high and mid mean?

low and high are the ends of the part still being searched, and mid is its middle index.

Recursive or iterative Binary Search: what is the difference?

Both have O(log n) time. The iterative one uses O(1) space, the recursive one uses O(log n) stack space.

Compare Binary Search and Linear Search.

Binary is much faster on large data but needs sorting first. Linear needs no sorting.

Concept

The Greedy method (used in Experiment 7) does not work reliably here, because "take the best-ratio item first" doesn't always give the best possible answer when items can't be split. So this problem is solved using Dynamic Programming (DP), which systematically stores all possibilities in a table to find the best answer.

The DP idea: build a table where rows represent items and columns represent capacity (0 up to the maximum capacity). Each cell stores "the maximum profit achievable using only these items, with this much capacity available". For every item, two choices are checked — include it, or exclude it — whichever gives more profit is stored in the table. The final cell holds the overall maximum profit.

Explanation (from the manual)

Concept

Given two strings, e.g. "AGGTAB" and "GXTXAYB" , the goal is to find the longest common subsequence between them.

A "subsequence" means: keeping the letters of a string in the same relative order, but allowed to skip some letters in between (the order itself must not change). For example, a subsequence of "AGGTAB" could be "GTB" (some letters skipped, but order preserved).

A "common subsequence" is one that appears in both strings. We want the longest such subsequence.

This is solved using Dynamic Programming: build a table comparing every character pair from both strings.

If the current characters of both strings are the same → this character becomes part of the LCS, so add 1 to the previous diagonal answer. If they are different → check both possibilities (skip a character from one string, or from the other) and keep whichever gives the longer result.

Worked Example

  String X = "AGGTAB"
  String Y = "GXTXAYB"

  The DP table is filled character by character, and matching characters are collected in
  order: G, T, A, B.

  Checking: "GTAB" appears in the same order in both strings —
  X = A-G-G-T-A-B (G, T, A, B appear in this order)
  Y = G-X-T-X-A-Y-B (G, T, A, B appear in this order too, skipping X, X, Y)

Time Complexity

LCS has a time complexity of O(m × n), where m and n are the lengths of the two strings. Every character pair is checked exactly once in the table, which makes this approach far more efficient than brute force (generating and comparing every possible subsequence, which would be extremely slow).

#include <stdlib.h>
#include <time.h>
int board[20];
int n;

// Check if it is safe to place a queen at board[row] = col
int isSafe(int row, int col)
{
    int i;
    for(i = 0; i < row; i++)
    {
        if(board[i] == col || abs(board[i] - col) == abs(i - row))
        return 0;
    }

{
    int i, j;
    solutionCount++;
    printf("\nSolution %d:\n", solutionCount);
    for(i = 0; i < n; i++)
    {
        for(j = 0; j < n; j++)
        {
            if(board[i] == j)
            printf("Q ");
            else
            printf(". ");
        }
        printf("\n");
    }
}

{
    if(row == n)

        printSolution();
        return;

            // Backtrack (implicit, next iteration overwrites board[row])
        }
    }

  2. Compare characters one by one — if all of them match, report a match at this position.
  3. If any mismatch occurs, stop comparing and slide the pattern one position forward.
  4. Repeat this until the end of the text is reached.

It is called "naive" because it doesn't use any smart shortcuts (like the KMP or Boyer–Moore algorithms do) — it simply tries every position directly.

Worked Example

  Text: "AABAACAADAABAABA"
  Pattern: "AABA"

  Index 0: text[0..3] = "AABA" → MATCH! (position 0)
  Index 1: text[1..4] = "ABAA" → does not match "AABA"
  Index 2: text[2..5] = "BAAC" → no match
  … (continue checking every position) …
  Index 9: text[9..12] = "AABA" → MATCH! (position 9)
  Index 12: text[12..15] = "AABA" → MATCH! (position 12)

  Result: Pattern "AABA" found at indices 0, 9, and 12.

Time Complexity

Naive String Matching has a worst-case time complexity of O(n × m), where n is the text length and m is the pattern length, since the entire pattern may need to be checked character-by-character at every position. This can be slow for large texts, which is why real-world applications (text editors, search engines) use smarter algorithms (KMP, Boyer–Moore, Rabin–Karp) that avoid repeated comparisons. Even so, the naive method is the easiest to understand and works perfectly fine for small texts.

What the Program Does

  1. The user enters a text string and a pattern string.
  2. The program slides the pattern over every possible position in the text, checking character-by-character (the process above).
  3. Every position where the full pattern matches is printed.
  4. If no match is found anywhere, "Pattern not found" is printed.
  5. The time taken (in seconds) is displayed.

In short: slide the pattern one position at a time over the text, compare character-by-character at each position, and report every position where it fully matches.

Viva questions

What is the Naive String-Matching algorithm?

It slides the pattern over the text one position at a time and checks the pattern character by character at each position.

What is its time complexity?

Worst case O(m × (n - m + 1)), that is O(nm). Best case O(n) when the first character mismatches every time.

When does the worst case happen?

For example text AAAAAAAB and pattern AAAB, where almost all characters match before a mismatch.

Name a faster string matching algorithm.

KMP takes O(n + m). Rabin-Karp uses hashing and Boyer-Moore skips characters.

What are n and m?

n is the length of the text and m is the length of the pattern.

How many shifts are checked?

n - m + 1 positions.

What does the program print for ABABDABACDABABCABAB and ABABCABAB?

Pattern found at index 10 (positions start from 0).

Can the pattern overlap itself in matches?

Yes. The naive method checks every position, so overlapping matches are also found.

Summary of algorithm design strategies

  1. Divide and Conquer: Breaks a problem into independent subproblems, solves them recursively, and combines the results (Quick Sort, Merge Sort, Binary Search, Strassen's).
  2. Greedy Strategy: Makes the locally optimal choice at each step with the hope of finding a global optimum (Fractional Knapsack, Prim's MST, Kruskal's MST).
  3. Dynamic Programming: Solves overlapping subproblems by storing their solutions in a table (memoization / tabulation) to avoid redundant computation (0/1 Knapsack, LCS, MCM).
  4. Backtracking: Builds candidates incrementally and abandons ("backtracks") a candidate as soon as it determines it cannot possibly lead to a valid solution (N-Queens).
  5. Brute Force: Exhaustively tries all possibilities without heuristic optimization (Bubble Sort, Linear Search, Naive String Matching).
