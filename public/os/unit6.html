6.1 UNIX — Introduction High ⭐⭐⭐⭐

English

UNIX is a multiuser, multitasking operating system originally developed at Bell Labs (AT&T) by Ken Thompson and Dennis Ritchie (1969). It follows the philosophy "everything is a file" and provides a hierarchical file system, layered architecture, and a rich set of small, composable utility programs. Rewritten in C in 1973 (making it portable).

Hinglish

UNIX ek aisa OS hai jisme ek hi time pe multiple users kaam kar sakte hain (multiuser) aur ek user multiple programs chala sakta hai (multitasking). Iska core idea hai ki "sab kuch file hai" — chahe wo hardware device ho ya directory, sab ko file jaisa treat kiya jata hai. Linux is UNIX ka hi inspired open-source version hai.

UNIX File System (inode structure)

UNIX uses an inode-based hierarchical file system. Each file has an inode (index node) containing metadata (size, permissions, timestamps, pointers to data blocks). The directory maps file names to inode numbers.

  • Root directory (/) — top of directory tree
  • Key directories: /bin (executables), /etc (config files), /home (user dirs), /dev (device files), /var (variable data), /tmp (temporary)
  • Everything is a file — devices (/dev/sda), pipes, sockets treated as files

UNIX Process Management

ConceptDescription
fork()Creates a copy of the calling process (child process). Child gets copy of parent's address space.
exec()Replaces current process image with a new program. Used after fork() to run a different program.
wait()Parent waits for child to finish. Prevents zombie processes from accumulating.
Zombie ProcessChild has finished but parent hasn't called wait() — entry still in process table.
Orphan ProcessParent has terminated but child still running — adopted by init process (PID 1).

6.2 Linux — Introduction & Architecture High ⭐⭐⭐⭐⭐ — guaranteed every year

English

Linux is a free, open-source, UNIX-like monolithic kernel created by Linus Torvalds in 1991, distributed as complete operating systems called distributions (Ubuntu, Fedora, Debian, etc.) that bundle the kernel with GNU utilities and a package manager.

Hinglish

Linux khud ek poora OS nahi hai — yeh sirf "kernel" hai. Jab is kernel ko GNU tools, shell, aur package manager ke saath bundle kiya jata hai, tab wo ek "distribution" (distro) banta hai — jaise Ubuntu ya Fedora. Linux UNIX se inspired hai isliye dono ke commands similar lagte hain, lekin Linux ka source code free hai.

Shell & Kernel Relationship Medium

English

The Shell is a command-line interpreter program that takes user commands, parses them, and requests the kernel to execute them — it is a user program, not part of the kernel itself. Common shells: sh, bash, csh, zsh.

Hinglish

Shell = translator between user aur kernel. Tum type karte ho ls -la, shell isko parse karki kernel ko bolta hai — "ye command execute karo." Kernel actual kaam karta hai, shell sirf interpreter hai. Multiple shells ek hi kernel ke upar chal sakti hain.

Shell Script Example (Bash)
#!/bin/bash echo "Enter your name:" read name if [ "$name" == "admin" ]; then echo "Welcome, Admin!" else echo "Hello, $name" fi

6.3 Real-Time Operating System (RTOS) High ⭐⭐⭐⭐ — define + types = 5-7 marks

English

A Real-Time Operating System (RTOS) is an OS designed to process data and respond to inputs within a strict, predictable time constraint (deadline). Correctness depends not just on logical output but on meeting the deadline.

Hinglish

RTOS ka sabse important point yeh hai — yahan "fast hona" kaafi nahi hai, "time pe hona" zaroori hai. Agar ek airbag system ko 50ms mein deploy hona chahiye aur wo 60ms mein deploy hota hai, to result galat maana jaayega chahe output correct kyun na ho. Normal OS (jaise Windows) mein deadline miss hone se sirf lag hota hai, RTOS mein deadline miss = system failure.

Hard vs Soft Real-Time Systems High — must diff

AspectHard Real-TimeSoft Real-Time
Deadline miss consequenceCatastrophic / system failureDegraded quality, but tolerable
Jitter toleranceAlmost zeroSome tolerance allowed
ExamplesAirbags, pacemakers, missile guidance, ABS brakesVideo streaming, audio playback, online gaming
SchedulingRate Monotonic, EDF (Earliest Deadline First)Priority-based, soft guarantees
OS neededDedicated RTOS (VxWorks, FreeRTOS, QNX)General OS with real-time extensions (Linux PREEMPT_RT)

RTOS Key Features

  • Determinism — Response time is predictable and bounded.
  • Low Latency — Interrupt handling is extremely fast (microseconds).
  • Priority Scheduling — Highest priority task always runs first.
  • Priority Inversion — Low-priority task blocking high-priority task (solved by priority inheritance).
  • Small footprint — Designed for embedded systems with limited RAM (FreeRTOS runs in <10KB RAM).

English

Mobile OS are operating systems specifically designed for mobile devices (smartphones, tablets). They are optimized for touch input, battery life, wireless connectivity, and application sandboxing. Key examples: Android (Google, Linux-based) and iOS (Apple, BSD/XNU-based).

❓ Unit 6 — Q&A (RTU Exam Pattern)

RTU EXAM Q&A
Q1. Define UNIX. Explain its architecture and key features. ★★★★ 7 Marks
7 Marks

UNIX = multiuser, multitasking OS developed at Bell Labs (1969) by Thompson & Ritchie, rewritten in C in 1973. Philosophy: "everything is a file." Architecture (4 layers): Hardware → UNIX Kernel (process/memory/file/device mgmt) → System Call Interface → Shell/Utilities → User Applications. Key features: hierarchical file system, multiprogramming, portability (C-based), pipes & filters, multiuser.

RTU EXAM Q&A
Q2. Differentiate between UNIX and Linux. ★★★★★ 5 Marks — asked almost every year
5 Marks

Key differences: UNIX = proprietary, costly, AT&T Bell Labs (1969), limited portability, vendor-specific (Solaris, AIX). Linux = open-source (GPL), free, Linus Torvalds (1991), highly portable (PCs, servers, phones), monolithic modular kernel, distributions (Ubuntu, Fedora, Android). One-liner: "Linux is a UNIX-like, open-source kernel; UNIX is the original proprietary family." Full table above.

RTU EXAM Q&A
Q3. Define RTOS. Explain Hard and Soft Real-Time systems with examples. ★★★★★ 7 Marks — asked almost every year
7 Marks

RTOS = OS where correctness depends on meeting strict time deadlines. Hard Real-Time = deadline miss = catastrophic failure (airbag must deploy in 50ms; pacemaker must fire in 0.5ms). Soft Real-Time = deadline miss = degraded quality but tolerable (video streaming can drop frames; game may lag). RTOS features: determinism, low interrupt latency, priority scheduling, small footprint. Examples: VxWorks, FreeRTOS, QNX (hard); Linux with PREEMPT_RT (soft). Full table above.

RTU EXAM Q&A
Q4. Explain Android architecture with diagram. ★★★★ 7 Marks
7 Marks

Android = 5-layer stack. Layer 1 (bottom): Linux Kernel — device drivers, memory mgmt, power mgmt, security (SELinux). Layer 2: Native Libraries (SQLite, OpenGL, WebKit) + Android Runtime (ART — compiles app bytecode to native). Layer 3: Application Framework (Activity Manager, Content Providers, Resource Manager, Location Manager). Layer 4 (top): Applications (Gmail, Chrome, WhatsApp). Uses Linux kernel but is NOT standard Linux — adds Binder IPC, Android-specific drivers, ART runtime. Diagram (Fig 6.3) above.

RTU EXAM Q&A
Q5. What are the differences between Android and iOS? ★★★★ 5 Marks
5 Marks

Android = Google, open-source (AOSP), Linux kernel, Java/Kotlin apps, Play Store + side-loading, very customizable, ~72% market share. iOS = Apple, closed-source, XNU (BSD+Mach) kernel, Swift/Obj-C apps, App Store only, highly restricted, ~27% market share. Android = open ecosystem, iOS = security + privacy focused. Full comparison table above.

RTU EXAM Q&A
Q6. Explain UNIX process management: fork(), exec(), zombie and orphan processes. ★★★★ 5-7 Marks
5 Marks

fork() = creates child process (copy of parent). exec() = replaces current process with a new program (used after fork to run a different binary). wait() = parent waits for child completion. Zombie process = child finished but parent hasn't called wait() — stays in process table. Orphan process = parent terminated, child still running — adopted by init (PID 1). All UNIX process creation uses fork-exec pattern.

RTU EXAM Q&A
Q7. Explain Linux kernel architecture. What is a kernel module? ★★★ 5 Marks
5 Marks

Linux kernel is monolithic but modular. Monolithic = all core functions run in one address space (kernel space). Modular = features can be added/removed at runtime via Loadable Kernel Modules (LKMs, e.g. device drivers — modprobe / insmod). Key subsystems: Process Scheduler (CFS — Completely Fair Scheduler), Memory Manager, VFS (Virtual File System — abstracts ext4, NTFS under one interface), Network Stack, Device Drivers. Commands: lsmod (list modules), modprobe wifi_driver (load driver).
