Experiment 14: Polygon fill algorithm (scan-line)

Aim: To implement the polygon fill algorithm.

Source code

#include<stdio.h>
#include<conio.h>
#include<stdlib.h>
#include<graphics.h>

void main()
{
    int gd = DETECT, gm, err;
    int n, i, j, k, y, ymin, ymax, cnt, x1, y1, x2, y2, col, tmp;
    int px[10], py[10];
    float xi[10], t;

    clrscr();
    printf("Enter number of vertices (3 to 10): ");
    scanf("%d", &n);
    if(n < 3 || n > 10)
    {
        printf("Number of vertices must be 3 to 10");
        getch();
        exit(0);
    }
    printf("Enter the vertices (x y), one per line, in order:\n");
    for(i = 0; i < n; i++)
        scanf("%d%d", &px[i], &py[i]);
    printf("Enter fill colour (1 to 14): ");
    scanf("%d", &col);

    ymin = py[0];
    ymax = py[0];
    for(i = 1; i < n; i++)
    {
        if(py[i] < ymin) ymin = py[i];
        if(py[i] > ymax) ymax = py[i];
    }

    initgraph(&gd, &gm, "C:\\TURBOC3\\BGI");
    err = graphresult();
    if(err != grOk)
    {
        printf("Graphics error: %s", grapherrormsg(err));
        getch();
        exit(1);
    }

    setcolor(col);
    for(y = ymin; y <= ymax; y++)
    {
        cnt = 0;
        for(i = 0; i < n; i++)
        {
            j = (i + 1) % n;
            x1 = px[i]; y1 = py[i];
            x2 = px[j]; y2 = py[j];
            if(y1 == y2)
                continue;
            if(y1 > y2)
            {
                tmp = x1; x1 = x2; x2 = tmp;
                tmp = y1; y1 = y2; y2 = tmp;
            }
            if(y >= y1 && y < y2)
            {
                xi[cnt] = x1 + (float)(y - y1) * (x2 - x1) / (y2 - y1);
                cnt++;
            }
        }

        for(i = 0; i < cnt - 1; i++)
            for(k = 0; k < cnt - 1 - i; k++)
                if(xi[k] > xi[k + 1])
                {
                    t = xi[k];
                    xi[k] = xi[k + 1];
                    xi[k + 1] = t;
                }

        for(k = 0; k + 1 < cnt; k += 2)
            line((int)(xi[k] + 0.5), y, (int)(xi[k + 1] + 0.5), y);
    }

    setcolor(WHITE);
    for(i = 0; i < n; i++)
    {
        j = (i + 1) % n;
        line(px[i], py[i], px[j], py[j]);
    }

    getch();
    closegraph();
}

The manual’s program draws a fixed polygon with drawpoly and fills it with a short loop that works only for that one shape. Its viva questions are about polygon clipping, not filling. This version takes any polygon, fills it with the scan-line method, and adds fill-related questions (the clipping questions are kept at the end).

Before you run

These programs open a graphics screen, so they need the Turbo C++ BGI driver files. Two things to check once:

  1. BGI path: the code uses "C:\\TURBOC3\\BGI" (double backslashes are required in C). It must match the BGI folder of your Turbo C++ install, which holds files such as EGAVGA.BGI. If the program prints "Graphics error", correct this path.
  2. Graphics library: in Turbo C++ choose Options > Linker > Libraries and tick Graphics library. Without it you get "undefined symbol _initgraph" when linking.
  3. File type: save the file with the .C extension (for example EXP4.C) so Turbo C++ compiles it as a C program.

Explanation

  1. Idea (scan-line fill): go through the polygon one horizontal line (scan line) at a time. On each line, find where it crosses the polygon edges, sort the crossings from left to right, and fill between the 1st and 2nd, the 3rd and 4th, and so on. The pixels between crossing 2 and crossing 3 are outside the polygon, so they are left empty.
  2. Finding the crossings: for every edge from (x1, y1) to (x2, y2) with y1 less than y2, the scan line y crosses it when y1 <= y < y2, at x = x1 + (y - y1)(x2 - x1)/(y2 - y1). Horizontal edges are skipped.
  3. Why y < y2 and not y <= y2: a vertex shared by two edges must be counted once, not twice, or the pairs would be mixed up. Counting only the lower end of each edge does this. The outline is drawn afterwards, so the bottom row is still covered.
  4. Example: for the polygon (100,100), (150,150), (200,100), (200,200), (100,200) at y = 120 the crossings are x = 100, 120, 180 and 200. The program fills 100 to 120 and 180 to 200, and leaves 120 to 180 empty because that is the notch.
  5. Each filled span is a horizontal line() in the chosen colour. After all the scan lines, the outline is drawn in white.
  6. Each of the (at most 10) edges gives at most one crossing per scan line, so xi[10] is big enough. A small bubble sort puts the crossings in order.

Viva questions

What is polygon filling?

Colouring all the pixels inside a polygon. The two main methods are scan-line fill and seed fill (flood fill and boundary fill).

Explain the scan-line polygon fill algorithm.

For each scan line from the lowest to the highest y of the polygon, find the intersections with the edges, sort them by x, and draw lines between pairs of intersections.

What is the even-odd rule?

A point is inside the polygon if a line from it crosses an odd number of edges. In scan-line fill this means filling between the 1st and 2nd crossing, then the 3rd and 4th, and so on.

How are vertices handled?

By counting an edge only for y1 <= y < y2, so a vertex shared by two edges is counted once and horizontal edges are ignored. Otherwise the crossings would not pair up correctly.

Does it work for concave polygons?

Yes. The even-odd pairing leaves the notches empty. Seed fill methods may need more care for such shapes.

What are the edge table and active edge table?

An edge table lists the edges sorted by their lowest y. The active edge table holds only the edges crossed by the current scan line. They make the method faster for large polygons. This program simply tests all edges for each line.

What is scan-line coherence?

The idea that neighbouring scan lines cross almost the same edges, with the crossing x changing by a constant 1/slope, so results can be updated instead of recalculated.

Difference between scan-line fill and seed fill?

Scan-line fill uses the polygon’s edges and needs no starting point. Seed fill starts at a point inside and spreads to neighbouring pixels until it reaches a boundary.

Which clipping algorithm is used for polygon clipping? (from the manual)

The Sutherland-Hodgman algorithm. It clips the polygon against one window edge at a time.

How do you clip a polygon? (from the manual)

Take each edge of the window in turn, keep the polygon vertices on the inside, and add the intersection points where polygon edges cross that window edge. The output polygon of one step is the input of the next.

What is the primary use of clipping in computer graphics? (from the manual)

To remove the parts of objects that lie outside the viewing window so they are not drawn.
