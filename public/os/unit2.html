1. Introduction to Operating System High ⭐⭐⭐

English

An Operating System is a control program that manages the execution of user programs, operates computer hardware, and acts as a resource manager (allocating CPU, memory, I/O devices among competing processes) and an extended/virtual machine (hiding hardware complexity behind a simple interface).

Hinglish

OS do roles play karta hai: (1) Resource Manager — CPU time, memory, disk space jaise limited resources ko fairly aur efficiently allocate karta hai multiple programs ke beech. (2) Extended Machine — hardware ki complexity (registers, interrupts, disk sectors) ko chhupa ke simple commands/APIs deta hai (jaise file ko "save" karna — tumhe disk sector ka pata nahi karna padta).

Functions / Goals of OS Medium

  • Process Management — creation, scheduling, termination of processes.
  • Memory Management — allocation/deallocation of memory to processes.
  • File Management — creation, deletion, organization of files & directories.
  • Device Management — managing I/O devices via drivers.
  • Security & Protection — controlling access to resources, user authentication.
  • User Interface — CLI (Command Line Interface) or GUI (Graphical User Interface).

2. History & Evolution of Operating Systems Medium ⭐⭐⭐

English

Operating systems evolved through several generations, each driven by hardware advances and the need for better resource utilization and user convenience.

GenerationKey FeatureExample/Era
1. Serial ProcessingNo OS; manual operation, one job at a time, plugboards1940s vacuum-tube machines
2. Batch SystemsJobs collected & processed in batches; reduces idle CPU time vs manual1950s-60s (punch cards)
3. Multiprogrammed BatchMultiple jobs kept in memory; CPU switches between jobs when one waits for I/O1960s
4. Time-Sharing SystemsCPU time divided into time-slices; multiple interactive users feel they have dedicated CPU1970s (CTSS, Multics, UNIX)
5. Personal Computer OSSingle-user, GUI-based, designed for ease of use1980s (MS-DOS, early Mac OS)
6. Distributed/Network OSMultiple computers connected, resource sharing over network1990s onward
7. Modern/Mobile OSMulti-core support, virtualization, touch-based mobile OS2000s-present (Linux, Windows, Android, iOS)
Hinglish

Simple memory trick: Serial → Batch → Multiprogrammed → Time-sharing → PC → Distributed → Modern. Har step pe goal yahi tha — CPU ka idle time kam karo aur users ko better experience do. Time-sharing sabse important hai exam ke liye — isi se modern multitasking OS ka concept aaya.

3. Structure & Operations of OS High ⭐⭐⭐⭐

Dual-Mode Operation High

English

Modern OS run in two modes to protect system resources: User Mode (restricted, application programs run here, cannot directly access hardware) and Kernel Mode (privileged, OS core runs here, full hardware access). A mode bit in hardware indicates the current mode; switching happens via system calls or interrupts.

Hinglish

User mode mein apps "limited power" ke saath chalte hain (security ke liye) — agar koi app crash ho bhi jaaye, to poora system crash nahi hota. Jab app ko hardware access chahiye (file read/write, etc.), to system call ke through kernel mode mein switch hota hai temporarily.

OS Structures Medium ⭐⭐⭐

4. Processes and Files High ⭐⭐⭐⭐

English

A Process is a program in execution — it includes the program code, current activity (program counter, registers), stack, and a data section. Each process is represented in the OS by a Process Control Block (PCB) containing all information needed to manage it.

Hinglish

Process = "running" program. Jab tak program disk pe hai (jaise .exe file), wo passive hai. Jaise hi run hota hai, OS use memory mein laata hai, resources deta hai, aur ek "process" ban jaata hai jiske paas khud ka state (registers, stack, program counter) hota hai.

Process States High — diagram-based question

Fig 2.2 — Process State Diagram: New → Ready → Running → (Waiting ⇄ Ready) → Terminated

Process Control Block (PCB) Fields Medium

  • Process ID (PID), Process State
  • Program Counter, CPU Registers
  • CPU Scheduling Information (priority, queue pointers)
  • Memory Management Information (base/limit registers, page tables)
  • Accounting Information (CPU used, time limits)
  • I/O Status Information (allocated devices, open file list)

5. Inter-Process Communication (IPC) High ⭐⭐⭐

English

Inter-Process Communication refers to mechanisms that allow processes to exchange data and synchronize their actions, mainly via two models: Shared Memory (processes share a region of memory and read/write directly) and Message Passing (processes exchange messages via the OS, using send()/receive()).

Hinglish

Shared memory mein dono process ek common memory area use karte hain (fast, but synchronization khud karna padta hai). Message passing mein OS ke through messages bheje jaate hain (slower but safer) — jaise do logon ke beech letter bhejna (message passing) vs ek common notice-board use karna (shared memory).

AspectShared MemoryMessage Passing
SpeedFaster (direct memory access)Slower (via OS kernel calls)
SynchronizationMust be handled by programmerHandled implicitly by OS
Best forLarge data transfer, same machineDistributed systems, small messages
ExamplePOSIX shared memory segmentsPipes, sockets, message queues

6. Critical Section Problem High ⭐⭐⭐⭐⭐

English

A Critical Section is a segment of code where a process accesses shared resources (variables, files, data structures) that must not be concurrently accessed by more than one process. A valid solution must satisfy:

  1. Mutual Exclusion: Only one process may execute in its critical section at a time.
  2. Progress: If no process is in its critical section, one of the waiting processes must be allowed to enter without indefinite delay.
  3. Bounded Waiting: There must be a limit on the number of times other processes are allowed to enter their critical section before a waiting process's request is granted.
Hinglish

Critical section = wo code jahan shared data ko modify kiya jaata hai. Agar 2 processes ek saath isi section mein chale jaayen (bina coordination ke), to data corrupt ho sakta hai ("race condition"). Teeno conditions (mutual exclusion, progress, bounded waiting) ek "fair aur safe" solution define karti hain.

7. Mutual Exclusion High ⭐⭐⭐

English

Mutual Exclusion is a property ensuring that when one process is executing in its critical section, no other process is allowed to execute in its own critical section, thereby preventing race conditions on shared data.

Hinglish

Mutual exclusion ka matlab — ek time pe sirf ek hi process shared resource use kar sake, baaki sab "wait" karein. Ye lock/key jaisa concept hai — jab tak ek process "key" hold kar rahi hai, doosri process andar nahi jaa sakti.

8. Semaphores, Wait & Signal Procedures High ⭐⭐⭐⭐⭐ — guaranteed

English

A Semaphore is an integer synchronization variable accessed only via two atomic operations: wait() (P) and signal() (V). A Binary Semaphore takes values 0 or 1 (used for mutual exclusion). A Counting Semaphore can take any non-negative integer value (used to control access to a resource pool with multiple instances).

wait(S): signal(S): while (S <= 0) S = S + 1; ; // busy wait S = S - 1;
Hinglish

Semaphore ek "counter" hai. wait() / P() = resource use karne se pehle counter ghatao (agar counter 0 hai, to process wait karegi). signal() / V() = resource use karne ke baad counter badhao. Binary semaphore = simple lock (0/1). Counting semaphore = jaise parking lot mein "kitni spots khaali hain" track karna.

Producer-Consumer Problem using Semaphores High ⭐⭐⭐⭐⭐ — classic RTU question

Example

Producer adds items to a shared buffer of size n; Consumer removes items. Using semaphores empty (counting, init=n), full (counting, init=0), and mutex (binary, init=1):

Producer: Consumer: do { do { wait(empty); wait(full); wait(mutex); wait(mutex); // add item to buffer // remove item from buffer signal(mutex); signal(mutex); signal(full); signal(empty); } while(true); } while(true);

empty tracks free slots, full tracks filled slots, mutex ensures only one process touches the buffer at a time.

9. Process Scheduling & Algorithms High ⭐⭐⭐⭐⭐ — Numerical guaranteed

English

Process Scheduling is the OS activity of selecting which process runs on the CPU at a given time, aiming to maximize CPU utilization and throughput while minimizing waiting time, response time, and turnaround time.

AlgorithmTypeKey Idea
FCFS (First Come First Serve)Non-preemptiveProcess executed in arrival order
SJF (Shortest Job First)Preemptive or Non-preemptiveProcess with shortest burst time runs first
Priority SchedulingPreemptive or Non-preemptiveHighest priority process runs first
Round Robin (RR)PreemptiveEach process gets a fixed time quantum in cyclic order

10. Threads & Multithreading High ⭐⭐⭐⭐

English

A Thread is the basic unit of CPU utilization — a lightweight process with its own program counter, register set, and stack, but sharing code, data, and resources (memory, files) with other threads of the same process. Multithreading is the ability of an OS to support multiple threads of execution within a single process.

Hinglish

Thread = process ke andar ek "lightweight sub-task". Jaise ek browser process mein alag-alag threads chal rahe hote hain — ek tab loading kar raha, doosra video play kar raha, teesra download kar raha — sab same process ke andar, memory share karte hue, lekin independently execute hote hain.

AspectProcessThread
MemorySeparate address spaceShares address space with parent process
Creation overheadHigh (heavyweight)Low (lightweight)
CommunicationNeeds IPC (slow)Direct (shared memory, fast)
Crash impactDoesn't affect other processesCan affect other threads in same process

Many-to-One

Many user-level threads mapped to one kernel thread. Fast thread management, but only one thread can access kernel at a time (no true parallelism).

One-to-One

Each user thread maps to a kernel thread. Allows true parallelism, but creating a user thread requires creating a kernel thread (overhead).

Many-to-Many

Many user threads multiplexed onto a smaller/equal number of kernel threads. Best of both — flexibility + parallelism.

Benefits of Multithreading

Responsiveness, resource sharing, economy (cheaper than processes), scalability on multi-core systems.
