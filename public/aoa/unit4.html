4.1 Branch and Bound — Concept FOUNDATION

📖 Definition

Branch and Bound (B&B) is a systematic search technique for solving optimization problems by exploring the solution space as a tree of partial solutions (branching), computing a bound on the best possible solution achievable from each node, and pruning any branch whose bound cannot beat the best solution found so far.

🗣️ Hinglish Explanation

Branch and Bound bhi backtracking jaisa hi exploration karta hai, lekin yeh sirf optimization problems (minimum/maximum dhoondhne wale) ke liye use hota hai. Har node par ek "bound" (estimate) calculate karte hain ki is path se aage jaake best kitna achha solution mil sakta hai. Agar yeh bound already mile hue best solution se kharab hai, toh us poori branch ko explore hi nahi karte (prune kar dete hain) — isse bahut computation bach jaata hai.

Branch and Bound vs Plain Backtracking

  • 🎯 Purpose: B&B is used for optimization problems (minimize cost / maximize profit); Backtracking is used for decision/feasibility problems (find any/all valid solutions).
  • ✂️ Pruning basis: B&B prunes using a numeric bound comparison; Backtracking prunes using a feasibility/constraint check.
  • 🔍 Search order: B&B commonly explores the most promising node first (Least Cost / Best-First search) rather than strict depth-first order.

4.2 Traveling Salesman Problem — Branch & Bound EXAM HOT — 10 MARK

📖 Definition

The Traveling Salesman Problem (TSP) requires finding the minimum-cost Hamiltonian cycle that visits every city exactly once and returns to the starting city, given a cost matrix between all pairs of cities; the Branch & Bound approach solves it by building partial tours and pruning branches whose lower-bound cost exceeds the best complete tour found so far.

🗣️ Hinglish

TSP mein ek salesman ko saare cities ek baar visit karke wapas start city aana hota hai, minimum total cost mein. Yeh NP-Hard problem hai, isliye brute-force mein (n-1)! routes check karne padte (bahut slow). B&B is state-space tree banata hai jisme har node ek partial tour represent karta hai, aur har node ka lower bound nikal kar un branches ko discard karte hain jo best-known tour se kabhi behtar nahi ho sakti.

B&B Approach for TSP

1. Compute initial lower bound for the root (sum of 2 minimum edges from each city / 2, rounded up) 2. Build a state-space tree: each node = partial tour (subset of edges fixed) 3. For each child node, compute its reduced-cost lower bound 4. Use a priority queue (least-bound-first) to expand the most promising node 5. Prune (discard) any node whose bound >= current best complete tour cost 6. Update "best tour" whenever a cheaper complete tour is found 7. Continue until all live nodes are pruned or expanded
💡 Example

For a 4-city TSP with a given cost matrix, the root lower bound is computed by summing, for every city, its two smallest outgoing edge costs and halving the total. As the tree branches on "include edge (i,j)" vs "exclude edge (i,j)" decisions, nodes with a bound worse than the current best complete tour are pruned, and the search continues until the cheapest complete Hamiltonian cycle is confirmed as optimal.

4.3 Lower Bound Theory 5-MARK

📖 Definition

Lower Bound Theory provides a mathematically guaranteed minimum cost (a value that the true optimal solution can never be cheaper than) for a partial or complete solution in a Branch & Bound search, allowing the algorithm to safely prune any branch whose lower bound is already worse than the best solution found so far.

🗣️ Hinglish

Lower bound ek "optimistic estimate" hota hai — yeh guarantee karta hai ki is node se aage chal kar bhi cost is value se kam kabhi nahi ho sakti. Agar yeh estimate khud hi current best solution se zyada hai, toh us node ko explore karne ka koi fayda nahi — usse prune kar dete hain. Better (tighter) lower bound ka matlab hai zyada branches prune hongi, aur algorithm fast chalega.

Computing a Lower Bound (TSP example)

For each city i, find its two smallest-cost outgoing edges. Lower Bound = ( Σ (sum of 2 smallest edges for each city) ) / 2 [rounded up]

As edges are fixed/excluded while branching, the bound is incrementally tightened (recomputed) for each child node, always remaining a valid (never-overestimating) bound on the true minimum cost achievable from that node.

📌 Why lower bounds matter: A tighter (higher, closer to the true optimum) lower bound prunes more branches and makes Branch & Bound far faster than exhaustive search, while still guaranteeing the optimal solution is never missed.

4.4 Backtracking Algorithms — Concept EXAM HOT

📖 Definition

Backtracking is a systematic trial-and-error technique that builds a solution incrementally, one component at a time, and abandons ("backtracks" from) a partial solution as soon as it determines that the partial solution cannot possibly be extended to a valid complete solution, then tries the next alternative.

🗣️ Hinglish

Backtracking ek tarah ka organized "trial and error" hai. Hum solution ko step-by-step build karte hain, aur har step par check karte hain ki abhi tak ka partial solution valid hai ya nahi (constraint check). Agar invalid ho jaata hai, toh hum waapas (backtrack) jaate hain pichle step par aur dusra option try karte hain — isse pure search tree explore nahi karna padta, sirf promising paths hi explore hote hain.

General Backtracking Algorithm

Backtrack(partial_solution): if partial_solution is a complete valid solution: record/output it; return for each candidate choice c (extending partial_solution): if c satisfies the constraints (is "safe"): add c to partial_solution Backtrack(partial_solution) // recurse remove c from partial_solution // BACKTRACK (undo choice)

4.5 N-Queens Problem (Backtracking) MOST IMPORTANT — 10 MARK

📖 Definition

The N-Queens Problem requires placing N queens on an N×N chessboard such that no two queens attack each other — i.e., no two queens share the same row, column, or diagonal — solved using backtracking by placing queens one column (or row) at a time and backtracking whenever a placement leads to a conflict.

🗣️ Hinglish

N-Queens mein N queens ko N×N board par is tarah rakhna hota hai ki koi bhi do queens ek dusre ko attack na kar sakein (same row, column, ya diagonal mein na hों). Backtracking approach: ek-ek karke har row mein queen place karte jaao (column choose karke), agar current placement safe hai toh aage badho, nahi toh backtrack karke dusra column try karo.

Algorithm

NQueens(board, row, n): if row == n: print/record solution; return true (if only one solution needed) for col = 0 to n-1: if isSafe(board, row, col): place queen at (row, col) if NQueens(board, row+1, n): return true remove queen at (row, col) // backtrack return false isSafe(board, row, col): Check column above is free, and both upper-left and upper-right diagonals are free of any previously placed queen
A valid 4-Queens solution — no two queens share a row, column, or diagonal
💡 Example: 4-Queens Backtracking Trace

Placing queens row by row: Q1 at (0,0) → Q2 cannot be at (1,0) or (1,1) (column/diagonal conflict) → try (1,2) → Q3 has no safe column in row 2 → backtrack to Q2, try (1,3) → Q3 at (2,1) → Q4 has no safe column → backtrack further... eventually the algorithm finds the valid solution (0,1),(1,3),(2,0),(3,2) shown above, after multiple backtracks.

📌 Complexity: The N-Queens backtracking search has a worst-case time complexity of O(N!) since up to N choices are tried per row across N rows, but pruning unsafe placements early makes it far faster in practice than checking all N^N raw placements.

4.6 Pattern Matching Algorithms — Overview FOUNDATION

📖 Definition

String/Pattern Matching is the problem of finding all occurrences of a given pattern string P (length m) within a larger text string T (length n). Different algorithms (Naïve, Rabin-Karp, KMP, Boyer-Moore) trade off pre-processing time, average-case speed, and worst-case guarantees.

🗣️ Hinglish

Pattern matching ka kaam hai ek badi text string mein ek chhoti pattern string ko dhoondhna — jaise Ctrl+F search. Sabse simple tareeka (Naïve) har possible position par character-by-character match check karta hai, jo slow hai. Smarter algorithms (Rabin-Karp hashing use karta hai, KMP pattern ke andar ke repeated prefixes ka use karta hai, Boyer-Moore text ko right-to-left scan karke bade jumps leta hai) bahut fast hote hain.

4.7 Naïve String Matching Algorithm 5-MARK

📖 Definition

The Naïve (Brute-Force) String Matching algorithm checks for the pattern at every possible starting position in the text by comparing characters one by one, sliding the pattern forward by exactly one position after each attempt (successful or not).

🗣️ Hinglish

Naïve method sabse simple hai — har position s (0 se n-m tak) par pattern ko text ke saath character-by-character compare karte hain. Match na hone par bhi sirf 1 position aage shift karte hain. Simple hai but bahut slow ho sakta hai worst case mein (jaise text = "aaaa...a", pattern = "aaa...b").

Algorithm

NaiveSearch(T, P): // n = len(T), m = len(P) for s = 0 to n-m: if T[s..s+m-1] == P[0..m-1]: print "Pattern found at shift s"

Complexity

CaseTime Complexity
Best CaseO(n) (mismatches found quickly at each shift)
Worst CaseO((n−m+1)·m) ≈ O(nm) (e.g., text and pattern of repeated characters)

4.8 Rabin-Karp Algorithm EXAM HOT — NUMERICAL

📖 Definition

The Rabin-Karp Algorithm uses a hash function to compute a numeric fingerprint of the pattern and of each text window of the same length; it compares hash values first, and only performs a full character-by-character comparison when hash values match, using a rolling hash to update each window's hash in O(1) time.

🗣️ Hinglish

Rabin-Karp pattern aur text ke har window ka ek hash value (number) calculate karta hai. Agar dono ke hash match karte hain tabhi actual characters compare karte hain (kyunki different strings ka hash kabhi-kabhi accidentally same ho sakta hai — "spurious hit"). Rolling hash ka use karke next window ka hash purane hash se O(1) mein nikal liya jaata hai (poora dobara calculate nahi karna padta) — isse yeh average case mein bahut fast ho jaata hai, especially multiple pattern search mein.

Rolling Hash Formula

hash(s) = ( T[s]·d^(m-1) + T[s+1]·d^(m-2) + ... + T[s+m-1] ) mod q Rolling update: hash(s+1) = ( d·( hash(s) − T[s]·d^(m-1) ) + T[s+m] ) mod q where d = number of characters in alphabet (e.g., 256), q = a large prime

Algorithm

RabinKarp(T, P, d, q): compute hash(P) and hash(T[0..m-1]) for s = 0 to n-m: if hash(T window) == hash(P): verify by direct character comparison (avoid false positive) if match: print "Pattern found at shift s" if s < n-m: roll the hash to next window in O(1)
💡 Example

Searching pattern "26" in text "31415926..." with d=10, q=11: hash("26")=26 mod 11=4. Each text window's hash is similarly computed and rolled forward; whenever a window's hash equals 4, a direct character check confirms whether it's a true match or a rare spurious hash collision.

Complexity

CaseTime Complexity
Average CaseO(n+m)
Worst CaseO(nm) (many spurious hash collisions, e.g., poor choice of q)

Particularly efficient for multiple pattern matching problems (plagiarism detection, etc.).

4.9 KMP (Knuth-Morris-Pratt) Matcher MOST IMPORTANT — 10 MARK

📖 Definition

The KMP Algorithm avoids re-examining previously matched text characters by pre-computing a prefix function (failure function) π for the pattern, which records the length of the longest proper prefix of the pattern that is also a suffix at each position, allowing the matcher to skip ahead intelligently after a mismatch instead of restarting from the next text position.

🗣️ Hinglish

KMP ka core idea hai: jab mismatch ho, toh hum text mein wapas pichhe nahi jaate — balki pattern ke andar pehle se match hue hisse ki "self-similarity" (prefix=suffix property) use karke seedha aage badh jaate hain. Iske liye pehle ek failure function (π array) precompute karte hain jo batata hai ki har position tak pattern ka sabse lamba prefix kya hai jo suffix bhi hai. Isse text ko ek baar hi scan karna padta hai — O(n+m) guaranteed, koi worst case slowdown nahi.

Computing the Prefix (Failure) Function π

ComputePrefixFunction(P): // m = len(P) π[0] = 0; k = 0 for q = 1 to m-1: while k > 0 and P[k] != P[q]: k = π[k-1] if P[k] == P[q]: k = k+1 π[q] = k return π
💡 Example: Failure function for P = "ABABCABAB"
i012345678
P[i]ABABCABAB
π[i]001201234

KMP Matching Algorithm

KMPMatcher(T, P): // n = len(T), m = len(P) π = ComputePrefixFunction(P) q = 0 // number of characters matched so far for i = 0 to n-1: while q > 0 and P[q] != T[i]: q = π[q-1] // use failure fn to fall back smartly if P[q] == T[i]: q = q+1 if q == m: // entire pattern matched print "Pattern found ending at index i" q = π[q-1]

Complexity

Pre-processing (prefix function): O(m) Matching phase: O(n) Total: O(n + m) — guaranteed in ALL cases (best, average, worst)

4.10 Boyer-Moore Algorithm EXAM HOT

📖 Definition

The Boyer-Moore Algorithm compares the pattern against the text right-to-left at each alignment, and on a mismatch, uses two pre-computed heuristics — the Bad Character heuristic and the Good Suffix heuristic — to shift the pattern forward by more than one position, often skipping large portions of the text entirely.

🗣️ Hinglish

Boyer-Moore pattern ko text ke saath right-to-left compare karta hai (ulta — pattern ke last character se start karta hai). Jab mismatch hota hai, yeh do smart heuristics use karta hai: Bad Character (jo text character mismatch hua hai, uske basis par pattern ko jitna door tak shift kar sakte hain) aur Good Suffix (jo portion already match ho chuka tha, uska use karke shift decide karna). In dono mein se jo bada shift deta hai, woh use hota hai — isliye practical mein yeh sabse fast algorithm maana jaata hai, especially large alphabets (English text) ke liye.

Bad Character Heuristic

On a mismatch at text character c, shift the pattern so that the last occurrence of c in the pattern (to the left of the mismatch point) aligns with the mismatched text position; if c doesn't occur in the pattern at all, shift the pattern entirely past the mismatch point.

Good Suffix Heuristic

When a mismatch occurs after matching a suffix (the already-matched tail of the pattern), shift the pattern to align the next occurrence of that matched suffix elsewhere in the pattern (or align the widest matching prefix-suffix overlap if no other occurrence exists).

💡 Example

Searching pattern "EXAMPLE" in a text: comparison starts from the pattern's last character 'E' against the aligned text character; on a mismatch, the bad-character rule may allow skipping several positions at once (e.g., jumping past a long stretch where the mismatched character doesn't appear anywhere in the pattern) instead of shifting by just one position as Naïve search would.

Complexity

CaseTime Complexity
Best CaseO(n/m) — sub-linear, large skips possible
Worst CaseO(nm) (rare, mitigated further with good-suffix rule)

In practice, Boyer-Moore is considered the fastest general-purpose string-matching algorithm for large alphabets like English text.

4.12 RTU Exam Questions & Answers (Importance-Wise)

Q1
Explain the Branch and Bound approach to solve the Traveling Salesman Problem, including lower bound calculation. 10 Marks

Branch and Bound solves TSP by building a state-space tree of partial tours, where each node's lower bound is computed by summing the two smallest outgoing edge costs for every city and halving the total, giving an optimistic minimum cost for completing the tour from that node. Using a least-cost-first expansion strategy, the algorithm prunes any node whose bound is no better than the cheapest complete tour found so far, continuing until all live nodes are either expanded into a complete tour or pruned, guaranteeing the optimal Hamiltonian cycle is found without exhaustively checking all (n-1)! routes.

Q2
Write the backtracking algorithm for the N-Queens problem and explain with a 4-Queens example. 10 Marks

The backtracking algorithm places queens row by row, trying each column in turn and checking via isSafe() that no previously placed queen shares the same column or diagonal; if safe, it places the queen and recurses to the next row, and if no column in a row is safe, it backtracks to the previous row and tries the next alternative there. For 4-Queens, after several conflicting attempts and backtracks, the algorithm eventually finds the valid solution placing queens at (0,1),(1,3),(2,0),(3,2), where no two queens attack each other.

Q3
Explain the KMP string matching algorithm. Compute the failure function for the pattern "ABABCABAB" and explain how matching proceeds. 10 Marks

KMP pre-computes a failure function π, where π[q] gives the length of the longest proper prefix of the pattern that is also a suffix ending at position q, allowing the matcher to skip re-comparison of already-matched characters after a mismatch by falling back to π[q-1] instead of restarting. For pattern "ABABCABAB", the computed failure function values are [0,0,1,2,0,1,2,3,4], and during matching, whenever a mismatch occurs after partially matching characters, the algorithm uses this table to resume comparison at the correct offset, giving an overall guaranteed time complexity of O(n+m).

Q4
Explain the Rabin-Karp string matching algorithm with its rolling hash formula. 10 Marks

Rabin-Karp computes a numeric hash for the pattern and for each equal-length window of the text, comparing hash values first and only performing a full character comparison when hashes match (to rule out spurious collisions). The rolling hash formula hash(s+1) = (d·(hash(s) − T[s]·d^(m-1)) + T[s+m]) mod q allows each subsequent window's hash to be computed in O(1) from the previous one, giving an average-case time complexity of O(n+m), though the worst case remains O(nm) if many spurious hash collisions occur.

Q5
Explain the Boyer-Moore string matching algorithm and its bad-character and good-suffix heuristics. 10 Marks

Boyer-Moore compares the pattern against the text from right to left at each alignment; on a mismatch, the bad-character heuristic shifts the pattern so the last occurrence of the mismatched text character in the pattern aligns with that position (or skips past it entirely if the character doesn't appear in the pattern), while the good-suffix heuristic uses the already-matched suffix to find the next valid alignment elsewhere in the pattern. The larger of the two suggested shifts is used at each step, giving Boyer-Moore a best-case sub-linear time of O(n/m) and making it the fastest general-purpose string matcher in practice, despite a rare worst case of O(nm).

Q6
Differentiate between Branch and Bound and Backtracking techniques. 5 Marks

Branch and Bound is used for optimization problems and prunes branches using a numeric lower/upper bound comparison against the current best solution, often expanding the most promising node first. Backtracking is used for decision/feasibility problems and prunes branches purely based on whether a partial solution still satisfies the problem's constraints, typically following a strict depth-first exploration order.

Q7
Explain the Naïve string matching algorithm and derive its worst-case time complexity. 5 Marks

The Naïve algorithm checks the pattern against the text at every possible starting shift (0 to n−m), comparing characters one by one and sliding forward by exactly one position regardless of match success. Its worst case occurs when the text and pattern consist of highly repetitive characters causing almost-full comparisons at every shift, giving a worst-case time complexity of O((n−m+1)·m), commonly approximated as O(nm).

Q8
What is Lower Bound Theory in Branch and Bound? Why is a tighter lower bound preferred? 5 Marks

Lower Bound Theory provides a guaranteed minimum achievable cost from a given partial solution node, ensuring that the true optimal completion of that branch can never cost less than this bound. A tighter (higher) lower bound is preferred because it allows the algorithm to prune more branches whose bound already exceeds the current best solution, reducing the search space and speeding up the overall Branch and Bound process without sacrificing optimality.

Q9
Compare the four string matching algorithms (Naïve, Rabin-Karp, KMP, Boyer-Moore) on the basis of time complexity and use cases. 5 Marks

Naïve matching needs no pre-processing but has a worst case of O(nm); Rabin-Karp adds O(m) hash pre-processing and achieves O(n+m) on average via rolling hashes, suiting multiple-pattern search, though it can degrade to O(nm) with hash collisions. KMP guarantees O(n+m) in every case using its O(m) failure-function pre-processing, making it reliable for worst-case-sensitive applications, while Boyer-Moore, using bad-character and good-suffix heuristics, achieves sub-linear O(n/m) best-case performance and is generally the fastest in practice for large-alphabet text such as English.

Q10
Explain the general backtracking algorithm structure with a flow describing how partial solutions are extended and discarded. 5 Marks

Backtracking builds a solution incrementally by trying each available candidate choice to extend the current partial solution, checking at every step whether the choice keeps the partial solution "safe" (consistent with the problem's constraints). If safe, the choice is added and the algorithm recurses to extend it further; if a complete valid solution is reached it is recorded, and whenever no candidate choice remains safe at a given step, the algorithm backtracks by undoing the most recent choice and trying the next alternative at the previous level.
