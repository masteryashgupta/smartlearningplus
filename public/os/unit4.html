1. Deadlock — Introduction High ⭐⭐⭐⭐⭐

English

A Deadlock is a situation where a set of processes are blocked, each holding some resources and waiting to acquire resources held by other processes in the set — resulting in a circular wait with no process able to proceed.

Hinglish

Deadlock ek aisi situation hai jahan sab processes ek doosre ka wait kar rahi hoti hain aur koi bhi aage nahi badh sakti. Jaise do gaadiyaan ek single-lane bridge ke dono siro pe khadi hain — dono doosre ko pehle hatne ka wait kar rahi hain, koi nahi hata!

Coffman's 4 Necessary Conditions for Deadlock High — must memorize

  1. Mutual Exclusion: At least one resource must be held in a non-sharable mode.
  2. Hold and Wait: A process is holding at least one resource and waiting to acquire additional resources held by other processes.
  3. No Preemption: Resources cannot be forcibly taken from a process; they must be released voluntarily.
  4. Circular Wait: There exists a circular chain of processes P1→P2→...→Pn→P1 such that each is waiting for a resource held by the next.
Hinglish

Memory trick for 4 conditions: M-H-N-C → Mutual exclusion, Hold and wait, No preemption, Circular wait. Inme se koi ek condition tod do → deadlock nahi hoga!

3. Deadlock Prevention High ⭐⭐⭐

Prevent deadlock by ensuring at least ONE Coffman condition is never satisfied:

  • Eliminate Mutual Exclusion: Make resources sharable (not always possible for printers etc.).
  • Eliminate Hold and Wait: Process must request ALL resources at once before starting, OR release all before requesting more.
  • Allow Preemption: If a process holding resources requests another unavailable resource, preempt all its resources.
  • Eliminate Circular Wait: Impose a total ordering on resource types; processes must request resources in increasing order of enumeration.

4. Deadlock Avoidance — Banker's Algorithm High ⭐⭐⭐⭐⭐ 🔥 Numerical

English

The Banker's Algorithm (Dijkstra, 1965) is a deadlock avoidance algorithm. Before granting a resource request, it simulates the allocation and checks if the resulting state is safe. A state is safe if a safe sequence exists — an ordering of processes where each can complete using currently available + resources released by previously finished processes.

Hinglish

Banker's Algorithm ek bank jaisa kaam karta hai — bank loan dene se pehle check karta hai ki baad mein bhi sab loans return ho sakenge ya nahi. Similarly, OS resource dene se pehle simulate karta hai — "agar ye resource de diya to kya koi safe sequence milega?" Agar haan, to de do. Nahi to wait karo.

Banker's Algorithm Worked Example (RTU pattern)

5 processes (P0–P4), 3 resource types (A=10, B=5, C=7). Allocation and Max matrices:

ProcessAlloc A B CMax A B CNeed A B C
P00 1 07 5 37 4 3
P12 0 03 2 21 2 2
P23 0 29 0 26 0 0
P32 1 12 2 20 1 1
P40 0 24 3 34 3 1

Available = A:3, B:3, C:2 (Total − ΣAllocation)

Safe Sequence: P1(need 1,2,2 ≤ available 3,3,2 ✓) → release → avail 5,3,2 → P3(0,1,1≤5,3,2 ✓) → avail 7,4,3 → P4(4,3,1≤7,4,3 ✓) → avail 7,4,5 → P0(7,4,3≤7,4,5 ✓) → avail 7,5,5 → P2(6,0,0≤7,5,5 ✓)

Safe Sequence: <P1, P3, P4, P0, P2> — System is in SAFE STATE ✅

5. Resource Allocation Graph (RAG) High ⭐⭐⭐⭐ 🔥

English

A Resource Allocation Graph (RAG) is a directed graph G = (V, E) used to represent the state of resource allocation. Vertices V = Processes (P) ∪ Resources (R). Edges: Request edge (Pi → Rj) = process requesting resource. Assignment edge (Rj → Pi) = resource assigned to process. Cycle in RAG = Deadlock (for single-instance resources).

Hinglish

RAG ek directed graph hai jisme processes (circles) aur resources (rectangles) nodes hote hain. Request edge = process resource maang raha hai (P→R dashed). Assignment edge = resource process ko diya gaya hai (R→P solid). Agar RAG mein cycle ho to deadlock hai (single instance ke case mein).

Wait-For Graph (WFG)

WFG is derived from RAG by removing resource nodes. If Pi → Rj and Rj → Pk, then Pi → Pk in WFG. A cycle in WFG = Deadlock (single-instance resources). OS periodically checks for cycles in WFG to detect deadlocks.

6. Deadlock Recovery Medium ⭐⭐⭐

Process Termination

  • Abort All — terminate all deadlocked processes. Quick but expensive (all work lost).
  • Abort One at a Time — terminate one process at a time and check if deadlock resolved. Costly but selective.

Resource Preemption

  • Select Victim — choose which process to preempt (min cost).
  • Rollback — restore victim to safe state.
  • Starvation — avoid selecting same process repeatedly.

Device Drivers High

English

A Device Driver is a software module that translates generic OS I/O requests into device-specific commands understood by the hardware controller. Each device requires its own driver.

Hinglish

Device driver ek translator hai — OS ek generic request deta hai "print karo" aur driver use specific printer language mein convert karta hai. Bina driver ke OS device se baat hi nahi kar sakta! Isliye naya printer connect karne pe driver install karna padta hai.

8. Disk Scheduling Algorithms High ⭐⭐⭐⭐⭐ 🔥 Numerical

English

Disk Scheduling is the OS policy for deciding the order in which disk I/O requests are served, to minimize seek time (time for disk arm to move to correct track) and maximize throughput.

AlgorithmIdeaAdvantageDisadvantage
FCFSServe requests in arrival orderFair, no starvationHigh seek time, poor performance
SSTFServe request closest to current head positionBetter than FCFSStarvation possible
SCAN (Elevator)Head moves in one direction, serves all, then reversesGood performanceVariation in wait time
C-SCANHead moves in one direction only, jumps to other endUniform wait timeSlight overhead at turnaround
LOOKLike SCAN but only goes as far as last requestEfficientSlightly complex
Disk Scheduling Numerical — SSTF (RTU pattern)

Disk queue: 98, 183, 37, 122, 14, 124, 65, 67. Head starts at 53. Apply SSTF.

From 53: closest = 65 (diff 12). From 65: closest = 67 (diff 2). From 67: closest = 37 (diff 30). From 37: closest = 14 (diff 23). From 14: closest = 98 (diff 84). From 98: closest = 122 (diff 24). From 122: closest = 124 (diff 2). From 124: closest = 183 (diff 59).

Sequence: 53→65→67→37→14→98→122→124→183. Total movement = 236 cylinders.

❓ Unit 4 — Q&A (RTU Exam Pattern)

RTU EXAM Q&A
Q1. Define Deadlock. State the four necessary conditions (Coffman conditions). ★★★★★ 5-7 Marks
5 Marks

Deadlock = set of processes each holding resources and waiting for resources held by others — circular wait with no progress. 4 conditions: Mutual Exclusion, Hold & Wait, No Preemption, Circular Wait. All four must hold simultaneously for deadlock.

RTU EXAM Q&A
Q2. Explain Banker's Algorithm with example. ★★★★★ 10 Marks — guaranteed every year
10 Marks

Banker's Algorithm: (1) Compute Need = Max − Allocation for each process. (2) Initialize Work = Available, Finish[i]=false. (3) Find a process i where Finish[i]=false AND Need[i] ≤ Work. (4) Work += Allocation[i], Finish[i]=true. (5) Repeat until all Finish=true (Safe) or no such i found (Unsafe). Full worked example above: Safe sequence <P1,P3,P4,P0,P2>.

RTU EXAM Q&A
Q3. What is a Resource Allocation Graph? How does it detect deadlock? ★★★★ 7 Marks
7 Marks

RAG = directed graph with processes (circles) and resources (rectangles). Request edge P→R, Assignment edge R→P. Deadlock detection: for single-instance resources, a cycle in RAG = deadlock. For multi-instance resources, use Wait-For Graph or reduction algorithm. WFG derived by removing resource nodes from RAG.

RTU EXAM Q&A
Q4. Explain disk scheduling algorithms: FCFS, SSTF, SCAN, C-SCAN with numerical. ★★★★★ 10 Marks — numerical guaranteed
10 Marks

All 4 algorithms defined in table above. SSTF numerical worked above (53→65→67→37→14→98→122→124→183, total 236 cylinders). Practice FCFS and SCAN on same queue to compare total head movement.

RTU EXAM Q&A
Q5. Explain different I/O techniques: Polling, Interrupt-Driven, DMA. ★★★★ 7 Marks
7 Marks

Polling = CPU checks device status in busy loop (simple but wastes CPU). Interrupt-Driven = device sends interrupt when ready, CPU handles ISR only (better CPU utilization). DMA = DMA controller handles data transfer directly, CPU only initializes (best — CPU nearly free during transfer). Table above gives full comparison.

RTU EXAM Q&A
Q6. What are the methods to handle deadlock? Compare prevention, avoidance, detection. ★★★★ 7 Marks
7 Marks

Prevention = eliminate one Coffman condition (high overhead). Avoidance = Banker's algorithm — check safe state before allocation (moderate overhead, needs advance info). Detection = allow deadlock, detect via RAG/WFG, recover by process termination or resource preemption (best utilization but recovery needed). Ignorance = Ostrich algorithm (Windows/Linux approach for rare deadlocks).
