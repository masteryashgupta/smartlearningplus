1. Introduction to Convolutional Codes High ⭐⭐⭐

English

A Convolutional Code is an error-control code in which the encoder output at any time instant depends not only on the current input block of k bits, but also on a fixed number of previous input blocks (stored in shift-register memory). Unlike block codes (where each codeword is encoded independently), convolutional codes process data as a continuous stream, convolving the input sequence with the encoder's impulse response (generator sequences) — hence the name.

Hinglish

Linear Block Code (Unit 4) aur Cyclic Code (Unit 5) mein har codeword independent hota hai — fixed k input bits se fixed n output bits bante hain, koi memory nahi. Convolutional code mein encoder ek shift register use karta hai jisme purane input bits "yaad" rehte hain — to current output sirf current input pe nahi, pichle kuch bits pe bhi depend karta hai. Isiliye data ko continuous stream ki tarah process karta hai, block-by-block nahi. Ye satellite communication, deep-space probes (Voyager), aur 4G/WiFi mein bahut use hota hai.

2. Convolutional Encoder — Structure & Parameters High ⭐⭐⭐⭐

English

A convolutional encoder is built from a k-bit-wide shift register with m memory stages, and n modulo-2 (XOR) adders tapped at specific register positions (defined by generator sequences/polynomials) to produce n output bits for every k input bits. It is denoted as an (n, k, m) code.

Code Rate: R = k/n (k input bits → n output bits) Constraint Length: K = m + 1 (total no. of input bits influencing one output set; m = memory order / no. of shift-register stages)
Hinglish

k = ek time mein kitne input bits jaate hain, n = unse kitne output bits banate hain, m = shift register mein kitne "purane" input bits store hote hain (memory). Constraint length K batata hai ki total kitne bits (current + memory) ek output ko affect karte hain — jitna zyada K, utna behtar error-correction lekin utna zyada complex decoder.

Fig 6.1 — Rate-½ Convolutional Encoder, K=3 (m=2 memory stages), generator polynomials g₁=(111), g₂=(101) — the classic "(7,5) octal" NASA encoder used throughout this unit's worked examples

3. Convolutional Encoders of Different Rates High ⭐⭐⭐

Rate-1/2 Encoder (k=1, n=2)

Most common in practice. One input bit produces two output bits per clock cycle (as shown in Fig 6.1 above). Used in deep-space communication, GSM, dial-up modems.

Rate-1/3 Encoder (k=1, n=3)

One input bit produces three output bits — lower rate, more redundancy, stronger error correction but lower throughput. Three generator polynomials g₁,g₂,g₃ tap the shift register at different positions; used where channel is extremely noisy (e.g. very weak satellite signal links).

General Rate-k/n Encoder

k input bits enter simultaneously per clock cycle, producing n output bits, with k separate shift registers feeding n modulo-2 adders. Higher k/n ratio (e.g. 2/3, 3/4) gives higher throughput but weaker error protection — there is always a fundamental trade-off between rate and error-correcting strength.

Hinglish

Rate k/n jitna chhota (jaise 1/3), utni zyada redundancy add hoti hai → behtar error correction, lekin bandwidth zyada use hoti hai (slow effective throughput). Rate jitna bada (jaise 3/4), utni kam redundancy → fast throughput lekin kamzor error protection. Engineer ko apne channel ki noise condition dekh kar ye trade-off choose karna padta hai.

4. Code Tree Representation Medium ⭐⭐⭐

English

A code tree is a graphical representation of a convolutional encoder where each level (depth) corresponds to one input time-step, each node represents the encoder's state, and each branch represents the output produced for a given input bit (0 = upper branch, 1 = lower branch, by convention). The tree grows without bound as more input bits arrive, doubling the number of branches at every level.

Hinglish

Code tree sabse "basic"/literal representation hai — har input bit ke liye tree do branches mein split hota hai (0 ya 1), aur har branch pe output bits likhe jaate hain. Problem ye hai ki ye tree exponentially badhta hai (har level pe nodes double), isiliye practically lamba sequence ke liye bahut bada ho jaata hai — yahi limitation trellis diagram solve karta hai (states repeat hote hain, tree "fold" ho jaata hai).

5. State Diagram High ⭐⭐⭐⭐

English

The state diagram represents the convolutional encoder as a finite-state machine: each node is one of the 2m possible shift-register contents (states), and each directed edge shows the transition to a new state for a given input bit, labeled "input/output". Unlike the code tree, the state diagram has a fixed, finite number of nodes — it compresses the infinitely-growing tree into a compact, repeating structure.

Hinglish

State diagram mein sirf 2m states hote hain (jaise m=2 ke liye 4 states: 00,01,10,11) — chahe sequence kitni bhi lambi ho, states repeat hote rehte hain. Har state se 2 outgoing edges hote hain (input 0 ke liye, input 1 ke liye), edge pe "input/output" label hota hai. Ye code tree se zyada practical/compact representation hai.

6. Trellis Diagram High ⭐⭐⭐⭐⭐ — essential for Viterbi numericals

English

A trellis diagram is the state diagram unrolled over time — it shows all possible states at every time instant (as columns), with branches connecting states from one time-step to the next. It combines the finite-state compactness of the state diagram with the explicit time-progression of the code tree, making it the ideal structure for decoding algorithms like Viterbi.

Hinglish

Trellis = state diagram ko time ke saath "unfold" kar diya — har time step pe sab 4 states ek column mein dikhte hain, aur lines unhe agle time-step ke states se jodti hain. Ye Viterbi algorithm ke liye perfect structure hai kyunki ismein "merging paths" dikhte hain — jab do different input sequences same state pe converge ho jaayen, to weak path ko discard kar sakte hain (yahi Viterbi ka core trick hai).

7. Maximum Likelihood Decoding — The Viterbi Algorithm High ⭐⭐⭐⭐⭐ (Most Important Topic — full numerical expected)

English

Maximum Likelihood (ML) Decoding selects, among all possible transmitted codeword sequences, the one that is "closest" (minimum Hamming distance, for a binary symmetric channel) to the received sequence. The Viterbi Algorithm is an efficient way to perform ML decoding on a trellis: instead of comparing every possible path (which grows exponentially), it computes a running path metric at each state and, whenever two paths merge into the same state, discards the path with the worse metric — keeping only the single best ("survivor") path into each state at every time step.

Hinglish

Maximum likelihood decoding ka matlab — sab possible transmitted sequences mein se wo sequence choose karo jo received sequence ke sabse "close" (kam se kam Hamming distance) ho. Lekin sab sequences ko check karna exponentially expensive hai. Viterbi algorithm ka trick — trellis pe chalte hue, jab bhi 2 paths same state pe milte hain ("merge"), to jo path zyada error/distance accumulate kar chuka hai use turant discard kar do, sirf best ("survivor") path rakho. Isse computation drastically kam ho jaata hai, aur phir bhi guaranteed optimal (ML) answer milta hai.

Viterbi Algorithm — Step-by-Step High — write this exact sequence in exam

  1. Initialize: Set path metric of the starting state (usually all-zero state 00) = 0; all other states = ∞ (unreachable initially).
  2. Branch metric computation: At each time step, for every valid transition, compute the branch metric = Hamming distance between the received bits and the expected output bits for that branch.
  3. Path metric update (Add-Compare-Select): For every state at the new time step, add the branch metric to the path metric of the originating state (for each incoming branch). If multiple branches arrive at the same state, compare them and select (keep) only the path with the minimum total metric — this is the survivor path for that state; discard the other(s).
  4. Repeat steps 2-3 for every time step until the end of the received sequence.
  5. Trace back: At the final time step, pick the state with the minimum path metric (usually the all-zero state if the encoder was flushed/terminated). Trace back through the stored survivor branches to recover the most likely input sequence.

8. Free Distance of a Convolutional Code High ⭐⭐⭐⭐

English

The Free Distance (dfree) of a convolutional code is the minimum Hamming distance between any two distinct (complete) code sequences generated by the encoder — equivalently, it is the minimum-weight nonzero path in the trellis/state diagram that diverges from the all-zero state and eventually remerges with it. It plays the same role for convolutional codes that minimum distance dmin plays for block codes — determining the code's error-correcting capability.

Error-correcting capability: t = ⌊(dfree − 1) / 2⌋
Hinglish

Free distance batata hai ki agar encoder all-zero state se "bhatak" jaaye (kisi non-zero input ki wajah se) aur fir se all-zero state pe wapas aaye, to is poore detour mein minimum kitna "weight" (1s ki count) accumulate hoga. Yahi number decide karta hai ki code kitne errors tak correct kar sakta hai — jaise block codes mein dmin karta hai.

Computing dfree for our Fig 6.1 encoder

Find the minimum-weight path that leaves state 00 and returns to state 00 (using the state diagram, Fig 6.3):

Path: 00 →(u=1, out=11, weight=2)→ 10 →(u=0, out=10, weight=1)→ 01 →(u=0, out=11, weight=2)→ 00

Total weight = 2+1+2 = 5

No shorter-weight path exists that diverges and remerges with state 00 (can be verified by checking all alternative paths — they all accumulate weight ≥5).

∴ dfree = 5 for this rate-½, K=3 code.
Error-correcting capability: t = ⌊(5−1)/2⌋ = 2 errors per decoding window.

Factors Affecting Free Distance Medium ⭐⭐

  • Increasing constraint length K (more memory/shift-register stages) generally increases dfree — better error correction, at the cost of decoder complexity (states grow as 2m).
  • Choice of generator polynomials matters greatly — poorly chosen generators can give a low dfree even for large K; generators must be chosen (e.g. via computer search) to maximize dfree.
  • Lower code rate (k/n) typically allows higher dfree due to greater redundancy.

UNIT 6: Convolutional Codes & Viterbi Decoding

1. Encoder & Structural Memory

  • Parameters: $(n,k,m)$ code, rate $R=k/n$, constraint length $K=m+1$
  • Memory: Shift register of $m$ stages $\Rightarrow 2^m$ possible states
  • Generators: Mod-2 adders connected via generator vectors $g_1, g_2$

2. Code Representations

  • Code Tree: Binary tree branching at each time instant ($2^t$ growth)
  • State Diagram: Directed graph of $2^m$ states with input/output edges
  • Trellis Diagram: Time-indexed state transitions (Repeats after $K$ steps)

3. Viterbi Decoding & Free Distance

  • ML Decoding: Finds code path with minimum total Hamming metric
  • ACS Rule: Add branch metric, Compare converging paths, Select survivor
  • Free Distance: $d_{free} = \text{min weight path leaving and returning to 00}$
