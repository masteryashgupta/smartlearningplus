7.1 Introduction to Cognitive Architecture (CA) EXAM HOT

📖 Definition

A Cognitive Architecture (CA) is a theoretical framework/blueprint that describes the fixed structures and mechanisms of the human mind — such as memory stores, perception, attention, and reasoning processes — which underlie intelligent behaviour. In HCI, a cognitive architecture is used as a computational or conceptual model of the user, so that a designer can predict, simulate, or explain how a person will perceive, think about, and act upon an interface, without needing an actual human to test every design.

🗣️ Hinglish Explanation

Cognitive Architecture ek tarah ka "blueprint of the mind" hai jo batata hai ki insaan ka brain information ko kaise perceive karta hai, kaise store karta hai (memory), aur kaise decision leke action leta hai. HCI designers isko use karte hain taaki wo bina real users ko baar-baar test kiye, predict kar saken ki new interface use karne mein user ko kitna time lagega, kahan confuse hoga, ya kahan error karega. Ismein human mind ko ek "information processing system" (jaise computer) ki tarah treat kiya jata hai — Input (Perception) → Processing (Cognition) → Output (Motor action).

Why Model the Human Mind as an Architecture?

  • Predictive Power: Designers can estimate task completion time, error rate, and learnability before building the actual system.
  • Explains Behaviour: Provides a scientific explanation of *why* a user struggles with a particular design (e.g., too many items overload working memory).
  • Design Guidance: Suggests concrete constraints — e.g., "don't show more than 7±2 unrelated items at once" comes directly from a cognitive architecture's memory model.
  • Cost Reduction: Reduces the need for expensive, repeated usability testing with real users at every design iteration.
A cognitive architecture models the user as an information-processing loop: Environment → Perception → Cognition → Action → back to Environment
💡 Example

When a user sees an error message pop up (Perception), recalls from memory what caused similar errors before (Cognition), decides to click "Retry" (Decision), and physically clicks the button (Motor action) — this entire chain is exactly what a cognitive architecture like the Model Human Processor attempts to formally represent and predict the timing of.

7.2 Types of Cognitive Architecture MUST KNOW

📖 Definition

Cognitive architectures are broadly classified based on how they represent knowledge and simulate reasoning — using explicit symbols and rules, using neural/numeric activation patterns, or a mixture of both.

🗣️ Hinglish

Alag-alag researchers ne mind ko model karne ke alag-alag tareeke banaye hain. Kuch models "rules aur symbols" (jaise IF-THEN logic) use karte hain, kuch "neural network jaisi weighted connections" use karte hain, aur kuch dono ko mix karte hain. HCI mein sabse zyada use hone wala symbolic model hai MHP (Model Human Processor), kyunki yeh interface design ke liye simple aur practical hai.

Three Broad Categories of Cognitive Architectures

TypeHow it Represents KnowledgeExamples
Symbolic ArchitectureUses explicit symbols, rules and production systems (IF condition THEN action) to represent knowledge and reasoning stepsModel Human Processor (MHP), ACT-R, SOAR, EPIC
Connectionist (Sub-symbolic) ArchitectureUses networks of simple interconnected units (like artificial neurons) with weighted connections; knowledge is distributed across the network rather than stored as discrete symbolsParallel Distributed Processing (PDP) models, Neural Network based cognitive models
Hybrid ArchitectureCombines symbolic rule-based reasoning with sub-symbolic/connectionist learning to get benefits of both precision and adaptabilityCLARION, SOAR (extended versions), ACT-R (with sub-symbolic activation equations)
Three broad families of cognitive architectures used to model human information processing
📌 For RTU exam purposes, the Model Human Processor (MHP) is the symbolic cognitive architecture you must know in depth — it is the classical, most examined CA in HCI syllabi.

7.3 Relevance of CA in Interactive System (IS) Design EXAM HOT

📖 Definition

The relevance of Cognitive Architecture in Interactive System (IS) design lies in its ability to give designers a scientific, predictive, and quantifiable understanding of the user's mental processes, so that interface decisions (layout, feedback timing, information density, navigation depth) can be justified and evaluated analytically rather than purely by guesswork or trial-and-error.

🗣️ Hinglish

CA humein batata hai ki user ka dimag interface ke saath interact karte waqt kaise kaam karta hai. Isse designer ko pata chalta hai ki menu itna deep nahi hona chahiye (working memory limited hai), response itni jaldi aani chahiye (cognitive processor ka apna ek fixed cycle time hai), aur agar bahut saari choices di gayi to decision lene mein zyada time lagega (Hick-Hyman Law). Yani CA sirf theory nahi — yeh directly practical design rules deta hai.

Key Areas Where CA Guides Interactive System Design

  • 1. Predicting Task Execution Time: Using GOMS/KLM-style analysis (built on MHP timings) to estimate how long an expert user will take to complete a task, without user trials.
  • 2. Managing Working-Memory Load: Since working memory can hold roughly 7±2 chunks, menus, forms, and dashboards are chunked/grouped so users are not overloaded.
  • 3. Designing Response & Feedback Timing: Knowing perceptual/cognitive/motor cycle times helps decide acceptable system response delays (e.g., feedback should appear within ~100 ms to feel "instantaneous").
  • 4. Reducing Decision Time: Hick-Hyman Law (rooted in the cognitive processor) tells designers that fewer, well-organized menu choices reduce user decision time.
  • 5. Error Prediction & Diagnosis: A CA can explain *why* an error occurred — e.g., a "slip" due to motor system automaticity vs. a "mistake" due to a wrong mental model — guiding better error-recovery design.
  • 6. Supporting Learnability: The Power Law of Practice (also a CA principle) predicts how performance speeds up with repeated use, guiding the design of tutorials and shortcuts for experts vs. novices.
💡 Example

Before building a new ATM interface, a designer can use the MHP's cycle-time values to analytically calculate that a 4-option menu will require less decision time than an 8-option menu, and can use working-memory limits to decide that a PIN should not be split into more than 2 chunks for the user to remember at once.

7.4 Model Human Processor (MHP) — Structure EXAM HOT

📖 Definition

The Model Human Processor (MHP), proposed by Card, Moran and Newell (1983) in "The Psychology of Human-Computer Interaction," is a simplified, engineering-style cognitive architecture that represents the human information-processing system as three interacting subsystems — the Perceptual System, the Cognitive System, and the Motor System — each with its own processor and associated memory store, working together like the CPU, RAM and I/O units of a computer.

🗣️ Hinglish

MHP insaan ko ek computer system ki tarah treat karta hai — jaise computer mein input device, processor aur output device hote hain, waise hi humare andar bhi 3 subsystems hain: ek jo dekhta/sunta hai (Perceptual), ek jo sochta hai aur decide karta hai (Cognitive), aur ek jo action perform karta hai (Motor). Har subsystem ka apna ek "processor" (jo kaam karne mein time leta hai) aur "memory" (jahan information store hoti hai) hota hai.

The Three Subsystems of MHP

MHP's three interacting subsystems — Perceptual, Cognitive, and Motor — each with a processor and memory store
  • Perceptual System: Receives sensory stimuli (visual, auditory) from the environment and briefly holds them in sensory buffers — the Visual Image Store (VIS) and Auditory Image Store (AIS) — before passing recognized information to the cognitive system.
  • Cognitive System: Processes the perceived information using Working Memory (WM) (short-term, limited capacity) and Long-Term Memory (LTM) (large/unlimited capacity), and decides what response is appropriate.
  • Motor System: Converts the cognitive system's decision into physical muscle movements (e.g., pressing a key, moving a mouse, speaking).

7.5 MHP Processors, Memories & Cycle Times 5-MARK

📖 Definition

Each of the three MHP subsystems has an associated processor cycle time — the time it takes that subsystem to complete one basic processing step — and, where applicable, a memory store characterized by its capacity (how much information it can hold) and decay time (how long the information remains before being lost).

🗣️ Hinglish

Har processor ka apna ek fixed "cycle time" hota hai — matlab wo ek step complete karne mein kitna time leta hai. Yeh values milliseconds mein hoti hain aur inhe add karke hum poore task ka total response time predict kar sakte hain. Memory ke liye do cheezein important hain: kitna store kar sakte ho (capacity) aur kitni der tak yaad rahega (decay time).

MHP Processor Cycle Times

ProcessorSymbolApprox. Cycle TimeRange
Perceptual ProcessorTp~100 ms50 – 200 ms
Cognitive ProcessorTc~70 ms25 – 170 ms
Motor ProcessorTm~70 ms30 – 100 ms
Total Response Time ≈ Tp + Tc + Tm (one simple recognize-act cycle)

MHP Memory Stores

Memory StoreCapacityDecay Time
Visual Image Store (VIS)~17 letters/items~200 ms
Auditory Image Store (AIS)~5 letters/items~1500 ms (1.5 s)
Working Memory (WM)~7 ± 2 chunks (Miller's Law)~7 – 226 s (decays fast without rehearsal)
Long-Term Memory (LTM)Effectively unlimitedEffectively unlimited (very slow/no decay)
📌 Miller's Magic Number 7±2 is the single most exam-favourite MHP fact — Working Memory holds about 7 (5 to 9) meaningful "chunks" of information at once, which is why phone numbers, menu items and password chunks are often grouped in sets of that size.

7.6 MHP Principles of Operation EXAM HOT

📖 Definition

Card, Moran and Newell supplemented the MHP structure with a set of operating principles — simplified laws that describe *how* the processors and memories behave in practice, allowing designers to make quantitative predictions about human performance.

🗣️ Hinglish

Sirf structure jaan lena kaafi nahi — MHP ke saath kuch "rules of thumb" bhi diye gaye hain jo batate hain ki yeh processors aur memories asal mein kaise behave karte hain. Yeh principles interface designers ke liye bahut useful hain kyunki inse hum numbers ke saath predictions kar sakte hain.

Major MHP Principles

  • 1. Recognize-Act Cycle Principle: On every cognitive processor cycle, the contents of working memory initiate actions associatively matched to that content (pattern recognition drives action).
  • 2. Variable Perceptual Processor Rate Principle: The perceptual processor cycle time varies inversely with stimulus intensity — brighter/louder stimuli are perceived faster.
  • 3. Discrete Perceptual Processor Principle: Perceptual processing operates as a series of discrete moments/samples rather than a continuous stream (like frames of a movie).
  • 4. Fitts' Law Principle: The time to point at a target of width W at distance D is a function of the index of difficulty log₂(2D/W) — larger, closer targets are acquired faster (covered in detail in Unit 3, reused here as an MHP-derived law).
  • 5. Power Law of Practice: The time to perform a task on the n-th trial decreases as a power function of n — practice makes users progressively (though diminishingly) faster.
  • 6. Uncertainty Principle (Hick-Hyman Law): Decision time increases with the logarithm of the number of equally probable choices: T = a + b·log₂(n).
  • 7. Rationality Principle: A person acts to attain their goals through rational action, given the structure of the task and their available knowledge/inputs.
  • 8. Problem Space Principle: Rational, goal-directed behaviour occurs within a "problem space" — searched through by applying available "operators" (actions) to move from the current state toward the goal state.
Hick-Hyman Law: T = a + b·log₂(n) [n = number of equally likely choices]
💡 Example

A restaurant kiosk with 4 menu categories will let a user decide faster than one with 16 flat menu items, because decision time grows only with the logarithm of the number of choices (Hick-Hyman Law) — this is why well-organized, hierarchical menus feel faster even with the same total number of options.

7.8 Introduction to OOP MUST KNOW

📖 Definition

Object-Oriented Programming (OOP) is a programming paradigm that organizes software design around objects — self-contained units that bundle together data (attributes/state) and the behaviour (methods) that operates on that data — rather than around a sequence of procedural instructions. Each object is an instance of a class, which acts as a blueprint/template defining what attributes and methods its objects will have.

🗣️ Hinglish

OOP ek programming style hai jisme hum poore program ko "objects" ke roop mein sochte hain — jaise real duniya mein "Button", "Car", "Student" alag-alag cheezein hain, waise hi code mein bhi hum inhe objects bana dete hain. Har object ke paas apna data (properties) aur apne functions (methods) hote hain. Class ek "mould/blueprint" hai jisse multiple objects banaye jaa sakte hain — jaise ek "Button class" se hum "OK button", "Cancel button" jaise multiple objects bana sakte hain.

Core OOP Terms

  • Class: A blueprint/template that defines a set of attributes and methods common to all objects of that type.
  • Object: A concrete instance of a class, having its own specific values for the attributes defined by the class.
  • Attribute (State): A data field/property that stores information about an object (e.g., a Button's label, color, isEnabled).
  • Method (Behaviour): A function defined inside a class that operates on the object's data (e.g., a Button's onClick()).
One class (Button) acts as a blueprint from which many independent objects (okBtn, cancelBtn, saveBtn) are instantiated

7.9 Four Pillars of OOP (Applied to UI Design) EXAM HOT

📖 Definition

OOP rests on four fundamental principles — Encapsulation, Abstraction, Inheritance, and Polymorphism — each of which has a direct, natural parallel in how user-interface widgets and controls are designed and reused.

🗣️ Hinglish

Yeh 4 pillars OOP ki foundation hain. UI design mein bhi yeh directly apply hote hain — jaise ek "Button" object apne andar ka internal drawing-logic chhupata hai (encapsulation), sirf zaruri properties dikhata hai (abstraction), ek "TextBox" ek generic "Control" class se properties inherit kar sakta hai (inheritance), aur ek hi "draw()" method har control type ke liye alag tareeke se kaam kar sakta hai (polymorphism).

1. Encapsulation

Definition: Bundling data and the methods that operate on it into a single unit (object), while hiding internal implementation details from the outside.

UI Example: A Slider widget hides its internal pixel-to-value conversion logic; other code only calls getValue()/setValue().

2. Abstraction

Definition: Exposing only the essential features of an object while hiding unnecessary complexity from the user of that object.

UI Example: A designer drags a "Calendar Picker" onto a form without needing to know how date-parsing or leap-years are handled internally.

3. Inheritance

Definition: A new class (subclass) can acquire the attributes and methods of an existing class (superclass), and add or override its own specific behaviour.

UI Example: A generic Control base class defines x, y, width, height, render(); Button, TextBox, and CheckBox all inherit from it and add their own specifics.

4. Polymorphism

Definition: The same method call behaves differently depending on the actual object type it is invoked on ("many forms").

UI Example: Calling render() on a list of mixed controls draws a Button as a rectangle with text, and a CheckBox as a small tick-box — same method name, different visual behaviour.

Inheritance (Control → Button/TextBox/CheckBox) combined with Polymorphism (each overrides render() differently)

7.10 Object Oriented Modeling (OOM) of User Interface Design EXAM HOT

📖 Definition

Object Oriented Modeling (OOM) of user interface design is the approach of applying OOP concepts and UML notations to analyze, design, and document a user interface — treating every screen element (button, form, window, menu) as an object belonging to a class, and describing the relationships (inheritance, composition, association) and interactions (message passing, event triggering) between these UI objects using standard diagrams.

🗣️ Hinglish

OOM ka matlab hai UI design ko bhi OOP ki tarah "objects" ke roop mein sochna aur usko UML diagrams (class diagram, sequence diagram, state diagram) se document karna. Isse UI components reusable, maintainable aur well-structured ban jaate hain — jaise ek "Form" class mein multiple "TextBox" aur "Button" objects composed hote hain.

Why Use OOM for UI Design?

  • Reusability: A well-designed Button class can be reused across every screen of the application without rewriting code.
  • Maintainability: Changing the visual style of all buttons only requires editing one class definition.
  • Clear Documentation: UML diagrams give developers and designers a shared, unambiguous visual language to discuss the UI structure.
  • Consistency: Since all similar widgets inherit from the same base class, the interface behaves consistently across the application.
  • Easier Testing: Each UI object can be unit-tested independently because its behaviour is encapsulated.
💡 Example

In designing a "Login Screen," OOM identifies the objects: LoginForm (a composite object containing) → UsernameField, PasswordField, LoginButton, and ForgotPasswordLink — each modeled as a class inheriting from a common UIControl base class, with the LoginForm object coordinating messages between them (e.g., clicking LoginButton triggers reading values from the two fields).

7.11 UML Diagrams Used in OOM for UI Design 5-MARK

📖 Definition

Unified Modeling Language (UML) provides a standard set of diagram types used to visually document the object-oriented model of a user interface, capturing its static structure and its dynamic (runtime) behaviour.

UML Diagrams Commonly Used for UI Modeling

DiagramPurposeUI Design Use
Class DiagramShows classes, their attributes/methods, and relationships (inheritance, association, composition)Models the static structure of UI controls, e.g. Control → Button/TextBox hierarchy
Use Case DiagramShows actors and the goals/tasks (use cases) they perform with the systemIdentifies what user tasks the interface must support before objects are designed
Sequence DiagramShows the time-ordered sequence of messages exchanged between objectsModels the flow when a user clicks "Login" — messages between LoginButton, LoginForm and AuthService
State (Statechart) DiagramShows the different states an object can be in and the events that trigger transitions between themModels a Button's states: Normal → Hover → Pressed → Disabled

7.12 OOM UI Design Process (Flowchart) 5-MARK

📖 Definition

The OOM UI design process is a sequence of steps that takes user requirements through object identification, class/relationship design, UML documentation, and iterative usability evaluation, to arrive at a working, well-structured interface.

🗣️ Hinglish

Yeh process step-by-step batata hai ki requirement gathering se lekar final tested interface tak kaise pahuchte hain — pehle use cases se pata karo user kya karna chahta hai, phir un tasks se "nouns" (objects) nikalo, unke classes aur relationships design karo, UML diagrams banao, prototype implement karo, aur phir usability testing karke iterate karo.

The Object-Oriented Modeling (OOM) UI design process — an iterative, object-first workflow

7.15 RTU Exam Q&A PYQ STYLE

Q1
What is a Cognitive Architecture? Explain its relevance in Interactive System design. 10 Marks

A Cognitive Architecture (CA) is a theoretical/computational framework describing the fixed mental structures (perception, memory, reasoning) underlying human information processing, used to model and predict user behaviour. Its relevance in Interactive System (IS) design lies in predicting task-execution times, managing working-memory load through chunking, guiding acceptable feedback/response timing, reducing decision time via principles like the Hick-Hyman Law, explaining/diagnosing user errors, and supporting learnability predictions through the Power Law of Practice — all of which allow analytical, evidence-based design decisions rather than pure trial and error.

Q2
List and briefly explain the types of Cognitive Architecture. 5 Marks

Cognitive architectures are of three broad types: Symbolic architectures, which represent knowledge with explicit rules and production systems (e.g., MHP, ACT-R, SOAR); Connectionist (sub-symbolic) architectures, which use networks of simple interconnected units with weighted, distributed knowledge representation (e.g., Parallel Distributed Processing models); and Hybrid architectures, which combine symbolic reasoning with connectionist learning to gain the benefits of both (e.g., CLARION).

Q3
Explain the Model Human Processor (MHP) with its structure, processors, and memories. 10 Marks

The Model Human Processor, proposed by Card, Moran and Newell, models human information processing as three interacting subsystems: the Perceptual System (with Visual and Auditory Image Stores and a Perceptual Processor, Tp ≈ 100 ms), the Cognitive System (with Working Memory and Long-Term Memory and a Cognitive Processor, Tc ≈ 70 ms), and the Motor System (with a Motor Processor, Tm ≈ 70 ms, that executes physical responses). Working Memory holds about 7±2 chunks with fast decay, while Long-Term Memory has effectively unlimited capacity and duration. Total simple response time is approximated as Tp + Tc + Tm.

Q4
State and explain any four principles of MHP operation. 5 Marks

Four key MHP principles are: (1) Recognize-Act Cycle Principle — on each cognitive cycle, working memory content associatively triggers matching actions; (2) Variable Perceptual Processor Rate Principle — perceptual cycle time varies inversely with stimulus intensity; (3) Uncertainty Principle (Hick-Hyman Law) — decision time increases with log₂ of the number of equally likely choices, T = a + b·log₂(n); and (4) Power Law of Practice — task-completion time decreases as a power function of the number of practice trials, meaning users get progressively faster with repetition.

Q5
What is OOP? Explain its four fundamental pillars with UI design examples. 10 Marks

Object-Oriented Programming (OOP) organizes software around objects that bundle data (attributes) and behaviour (methods) together, instances of classes acting as blueprints. Its four pillars are: Encapsulation — hiding internal implementation (e.g., a Slider widget hides its pixel-to-value logic); Abstraction — exposing only essential features (e.g., dragging a Calendar Picker without knowing date-parsing internals); Inheritance — subclasses reuse a superclass's features (e.g., Button and TextBox inheriting common properties from a Control base class); and Polymorphism — the same method call behaves differently per object type (e.g., calling render() draws a Button and a CheckBox differently).

Q6
Explain Object Oriented Modeling (OOM) of User Interface design with its process. 10 Marks

Object Oriented Modeling (OOM) of UI design applies OOP concepts and UML notations to treat every interface element as an object belonging to a class, describing relationships (inheritance, composition) and interactions between them. The process involves: gathering requirements via use cases, identifying UI objects (nouns) from those use cases, defining classes and their relationships, documenting the design using UML diagrams (class, sequence, state), implementing/prototyping the interface, and iteratively usability-testing and refining the design. This approach improves reusability, maintainability, consistency, and documentation clarity of the interface.

Q7
Differentiate between a Class Diagram, Sequence Diagram, and State Diagram in UML. 5 Marks

A Class Diagram is a static diagram showing classes, their attributes, methods, and relationships such as inheritance and composition. A Sequence Diagram is a dynamic/behavioural diagram showing the time-ordered sequence of messages exchanged between objects, such as the flow when a Login button is clicked. A State Diagram is also dynamic/behavioural but focuses on a single object, showing its possible states (e.g., Normal, Hover, Pressed, Disabled for a Button) and the events that trigger transitions between them.

Q8
Explain Miller's Magic Number 7±2 and its significance in interface design. 5 Marks

Miller's Magic Number states that human Working Memory can hold approximately 7 (ranging from 5 to 9) meaningful "chunks" of information at a time, as part of the MHP's Cognitive System. This is significant for interface design because it justifies grouping/chunking information — such as splitting long numbers, limiting the number of simultaneous menu options, or grouping form fields — so that users are not cognitively overloaded and can process and recall interface information effectively.

Q9
Explain the relevance of Encapsulation and Inheritance in designing reusable UI components. 5 Marks

Encapsulation lets a UI widget (like a Slider or DatePicker) hide its internal logic and expose only a clean interface (e.g., getValue()/setValue()), preventing other parts of the application from depending on or breaking its internals. Inheritance lets common properties (position, size, visibility, event-handling) be defined once in a base Control class and reused across all specific widgets like Button, TextBox, and CheckBox, avoiding duplicated code and ensuring consistent behaviour across the entire interface, while still allowing each widget to add its own specialized features.

Q10
Write short notes on: (a) Working Memory vs Long-Term Memory (b) Hick-Hyman Law. 5 Marks

(a) Working Memory (WM) is a small-capacity (~7±2 chunks), fast-decaying store used for active, temporary processing of information, whereas Long-Term Memory (LTM) has effectively unlimited capacity and duration, storing permanent knowledge and skills. (b) The Hick-Hyman Law states that decision time increases logarithmically with the number of equally probable choices available, expressed as T = a + b·log₂(n), which explains why fewer, well-organized menu options let users decide and respond faster than many flat, unorganized options.
