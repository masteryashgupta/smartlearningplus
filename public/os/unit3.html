1. Introduction to Memory Management High ⭐⭐⭐

English

Memory Management is the OS functionality that handles the allocation, deallocation, tracking, and protection of the computer's primary memory (RAM) among multiple processes running concurrently.

Hinglish

Ek hi time pe bahut saare programs chalate ho — jaise Chrome, WhatsApp, VS Code. OS ka kaam hai inhe RAM mein aise fit karna ki koi kisi ka data na churaye aur sab smoothly chale. Yahi hai Memory Management!

Logical vs Physical Address High

Logical Address

Address generated by the CPU during program execution. Also called virtual address. Program sochta hai — "main address 500 pe hoon" — ye sochna logical address hai. Real nahi hai ye!

Physical Address

Actual address in the memory unit. What the MMU sees and uses to access RAM. RAM mein actually kahan data pada hai — wo physical address hai. MMU logical ko physical mein translate karta hai.

2. Contiguous Memory Allocation High ⭐⭐⭐ 🔥

English

In contiguous memory allocation, each process is allocated a single contiguous section of memory. The entire process must reside in one continuous block of physical memory from start to end.

Hinglish

Jaise ek hotel room booking karo — tum chahte ho Room 101 se 110 tak ek saath mile. Bich mein koi doosra nahi aana chahiye. Yahi contiguous allocation hai — ek continuous block ek process ke liye.

Allocation Strategies

StrategyDescriptionAdvantageDisadvantage
First FitAllocate first hole large enoughFastLeaves small fragments at start
Best FitAllocate smallest sufficient holeLeaves smallest leftoversSlow (search all)
Worst FitAllocate largest holeLarge fragment still usableWorst performance overall

Fragmentation High

Internal Fragmentation

Memory wasted INSIDE an allocated block. Occurs when process size < partition size. E.g., 100KB partition given to 82KB process → 18KB wasted.

External Fragmentation

Total free memory is sufficient but NOT contiguous. E.g., Free holes: 30K + 50K + 20K = 100K, but 90K process cannot be allocated in any single hole. Solution: Compaction.

3. Paging High ⭐⭐⭐⭐⭐ 🔥

English

Paging is a memory management scheme that eliminates external fragmentation by dividing physical memory into fixed-size blocks called frames and logical memory into same-size blocks called pages. The OS maintains a page table to map logical pages to physical frames.

Hinglish

Paging mein RAM ko equal size ke "frames" mein baant dete hain aur process ko "pages" mein baant dete hain (same size). Page Table ye track karta hai ki kaunsa page kaunse frame mein pada hai. Isse external fragmentation nahi hoti — kyunki pages non-contiguous bhi ho sakti hain!

Logical Address = (Page Number p, Page Offset d) Physical Address = (Frame Number f, Page Offset d) Frame Number f = page_table[p] Physical Address = f × page_size + d
Numerical Example — Address Translation

Page Table: Page 0→Frame 4, Page 1→Frame 7, Page 2→Frame 3, Page 4→Frame 5. Page size = 512 bytes. Find physical address for logical address 2100.

Step 1: Page Number = 2100 ÷ 512 = 4 (integer division)
Step 2: Offset = 2100 mod 512 = 2100 - (4×512) = 52
Step 3: Page 4 → Frame 5 (from page table)
Step 4: Physical Address = 5 × 512 + 52 = 2560 + 52 = 2612

TLB — Translation Lookaside Buffer High 🔥

English

A TLB (Translation Lookaside Buffer) is a high-speed hardware cache (associative memory) that stores recently used page-to-frame mappings to speed up address translation. TLB Hit = fast (1 memory access). TLB Miss = access page table in RAM (2 memory accesses).

EAT = α × (TLB time + Memory time) + (1-α) × (TLB time + 2 × Memory time) where α = TLB hit ratio Example: α=0.80, TLB=20ns, Mem=100ns EAT = 0.80×(20+100) + 0.20×(20+200) = 96 + 44 = 140 ns

5. Virtual Memory & Demand Paging High ⭐⭐⭐⭐⭐ 🔥

English

Virtual Memory is a technique that allows programs to execute even if not completely in physical memory — it creates an illusion of a very large memory by using disk as an extension of RAM. Demand Paging is a virtual memory strategy where pages are loaded into RAM only when they are actually needed (demanded), rather than loading the entire process at startup.

Hinglish

Poori movie download mat karo — jitna dekh rahe ho utna hi load ho. Jab aage ki frame chahiye hogi tab download hogi. OS bhi yahi karta hai — puri process load nahi karta, sirf jab uss page ki zaroorat pade tab RAM mein laata hai. Page Fault = page RAM mein nahi hai, OS disk se laata hai!

Page Fault Handling Steps:

  1. Process accesses page → Check page table (valid bit check)
  2. Valid bit = 0 → Page Fault interrupt!
  3. OS: Find free frame in RAM
  4. Load page from disk (swap space) into the free frame
  5. Update page table, set valid bit = 1, restart instruction
EAT (Demand Paging) = (1 - p) × ma + p × page_fault_time where p = page fault rate, ma = memory access time Example: ma=100ns, page_fault_time=10ms, p=0.001 EAT = 0.999×100ns + 0.001×10,000,000ns = 10,099.9 ns ≈ 10.1 µs

6. Page Replacement Algorithms High ⭐⭐⭐⭐⭐ 🔥 — Numerical guaranteed

English

When a page fault occurs and all frames are full, the OS must choose a victim page to replace. Page replacement algorithms determine which page to remove.

AlgorithmKey IdeaPage FaultsBelady's Anomaly?
FIFOReplace oldest page in memorySimple but poorYES ❌ (suffers anomaly)
OPT (Optimal)Replace page that won't be used for longest timeMinimum (theoretical)No ✅
LRUReplace page that was least recently usedGood approximation of OPTNo ✅
💡Belady's Anomaly: With FIFO only — increasing number of frames can INCREASE page faults! Reference string 1,2,3,4,1,2,5,1,2,3,4,5 → with 3 frames: 9 faults, with 4 frames: 10 faults (anomaly!).

7. Thrashing High ⭐⭐⭐⭐ 🔥

English

Thrashing is a condition where a process spends more time swapping pages in and out of memory than executing instructions. CPU utilization drops drastically because processes are constantly waiting for page I/O.

Hinglish

Thrashing = system itna zyada page fault mein busy ho jaata hai ki actual kaam hi nahi hota. Jaise ek student itna zyada notes dhundhne mein busy ho ki padhta hi nahi! Solution: Working Set Model — process ko utne frames do jitne uska "working set" mein pages hain.

Solutions to Thrashing:

  • Working Set Model — Allocate frames = working set size of the process.
  • Page Fault Frequency — Too high rate → give more frames; too low → remove frames.
  • Reduce Multiprogramming — Swap out some processes entirely.
  • Use better replacement algorithm — LRU over FIFO.

8. Segmentation Medium ⭐⭐⭐

English

Segmentation is a memory management scheme that supports the programmer's view of memory. Memory is divided into variable-size segments — each corresponding to a logical unit like code, stack, heap, symbol table, etc. Address = (Segment#, Offset). Physical Address = Base + Offset (if offset < limit, else Segmentation Fault).

Hinglish

Paging mein memory ko fixed pages mein baant diya. Segmentation mein logical groups mein baant dete hain — jaise Code segment, Data segment, Stack segment. Programmer ko ye dikh sakta hai aur ye meaningful hai. Variable size ke hote hain.

❓ Unit 3 — Q&A (RTU Exam Pattern)

RTU EXAM Q&A
Q1. What is paging? Explain address translation in paging with diagram. ★★★★★ 10 Marks
10 Marks

Paging divides logical memory into fixed-size pages and physical memory into frames of same size. OS maintains a page table. Physical Address = frame# × page_size + offset. Full diagram and numerical example (2100→2612) given above.

RTU EXAM Q&A
Q2. Explain FIFO, LRU and Optimal page replacement with example. ★★★★★ 10 Marks — guaranteed
10 Marks

FIFO = replace oldest page (suffers Belady's anomaly). OPT = replace page used furthest in future (theoretical, minimum faults). LRU = replace least recently used (best practical). Practice with reference string 7,0,1,2,0,3,0,4,2,3,0,3,2,1,2,0,1,7,0,1 with 3 frames.

RTU EXAM Q&A
Q3. What is thrashing? How is it caused? How to prevent it? ★★★★ 5-7 Marks
5 Marks

Thrashing = process spends more time in page I/O than execution. Cause = too many processes, each getting too few frames. Prevention = Working Set Model (allocate frames = working set size), Page Fault Frequency control, reduce multiprogramming degree.

RTU EXAM Q&A
Q4. Explain TLB and calculate Effective Access Time. ★★★★ 5 Marks 🔥 PYQ
5 Marks

TLB = high-speed cache for page-to-frame mappings. TLB Hit → 1 memory access. TLB Miss → 2 memory accesses. EAT = α(ε+m) + (1-α)(ε+2m). Example: α=0.80, ε=20ns, m=100ns → EAT = 140ns. Full formula above.

RTU EXAM Q&A
Q5. Differentiate between paging and segmentation. ★★★ 5 Marks
5 Marks

Paging = fixed-size pages, no external fragmentation, transparent to programmer, page table used. Segmentation = variable-size segments, external fragmentation, visible to programmer, segment table used. Full table above.

RTU EXAM Q&A
Q6. What is virtual memory? What are its advantages? ★★★★ 5 Marks
5 Marks

Virtual memory = technique allowing programs to execute without being fully in RAM, using disk as extension. Advantages: programs larger than physical RAM can execute, more processes can coexist, faster process creation, easier library sharing. Implemented via demand paging.

RTU EXAM Q&A
Q7. What is Belady's Anomaly? Which algorithm suffers from it? ★★ 3 Marks
3 Marks

Belady's Anomaly = counterintuitive phenomenon where increasing frames results in MORE page faults. Only FIFO suffers from it. LRU and OPT do NOT (they are "stack algorithms"). Example: reference string 1,2,3,4,1,2,5,1,2,3,4,5 → 3 frames: 9 faults, 4 frames: 10 faults.
