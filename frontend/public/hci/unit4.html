01. Introduction — Why Guidelines Matter HIGH
Guidelines, principles aur heuristics interface design ko "guess-work" se "science" banate hain
Definition

Design Guidelines in HCI are a set of recommendations, rules, and principles derived from research on human cognition, perception, and behavior that help designers create interfaces which are easy to learn, efficient to use, and pleasant to interact with.

🇮🇳 Hinglish Explanation
Jab bhi hum koi software ya app design karte hain, hume pata nahi hota ki user kaise sochega, kya expect karega. Isliye HCI experts ne years of research ke baad kuch "guidelines" aur "rules" banaye hain jo bataate hain ki ek good interface kaisa hona chahiye. Ye guidelines designer ko batati hain — consistency rakho, feedback do, errors se bachao, user ko control do, waghera. Is unit mein hum 4 major frameworks padhenge: Shneiderman's 8 Golden Rules, Norman's 7 Principles, Norman's Interaction Model, aur Nielsen's 10 Heuristics — plus unhe evaluate karne ke 3 tareeke: Heuristic Evaluation, Contextual Inquiry, aur Cognitive Walkthrough.
💡
Exam Tip: RTU mein "Shneiderman's 8 rules list karo", "Nielsen's 10 heuristics with example" aur "Norman's 7 stage model diagram" — ye teeno bahut common 10-mark questions hain. Diagram bana kar dikhana bonus marks deta hai.

02. Shneiderman's Eight Golden Rules HIGH

Definition

Ben Shneiderman's Eight Golden Rules are a set of interface design principles proposed to guide the design of interactive systems so that they are consistent, predictable, and reduce the user's cognitive load and error rate.

🇮🇳 Hinglish
Ben Shneiderman ek famous HCI researcher hai jisne 8 "golden rules" batayi jo har achhe interface mein follow honi chahiye — chahe woh website ho, mobile app ho ya desktop software. Ye rules generic hain, kisi bhi domain pe apply hote hain.

Fig 1: Shneiderman's Eight Golden Rules of Interface Design

#RuleMeaningExample
1Strive for ConsistencySame terminology, layout, colour and command sequence should be used throughoutAll "Save" buttons look and behave the same across all screens of an app
2Enable Frequent Users to Use ShortcutsProvide accelerators like keyboard shortcuts, macros for expert usersCtrl+C / Ctrl+V for copy-paste instead of navigating menus every time
3Offer Informative FeedbackEvery action should have an appropriate, visible system responseProgress bar while uploading a file; green tick after form submission
4Design Dialogs to Yield ClosureGroup actions into sequences with a beginning, middle and end so user feels a sense of completion"Order placed successfully" confirmation screen after checkout
5Offer Error Prevention & Simple Error HandlingDesign so users cannot easily make serious errors; if they do, give clear recovery instructionsGreying-out "Submit" button until all mandatory fields filled
6Permit Easy Reversal of ActionsActions should be undoable, reducing anxiety of exploring the interfaceCtrl+Z Undo; "Move to Trash" instead of permanent delete
7Support Internal Locus of ControlExperienced users want to feel they are in charge of the system, not the system controlling themUser can cancel a long-running download/search anytime
8Reduce Short-Term Memory LoadHuman short-term memory is limited (7±2 items); interface should minimize the need to remember informationAuto-fill/auto-suggest of previously entered address instead of retyping
Mnemonic to Remember

"C-S-F-C-E-R-L-M" → Consistency, Shortcuts, Feedback, Closure, Errors, Reversal, Locus of control, Memory load. Yaad rakhne ke liye story bana lo: "Consistent Shopping Feels Complete, Errors Reverse, Locus Matters".

03. Norman's Seven Principles of Design HIGH

Definition

Don Norman's Seven Principles (from his book "The Design of Everyday Things") are design principles that help transform difficult, hard-to-use tasks into simple ones by considering how humans perceive, think about, and interact with objects and systems.

🇮🇳 Hinglish
Don Norman ne apni book mein bताया ki achhe products (chahe door handle ho ya software) users ko khud batate hain ki unhe kaise use karna hai — bina manual padhe. Ye 7 principles wahi cheez software design mein achieve karne ke liye use hote hain.
#PrincipleExplanationExample
1Use both Knowledge in the World & in the HeadPeople use a combination of information stored in memory and information available in the environment (labels, icons, cues)Icon of a printer on a button — user doesn't need to memorize a code, the icon itself gives the cue
2Simplify the Structure of TasksReduce the mental effort needed by breaking complex tasks into simple steps or using automation/toolsMulti-step wizard for account setup instead of one huge complex form
3Make Things VisibleBridge the gulf of execution and evaluation by making controls and system state visible to the userVisible "Save" icon, visible battery/wifi status icons on a phone
4Get the Mappings RightEnsure a correct relationship between controls and their effects, matching user's mental modelSteering wheel turn right → car turns right (natural mapping); volume slider up = louder
5Exploit the Power of ConstraintsUse physical, logical, semantic and cultural constraints to guide the user and prevent incorrect actionsSIM card/USB slot shaped so it can only be inserted one correct way
6Design for ErrorAssume errors will happen; design the system so errors can be easily detected and reversedConfirmation dialog "Are you sure you want to delete this file?"
7When All Else Fails, StandardizeWhere no natural mapping exists, provide a standard that everyone can learn once (e.g., across an industry/platform)QWERTY keyboard layout; steering wheel always on left/right per country standard
Constraint Types (Principle 5, expand this in answers)

Physical constraints — shape/size restricts action (a plug fits one way).
Semantic constraints — meaning of a situation restricts action (a rider can only sit facing forward on a bike, that's the meaning of "sitting on a bike").
Cultural constraints — social conventions guide behaviour (red colour = stop/danger, universally understood).
Logical constraints — logical relationship between layout and function (if one part left, others must fit the remaining slot in a puzzle).

04. Norman's Model of Interaction (Seven-Stage Action Cycle) HIGH

Definition

Norman's Model of Interaction describes the interaction between a user and a system as a cycle of seven stages, divided into an Execution phase (forming and carrying out an action) and an Evaluation phase (perceiving and interpreting the result), connected via a goal.

🇮🇳 Hinglish
Jab bhi hum computer pe koi kaam karte hain (jaise email bhejna), hamara brain automatically 7 steps follow karta hai — pehle goal sochte hain, phir plan banate hain ki kya action lena hai, phir action execute karte hain, aur phir screen dekh kar samajhte hain ki humara action successful hua ya nahi. Norman ne is poore cycle ko 7 stages mein divide kiya hai.

Fig 2: Norman's Seven-Stage Model of Interaction (Action Cycle)

  1. Form the Goal — user decides what they want to accomplish (e.g., "I want to print this document").
  2. Form the Intention — user decides on a specific intention to reach that goal (e.g., "I will use the print command").
  3. Specify the Action — user plans the exact sequence of actions needed (e.g., "click File then Print").
  4. Execute the Action — user physically performs the action (clicking the mouse, pressing keys).
  5. Perceive the State of the World — user observes the system/environment after the action (sees the print dialog or a printed page).
  6. Interpret the State — user makes sense of what they perceived (understands that printing has started or an error occurred).
  7. Evaluate the Outcome — user compares the interpreted outcome with the original goal to check if it was achieved.

05. Gulf of Execution & Gulf of Evaluation HIGH

Definition

Gulf of Execution is the gap between a user's intentions and the actions allowed/available by the system. Gulf of Evaluation is the gap between the physical presentation of the system's state and the user's expectation/interpretation of it.

🇮🇳 Hinglish
Simple bhasha mein: Gulf of Execution = "Mujhe pata nahi ye kaam kaise karna hai, system mujhe batata hi nahi" (user confuse hai ki kya karna chahiye). Gulf of Evaluation = "Maine action kar diya lekin samajh nahi aa raha ki hua kya, system ne bataya hi nahi" (user confuse hai ki result kya hua). Good design in dono gulfs ko chhota kar deta hai — clear labels, feedback, icons ke through.

Gulf of Execution

Occurs when user doesn't know what actions are possible or how to perform them. Reduced by making controls, options and their functions visible and matching the user's mental model (good mapping).

Example: A remote control with 40 unlabeled buttons — user doesn't know which button does what.

Gulf of Evaluation

Occurs when user cannot easily tell whether the goal was achieved from the feedback the system provides. Reduced by giving clear, immediate feedback.

Example: Clicking "Submit" and nothing happens on screen — user unsure if the form was submitted.

Exam Angle

Questions often ask: "How can designers reduce the Gulf of Execution and Evaluation?" → Answer: Execution gulf is reduced through good mapping and visibility of controls; Evaluation gulf is reduced through good feedback and system status visibility (this directly connects to Norman's Principle 3 & 4 above).

06. Nielsen's Ten Usability Heuristics HIGH

Definition

Jakob Nielsen's Ten Usability Heuristics are general, broadly-applicable rules of thumb used to evaluate the usability of a user interface, developed by Jakob Nielsen and Rolf Molich in 1990 (refined in 1994).

🇮🇳 Hinglish
Ye sabse zyada exam mein pucha jaane wala topic hai. Nielsen ke 10 heuristics ek checklist ki tarah use hote hain — koi bhi interface evaluate karte waqt hum in 10 points ko check karte hain ki interface unhe follow kar raha hai ya nahi.
#HeuristicMeaning
1Visibility of System StatusSystem should always keep users informed about what is going on, through appropriate feedback within reasonable time
2Match Between System and the Real WorldSystem should speak the user's language, with familiar words/phrases/concepts rather than system-oriented terms
3User Control and FreedomUsers need a clearly marked "emergency exit" to leave an unwanted state, without having to go through an extended process; support undo/redo
4Consistency and StandardsUsers should not have to wonder whether different words, situations, or actions mean the same thing — follow platform conventions
5Error PreventionCareful design which prevents a problem from occurring in the first place, better than good error messages
6Recognition Rather than RecallMinimize memory load by making objects, actions and options visible; user shouldn't need to remember info from one part of dialog to another
7Flexibility and Efficiency of UseAccelerators (unseen by novice users) may speed up interaction for expert users, so the system can cater to both inexperienced and experienced users
8Aesthetic and Minimalist DesignDialogues/screens should not contain irrelevant or rarely needed information which competes with relevant units of information
9Help Users Recognize, Diagnose, and Recover from ErrorsError messages should be expressed in plain language (no codes), precisely indicate the problem, and constructively suggest a solution
10Help and DocumentationEven though it's better if the system can be used without documentation, it may be necessary to provide help that is easy to search, focused on the user's task, lists concrete steps

Exam mein aksar pucha jata hai — "kisi bhi ek app/website ka example lekar Nielsen ke heuristics apply karo". Neeche ek Online Shopping App (like Amazon/Flipkart) ka example diya hai jisse aap kisi bhi app pe apply kar sakte ho.

08. Heuristic Evaluation HIGH

Definition

Heuristic Evaluation is a usability inspection method in which a small set of expert evaluators independently examine a user interface and judge its compliance with a list of recognized usability principles (heuristics), most commonly Nielsen's ten heuristics.

🇮🇳 Hinglish
Heuristic evaluation ek "expert review" method hai — real users ko involve kiye bina, kuch usability experts interface ko check karte hain aur Nielsen ke 10 rules ke against dekhte hain ki kahan-kahan violation ho raha hai. Ye method fast aur cheap hai, real user testing se pehle use hota hai.

Steps of Heuristic Evaluation

  1. Select Evaluators: Choose 3–5 usability experts (studies show a single evaluator finds only ~35% of usability problems, while 5 evaluators together find ~75%).
  2. Briefing: Evaluators are briefed about the scope of the system, scenario, and target users.
  3. Independent Evaluation: Each evaluator inspects the interface alone (not as a group) against Nielsen's 10 heuristics, noting every usability violation found.
  4. Severity Rating: Each problem is rated on a severity scale (0 = not a problem, 1 = cosmetic, 2 = minor, 3 = major, 4 = usability catastrophe).
  5. Aggregation: All findings from evaluators are combined into a master list; duplicate issues are merged.
  6. Debriefing / Report: Results are discussed with the design team and prioritized fixes are suggested.
SeverityRatingMeaning
0Not a problemNo usability issue at all
1CosmeticFix only if extra time available
2MinorFixing should be given low priority
3MajorImportant to fix, should be given high priority
4CatastropheImperative to fix before product release
Pros & Cons

Advantages: Cheap, fast, does not require real users, can be done early in design cycle.
Disadvantages: Depends heavily on expertise of evaluators; may miss issues that only real users encounter; can find "false positives" (issues that aren't real problems for actual users).

09. Contextual Inquiry HIGH

Definition

Contextual Inquiry is a user-centered field research method in which the designer/researcher observes and interviews users while they perform their real tasks in their actual work environment, to understand the true context of use.

🇮🇳 Hinglish
Contextual Inquiry mein hum user ke real environment (office, ghar, factory) mein jaate hain aur unko unka normal kaam karte hue dekhte hain — interview room mein baithkar poochne ke bajaye. Isse hume "real" problems pata chalte hain jo user khud bata bhi nahi paata kyunki woh unhe itni aadat ho chuki hoti hai unhe notice hi nahi karta.

Four Core Principles of Contextual Inquiry

PrincipleMeaning
ContextGo to the user's workplace/environment and observe actual, ongoing work rather than asking users to recall or summarize past experience
PartnershipResearcher and user collaborate as partners to understand the work — more like an apprentice learning from a master than an interviewer questioning a subject
InterpretationResearcher shares their interpretation of what they observed with the user, immediately, to confirm or correct understanding
FocusResearcher steers the conversation with a clear focus/objective in mind, so relevant data is gathered instead of unrelated conversation
Real-World Example

To redesign a hospital's patient record software, a designer visits the ward and watches a nurse actually use the current system while attending patients — noticing that the nurse often has to enter data one-handed while holding equipment, which a lab-based interview would never reveal.

10. Cognitive Walkthrough HIGH

Definition

Cognitive Walkthrough is a usability inspection method where evaluators walk through a sequence of steps/tasks in an interface, at each step asking a set of standard questions from the perspective of a new/first-time user, to identify how "learnable" (explorable) the interface is.

🇮🇳 Hinglish
Cognitive Walkthrough mein evaluator khud ek naya user ban jaata hai aur ek-ek step follow karta hai jaise task complete kar raha ho, aur har step pe khud se 4 sawaal poochta hai — "kya main ye action try karunga?", "kya mujhe pata chalega ye action available hai?", waghera. Ye specifically "ease of learning" (first-time use) pe focus karta hai, na ki overall usability pe.

Four Key Questions Asked at Every Step

#Question
Q1Will the user try to achieve the right effect? (Does the user have the correct goal at this point?)
Q2Will the user notice that the correct action is available? (Is the control visible?)
Q3Will the user associate the correct action with the effect they are trying to achieve? (Is the label/icon clear enough?)
Q4If the correct action is performed, will the user see that progress is being made toward the goal? (Is feedback given?)

Steps to Conduct a Cognitive Walkthrough

  1. Define Inputs: Identify the users, the specific task, the correct action sequence to complete it, and the interface (or a prototype/mockup of it).
  2. Walk through Each Action: For every single step in the correct sequence, the evaluator asks the 4 key questions from a first-time user's perspective.
  3. Record Failure Stories: Whenever the answer to any question is "No", the evaluator writes a "failure story" explaining why a real new user might fail at that step.
  4. Revise Design: Based on the failure stories, the interface is redesigned — e.g. adding clearer labels, more visible buttons, or better feedback.
Worked Example

Task: "Change your profile picture" on a website. Step: click the small pencil icon overlapping the profile photo.
Q2 (Will user notice the action is available?) → Fails if the pencil icon is tiny/grey and blends into the background — evaluator records this as a failure story and recommends making the icon larger/more visible on hover.

FocusOverall usability vs. general heuristics (10 rules)Ease of learning for first-time / novice usersReal context, real tasks, real workflow

🎯
All three are called Usability Inspection / Evaluation Methods. Heuristic Evaluation and Cognitive Walkthrough are "expert-based" / analytical methods (no real users needed), while Contextual Inquiry is an "empirical" / field method involving real users. Usability Testing (lab-based, with real users performing tasks while being observed) is another empirical method often compared alongside these three.
Hinglish Trick

Shneiderman's 8 Rules: "Consistent Shortcuts Feedback Closure, Error-free Reversal Locus Memory" (Consistency, Shortcuts, Feedback, Closure, Error prevention, Undo reversal, Locus of control, Low memory load).
Norman's Gulfs: Gulf of Execution = "Main kya karu?" (Controls samajh nahi aa rahe). Gulf of Evaluation = "Hua kya?" (Feedback clear nahi hai).
Nielsen's Rule of Thumb: 3 to 5 Expert Evaluators are enough to catch ~75-85% of usability issues in Heuristic Evaluation!

Q1 · 10 MARKS
10 MARKS
Explain Shneiderman's Eight Golden Rules of interface design with suitable examples.

Ben Shneiderman proposed eight golden rules to guide good interface design: (1) Strive for consistency, (2) Enable frequent users to use shortcuts, (3) Offer informative feedback, (4) Design dialogs to yield closure, (5) Offer error prevention and simple error handling, (6) Permit easy reversal of actions, (7) Support internal locus of control, and (8) Reduce short-term memory load.

Each rule reduces cognitive load or error rate — for example, "informative feedback" is applied through progress bars or confirmation messages, while "reduce short-term memory load" is applied through auto-fill and recently-used lists. (See full table in section 02 above for detailed examples of each rule.)

Q2 · 10 MARKS
10 MARKS
Describe Norman's Seven Stage Model of Interaction with a neat diagram. What are Gulf of Execution and Gulf of Evaluation?

Norman's model views interaction as a cycle of 7 stages split into Execution (Form Goal → Form Intention → Specify Action → Execute Action) and Evaluation (Perceive State → Interpret State → Evaluate Outcome), connected through a shared Goal.

The Gulf of Execution is the gap between the user's intentions and the actions the system allows — reduced by good visibility and mapping of controls. The Gulf of Evaluation is the gap between the system's actual state/output and the user's understanding of it — reduced by clear, immediate feedback. Good interface design aims to minimize both gulfs.

Q3 · 10 MARKS
10 MARKS
List and explain Nielsen's Ten Usability Heuristics. Illustrate with an example of an application.

The ten heuristics are: (1) Visibility of system status, (2) Match between system and real world, (3) User control and freedom, (4) Consistency and standards, (5) Error prevention, (6) Recognition rather than recall, (7) Flexibility and efficiency of use, (8) Aesthetic and minimalist design, (9) Help users recognize, diagnose and recover from errors, and (10) Help and documentation.

Example: In an e-commerce app, "visibility of system status" is shown through order tracking; "error prevention" through a confirmation dialog before placing a costly order; "recognition rather than recall" through saved addresses. (Full mapping given in section 07 above.)

Q4 · 10 MARKS
10 MARKS
What is Heuristic Evaluation? Explain its process and severity rating scale.

Heuristic Evaluation is a usability inspection method where 3-5 expert evaluators independently examine an interface against a set of recognized usability heuristics (commonly Nielsen's 10) to identify usability problems.

Process: select evaluators → brief them on scope → each evaluator independently inspects the interface, noting violations → each violation is rated on a severity scale (0=not a problem to 4=usability catastrophe) → results are aggregated and debriefed with the design team to prioritize fixes.

Q5 · 10 MARKS
10 MARKS
Explain Cognitive Walkthrough as a usability evaluation technique with the four key questions asked at each step.

Cognitive Walkthrough is a usability inspection method where evaluators simulate a first-time user stepping through a task, asking at each step: (1) Will the user try to achieve the right effect? (2) Will the user notice the correct action is available? (3) Will the user associate the correct action with the desired effect? (4) Will the user see that progress is being made toward the goal?

Whenever an answer is "No", a failure story is recorded, and the interface is redesigned to fix that learnability gap — for example, making a hidden icon more visible.

Q6 · 5 MARKS
5 MARKS
Write short note on Contextual Inquiry.

Contextual Inquiry is a field research method where the designer observes and interviews users while they perform actual tasks in their real work environment. It is based on four principles: Context (observe real, ongoing work), Partnership (researcher and user collaborate like master-apprentice), Interpretation (share understanding with user for confirmation), and Focus (keep a clear objective during the study).

Q9 · 5 MARKS
5 MARKS
What is the severity rating scale used in Heuristic Evaluation?

Nielsen's severity scale ranges from 0 (not a usability problem) to 4 (usability catastrophe, must fix before release), with 1=cosmetic, 2=minor, and 3=major problems in between. This helps prioritize which issues to fix first when resources are limited.

Q10 · 5 MARKS — Short Note
5 MARKS
Write a short note on "Recognition rather than Recall" heuristic with an example.

This Nielsen heuristic states that users' memory load should be minimized by making objects, actions, and options visible, rather than requiring the user to recall information from memory. Example: A word processor showing a visible toolbar with icons (recognition) is easier to use than requiring the user to remember and type keyboard commands for every function (recall).

Q11 · 5 MARKS
5 MARKS
What are the four core principles of Contextual Inquiry?

Context: Study happens in the user's real environment during actual work.
Partnership: Researcher and user collaborate, more like apprentice-master than interviewer-subject.
Interpretation: Researcher shares observations with the user immediately to validate understanding.
Focus: Researcher steers the study with a clear goal so relevant data is collected.

Q12 · 10 MARKS
10 MARKS
Compare Heuristic Evaluation, Cognitive Walkthrough, and Contextual Inquiry as usability evaluation techniques.

All three are usability evaluation methods but differ in approach: Heuristic Evaluation uses experts checking an interface against Nielsen's 10 general heuristics without involving real users; Cognitive Walkthrough has experts simulate a first-time user going step-by-step through a task, asking 4 specific questions at each step, again without real users; Contextual Inquiry, unlike the other two, involves real users and requires the researcher to observe/interview them performing genuine tasks in their real work environment.

Heuristic Evaluation and Cognitive Walkthrough are fast, cheap, analytical/expert-based methods used early in design; Contextual Inquiry is slower and costlier but produces the richest, most realistic understanding of actual user needs and is typically used during requirements gathering.
