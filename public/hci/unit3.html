3.1 Basic Idea of Model-Based Design and Evaluation FOUNDATION

📖 Definition

Model-Based Design and Evaluation is an approach in HCI where mathematical, cognitive, or structural models of the user, the task, and the system are used to predict, analyze, and evaluate interface usability — such as task completion time, error rate, or learnability — without needing to build a full prototype or run expensive user trials for every design iteration.

🗣️ Hinglish Explanation

Traditional design mein hum interface banate hain, real users se test karwate hain, feedback lete hain aur phir redesign karte hain — yeh cycle bahut costly aur time-consuming hota hai. Model-based design mein hum user ke behaviour, memory, aur motor skills ko ek mathematical ya predictive model se represent karte hain (jaise GOMS, Fitts' Law). Fir hum bina real user ke, sirf calculation/formula se yeh predict kar sakte hain ki "kaun sa design fast hoga" ya "kitna time lagega task complete karne mein". Isse design cycle early stage mein hi improve ho jata hai, real users ki zarurat kam pad'ti hai, aur cost/time dono bachte hain.

Why Use Models Instead of Only User Testing?

💰
Cost & Time Saving: No need to recruit users and run full usability trials for every small design change.
⏱️
Early-Stage Prediction: Designers can compare multiple design alternatives quantitatively before any prototype exists.
🔁
Repeatable & Objective: Model output is consistent (same formula → same result), unlike variable human testers.
⚠️
Limitation: Models only approximate real behaviour — they usually predict expert, error-free, routine performance and cannot fully replace real user testing for learnability, emotion, or novel tasks.

3.2 Types of Models in HCI THEORY

📖 Definition

Models used in HCI can broadly be grouped by what they represent (user's cognition, user's task, or the system) and by what they are used for — describing existing behaviour, predicting future performance, or prescribing how a design should be built.

🗣️ Hinglish

HCI mein models ko roughly teen tarah se classify kiya ja sakta hai — kya wo sirf existing behaviour ko describe kar rahe hain (descriptive), kya wo future performance ko number mein predict kar rahe hain (predictive, jaise Fitts' Law time predict karta hai), ya kya wo designer ko batate hain ki design kaise banaya jaye (prescriptive/normative, jaise Shneiderman ke golden rules). GOMS aur KLM predictive hote hain kyunki time nikal ke dete hain, jabki cognitive walkthrough descriptive/evaluative hota hai.

Model TypeWhat it DoesExamples in HCI
Descriptive ModelsDescribe/explain existing user behaviour or interaction structureNorman's Model of Interaction, Task-Action Grammar
Predictive ModelsQuantitatively predict performance metrics (time, errors) before testingGOMS, KLM, Fitts' Law, Hick-Hyman's Law
Prescriptive / Normative ModelsPrescribe rules/guidelines that a good design should followShneiderman's 8 Golden Rules, Nielsen's 10 Heuristics
Cognitive ModelsRepresent how users perceive, think, remember and decideModel Human Processor (MHP), GOMS
Task ModelsRepresent the structure/hierarchy of tasks a user performsHierarchical Task Analysis (HTA), CTT
💡 Example

Suppose a designer wants to compare two ATM PIN-entry screens. A predictive model (KLM) can estimate that Design A takes 4.2 seconds and Design B takes 3.6 seconds for an expert user — allowing the designer to pick Design B before building either screen or testing with real customers.

3.3 GOMS Family of Models — Overview EXAM HOT

📖 Definition

GOMS (proposed by Card, Moran and Newell, 1983) is a family of predictive, engineering-style models that describe a user's task performance in terms of Goals, Operators, Methods, and Selection Rules, allowing analysts to predict the time an expert, error-free user takes to complete a task.

🗣️ Hinglish

GOMS ek framework hai jo kisi bhi task ko chaar components mein todta hai: Goal (user kya achieve karna chahta hai), Operators (chhote-chhote actions jo user perform karta hai, jaise key press, mouse move), Methods (operators ki sequence jo goal achieve karti hai), aur Selection Rules (agar goal achieve karne ke multiple methods hain, toh kaunsa method use karna hai yeh decide karne ke rules). GOMS ka use expert, routine, error-free user ke performance time predict karne ke liye hota hai.

The Four Components of GOMS

ComponentMeaningExample
GoalsThe end state the user wants to achieve"Delete a misspelled word"
OperatorsElementary perceptual, motor, or cognitive actionsMove mouse, click, press key, think/recall
MethodsA learned sequence of operators/sub-goals that accomplishes a goal"Point-click-drag to select, then press Delete"
Selection RulesRules to choose among multiple applicable methods"If mouse is near, use pointing method; else use keyboard shortcut"
Fig 3.2 — GOMS breaks a Goal into Methods (chosen via Selection Rules), each Method made of Operators
🎯
Important: GOMS models assume the user is a skilled/expert operator performing a routine, error-free task — they do NOT model learning, errors, or novice exploration behaviour.

3.4 KLM — Keystroke-Level Model EXAM HOT — NUMERICAL

📖 Definition

The Keystroke-Level Model (KLM), the simplest member of the GOMS family, predicts the time an expert user takes to execute a task error-free by decomposing it into a sequence of elementary physical and mental operators, each with an empirically-derived standard execution time, and summing them.

🗣️ Hinglish

KLM sabse simple aur most-used GOMS model hai. Isme har task ko chhote-chhote "operators" mein todte hain — jaise ek key press karna (K), mouse point karna (P), hands ko keyboard/mouse par le jaana (H), kuch sochna/decide karna (M), ya system ka response wait karna (R). Har operator ka ek fixed standard time hota hai (research se nikala gaya), aur total task time = sab operators ke time ka sum. Isse hum bina real testing ke, sirf calculation se pata laga sakte hain ki task karne mein kitna time lagega.

KLM Operators & Standard Times (Card, Moran & Newell)

OperatorNameMeaningStandard Time
KKeystrokePressing a key or mouse button0.08s (expert) – 1.20s (novice); avg ≈ 0.28s
PPointingMoving mouse pointer to a target on screen≈ 1.10s (Fitts' Law-based avg)
HHomingMoving hand between keyboard and mouse≈ 0.40s
DDrawingDrawing line segments (e.g., in a drawing tool)Variable — formula-based on segments
MMentalMentally preparing / deciding / recalling before an action≈ 1.35s
RSystem ResponseWaiting for the system to respondVariable — depends on system
KLM Total Execution Time Formula T_execute = T_K + T_P + T_H + T_D + T_M + T_R = sum of times for every operator used in the task

Mental Operator (M) Placement — Heuristic Rules

  1. Insert an M before every K (keystroke) or K-sequence that is not part of the same cognitive "chunk" (e.g., before typing a new, unrelated word).
  2. Do NOT insert M between K's that belong to the same well-learned unit (e.g., within one familiar word being typed).
  3. Insert an M before a P (pointing) if the target's location must first be decided/searched for, but not if it is a habitual, anticipated action.
  4. Delete any M that is immediately followed by another M — only one M is retained.
  5. Insert an M before command-terminating actions like pressing Enter, if a decision is being finalized.
💡 Worked Numerical Example

Task: Using the mouse, select a highlighted word on screen and delete it (hand starts on mouse).

Step-by-step Operator Sequence: M → decide to select the word = 1.35s P → point mouse to the word = 1.10s K → double-click to select word (1 click) = 0.28s M → decide to delete = 1.35s H → home hand from mouse to keyboard = 0.40s K → press Delete key = 0.28s -------------------------------------------------- Total T = 1.35+1.10+0.28+1.35+0.40+0.28 = 4.76 seconds

3.5 CMN-GOMS (Original GOMS by Card, Moran & Newell) CONCEPT + EXAMPLE

📖 Definition

CMN-GOMS is the original, full GOMS model that represents a task as an explicit hierarchy of goals and sub-goals, each achievable through one or more Methods written in a program-like, stepwise notation, with Selection Rules used to choose between competing methods.

🗣️ Hinglish

CMN-GOMS mein pura task ek goal-subgoal hierarchy ki tarah likha jaata hai, jaise programming pseudocode. Har GOAL ko todha jaata hai chote SUBGOALS mein, aur har subgoal ko achieve karne ka ek METHOD hota hai jo operators ki step-by-step list hoti hai. Agar ek subgoal ko achieve karne ke multiple tarike (methods) hain, toh SELECTION RULE decide karta hai kaunsa method choose karna hai based on context.

CMN-GOMS Notation Example — "Delete a Word" Task

GOAL: DELETE-WORD . GOAL: SELECT-WORD . [select Method-1 if mouse available] . [select Method-2 if keyboard-only] . METHOD-1 FOR GOAL: SELECT-WORD USING MOUSE . STEP 1. MOVE-CURSOR TO word (Operator: P) . STEP 2. DOUBLE-CLICK mouse-button (Operator: K) . RETURN WITH GOAL ACCOMPLISHED . GOAL: DELETE-SELECTED-TEXT . METHOD FOR GOAL: DELETE-SELECTED-TEXT . STEP 1. HOME hand to keyboard (Operator: H) . STEP 2. PRESS "Delete" key (Operator: K) . RETURN WITH GOAL ACCOMPLISHED
💡 Note

CMN-GOMS is more detailed and structural than KLM — it captures the full goal hierarchy and decision logic, while KLM only focuses on predicting execution time once a single method is chosen. CMN-GOMS is typically used first to model task structure; KLM is then used on the chosen method to predict time.

KLM

  • Fastest & simplest to apply
  • Only predicts execution time
  • Operators executed strictly one after another
  • No modelling of learning or goal structure

CMN-GOMS

  • Models full goal/sub-goal hierarchy
  • Includes Selection Rules for method choice
  • More effort to build than KLM
  • Better for understanding task logic, not just timing

3.7 Fitts' Law EXAM HOT — NUMERICAL

📖 Definition

Fitts' Law is a predictive model of human movement stating that the time required to rapidly move to and point at a target is a function of the distance to the target and the target's width (size) — larger, closer targets are acquired faster than smaller, farther targets.

🗣️ Hinglish

Fitts' Law batata hai ki mouse ya finger se kisi target (jaise button) tak pahunchne mein kitna time lagega — yeh depend karta hai target ki distance (D) aur target ke size/width (W) par. Jitna target bada aur jitna close hoga, utna kam time lagega usko click karne mein — aur jitna chhota aur door hoga, utna zyada time lagega. Isiliye UI design mein important buttons ko bada aur easily reachable rakha jaata hai.

Fig 3.3 — Fitts' Law variables: Distance (D) to target and target Width (W)

Formula

Fitts' Law (Shannon Formulation — most widely used) MT = a + b × log2( D / W + 1 ) where: MT = Movement (pointing) time a, b = empirical constants (depend on device, determined by regression) D = distance from starting point to the center of the target W = width of the target along the movement axis ID = log2(D/W + 1) → "Index of Difficulty" (measured in "bits")
💡 Worked Numerical Example

Given: D = 400 px, W = 40 px, a = 50 ms, b = 150 ms/bit.

ID = log2(400/40 + 1) = log2(11) ≈ 3.46 bits MT = 50 + 150 × 3.46 = 50 + 519 = 569 ms ≈ 0.57 seconds

Applications of Fitts' Law in UI Design

  • 🎯 Bigger buttons for frequent/important actions (e.g., large "Submit" buttons) reduce W → higher error, so bigger targets are used for critical actions.
  • 📍 Screen edges & corners act as "infinite width" targets — the pointer cannot overshoot past the screen edge, so edge/corner menus (e.g., Start button in a corner) are acquired very fast.
  • 📏 Keep related/frequent controls close together to reduce distance D and hence movement time.
  • 📱 On touchscreens, this generalizes to finger-touch target sizing (minimum recommended touch target ~ 9-10mm).

3.8 Hick-Hyman's Law EXAM HOT

📖 Definition

The Hick-Hyman Law (Hick 1952, Hyman 1953) states that the time taken to make a decision among n equally-probable choices increases logarithmically with the number of choices/alternatives available.

🗣️ Hinglish

Hick-Hyman's Law batata hai ki jitne zyada options (choices) user ke saamne honge, decision lene mein utna zyada time lagega — lekin yeh increase linear nahi, logarithmic hota hai. Matlab options double karne se time double nahi hota, thoda hi badhta hai. Isliye UI design mein bahut saare options ek hi jagah dikhane se better hai ki unhe categories mein todkar (grouped menus) dikhaya jaaye — isse decision time kam hota hai.

Fig 3.4 — RT vs number of choices: rises fast initially, then flattens (logarithmic curve)

Formula

Hick-Hyman's Law RT = a + b × log2( n + 1 ) where: RT = Reaction / decision time a, b = empirical constants (device/context dependent) n = number of equally likely choices/alternatives "+1" accounts for the possibility of making "no choice"
💡 Worked Numerical Example

Given: n = 8 menu items, a = 200 ms, b = 150 ms/bit.

RT = 200 + 150 × log2(8 + 1) = 200 + 150 × 3.17 = 200 + 475.5 ≈ 675.5 ms

🧮 Interactive Hick-Hyman Simulator

RT ≈ 675.5 ms

Applications of Hick-Hyman's Law

  • 📋 Grouped/hierarchical menus (categories → sub-items) reduce effective choices visible at once, speeding up decisions vs one giant flat menu.
  • 🔍 Search + autocomplete reduces the number of visible choices dynamically as the user types.
  • ⚠️ Too much menu grouping (too many levels) increases navigation time — a trade-off (breadth vs depth) must be balanced.

3.10 Model-Based Design Case Studies APPLICATION

🏧 Case Study 1 — ATM PIN Entry Screen (KLM)

Two ATM keypad layouts are compared using KLM. Design A requires the user to home hands between a physical keypad and a touchscreen "Confirm" button; Design B keeps everything on the touchscreen.

DesignOperator SequencePredicted Time
A (Keypad + Touch Confirm)M,K,K,K,K,H,M,K≈ 5.9s
B (All Touchscreen)M,K,K,K,K,M,K≈ 5.5s

Result: Design B is faster since it removes the Homing (H) operator — confirming the model-based prediction that all-touchscreen input reduces task time.

⌨️ Case Study 2 — Keyboard Layout Comparison (Fitts' Law + KLM)

QWERTY layout vs an alternative optimized layout are compared for typing a common word — Fitts' Law estimates the pointing/finger-travel time between key positions (distance between frequently-paired letters), while KLM sums total keystroke time.

LayoutAvg. Distance Between Frequent Letter PairsPredicted Typing Time (relative)
QWERTYHigher (not optimized for English digraphs)Baseline (100%)
Optimized LayoutLower (frequent pairs closer together)~10-15% faster (model prediction)
📱 Case Study 3 — Mobile Menu Design (Hick-Hyman's Law)

A mobile app team compares a flat menu of 16 options against a grouped menu with 4 categories × 4 items each, using Hick-Hyman's Law to predict decision time at each screen.

Menu StyleChoices VisiblePredicted Decision Time
Flat (16 items)n = 16RT = 200 + 150×log2(17) ≈ 813 ms
Grouped (4 + 4)n = 4, then n = 4 again2 × (200 + 150×log2(5)) ≈ 2 × 548 = 1096 ms total, but each step feels faster and less overwhelming

Result: While total time can be similar or slightly higher for grouped menus, model-based analysis helps designers make an informed trade-off between raw speed and reduced cognitive load — rather than guessing.

3.12 RTU Exam Q&A Bank MUST PRACTICE

Q1
What is Model-Based Design and Evaluation? Explain its basic idea with the different types of models used in HCI. 10 Marks

Model-based design and evaluation uses mathematical, cognitive, or structural models of the user and task to predict usability metrics like time and errors without building full prototypes or running extensive user tests, allowing early, low-cost comparison of design alternatives. Models in HCI are broadly classed as descriptive (explaining behaviour, e.g. Norman's model), predictive (quantifying performance, e.g. GOMS, Fitts' Law), and prescriptive/normative (offering design guidelines, e.g. Shneiderman's golden rules), along with cognitive models like the Model Human Processor and task models like Hierarchical Task Analysis.

Q2
Explain the GOMS model with its four components. How does CMN-GOMS differ from KLM? 10 Marks

GOMS, proposed by Card, Moran and Newell, models a task using Goals (what the user wants to achieve), Operators (elementary perceptual/motor/cognitive actions), Methods (learned sequences of operators achieving a goal), and Selection Rules (rules choosing between multiple applicable methods) to predict expert, error-free task performance. CMN-GOMS is the original, detailed model that represents the full goal-subgoal hierarchy with explicit methods and selection rules in a program-like notation, whereas KLM is a simplified variant that skips the hierarchy and selection logic, focusing purely on summing standard operator times to predict execution time for one already-chosen method.

Q3
Using the Keystroke-Level Model (KLM), calculate the time to select a paragraph with the mouse and delete it, given the hand starts on the mouse. Show all operators used. 10 Marks

The task decomposes into: M (decide to select, 1.35s), P (point to paragraph start, 1.10s), K (click-drag to select, 0.28s), M (decide to delete, 1.35s), H (home hand to keyboard, 0.40s), and K (press Delete, 0.28s), summing to a total predicted execution time of approximately 4.76 seconds. This illustrates how KLM decomposes any routine interactive task into elementary operators with standard times to predict expert performance without user testing.

Q4
State and explain Fitts' Law. Calculate the movement time for a target at distance D=300px and width W=30px, given a=50ms and b=150ms/bit. 10 Marks

Fitts' Law predicts that the time to rapidly point at a target depends logarithmically on the ratio of distance to target width, expressed as MT = a + b·log2(D/W + 1), where the log term is called the Index of Difficulty (ID) measured in bits, meaning larger and closer targets are acquired faster. For D=300 and W=30, ID = log2(300/30 + 1) = log2(11) ≈ 3.46 bits, giving MT = 50 + 150×3.46 ≈ 569 milliseconds.

Q5
State Hick-Hyman's Law and explain its significance in menu design. Calculate reaction time for 12 choices with a=200ms, b=150ms/bit. 10 Marks

Hick-Hyman's Law states that decision time among n equally likely choices grows logarithmically as RT = a + b·log2(n + 1), meaning that doubling the number of options does not double the decision time — this motivates grouping large flat menus into smaller hierarchical categories to reduce the effective choice count at each step and lower perceived decision time. For n=12, RT = 200 + 150×log2(13) = 200 + 150×3.70 ≈ 755 milliseconds.

Q6
List and explain the standard KLM operators with their times, and state the heuristic rules for placing the Mental (M) operator. 10 Marks

The six KLM operators are K (keystroke, ~0.28s average), P (pointing with mouse, ~1.10s), H (homing between input devices, ~0.40s), D (drawing line segments, variable), M (mental preparation, ~1.35s), and R (waiting for system response, variable), which together sum to give the total predicted execution time of a task. The mental operator placement heuristics state that M should be inserted before an unrelated keystroke or decision-requiring pointing action, but omitted within a single well-learned chunk, and that consecutive M's should be collapsed into a single M.

Q7
Differentiate between Fitts' Law and Hick-Hyman's Law. 5 Marks

Fitts' Law predicts the time needed to physically move to and point at a target as a function of distance and target width (a motor task), while Hick-Hyman's Law predicts the time needed to cognitively decide among a number of choices (a decision task); both share a similar logarithmic mathematical form but model fundamentally different aspects of interaction — physical movement versus mental choice.

Q8
What are NGOMSL and CPM-GOMS? How do they extend the basic GOMS model? 5 Marks

NGOMSL (Natural GOMS Language) is a more structured variant of GOMS that expresses methods as learnable production rules, allowing prediction of both execution time and the time needed to learn a procedure. CPM-GOMS (Cognitive-Perceptual-Motor GOMS), based on the Model Human Processor, allows perceptual, cognitive, and motor operators to execute in parallel rather than strictly sequentially, giving more accurate but more complex predictions of expert performance than KLM.

Q9
Explain why models like GOMS and Fitts' Law cannot fully replace real user testing. 5 Marks

These models assume an expert user performing a routine, well-learned, error-free task, so they cannot capture novice learning curves, exploratory behaviour, error recovery, emotional response, or unpredictable real-world usage patterns that real user testing reveals. They are best used for early, comparative, quantitative screening of design alternatives, with real user testing still required to validate learnability, satisfaction, and error-handling.

Q10
Give two practical UI design applications each of Fitts' Law and Hick-Hyman's Law. 5 Marks

Fitts' Law motivates making frequently-used buttons larger and placing them close to the expected cursor position, and placing critical controls at screen edges/corners which act as targets of effectively infinite width. Hick-Hyman's Law motivates organizing large sets of options into grouped or hierarchical menus rather than one long flat list, and using search/autocomplete to dynamically reduce the number of visible choices as the user types.
